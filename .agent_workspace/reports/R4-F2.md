## `io/pch.py` — Nastran punch, real modes

* **Format**: 80-column punch layout — 72 data chars + sequence number,
  `$EIGENVALUE = <lambda>  MODE = <n>` headers (λ = ω² in (rad/s)², same
  convention as `ModalResult.eigenvalues`), `$EIGENVECTOR` blocks, `G`
  points as `T1 T2 T3` / `-CONT- R1 R2 R3`, scalar `S`/`E`/`M` points as
  one value (mapped to local DOF 0).
* **Reader tolerance** (verified against a hand-built MSC-style file):
  sequence numbers optional, 6-decimal or any precision, Fortran `D`
  exponents, `$SUBCASE`/`$TITLE`... headers, modes with differing node
  sets (zero-filled + warning). Complex blocks (`$REAL-IMAGINARY` /
  `$MAGNITUDE-PHASE OUTPUT`) and non-eigenvector blocks
  (`$DISPLACEMENTS`, stresses, ...) are skipped with one aggregated
  warning each — never an error. No real modes at all → `PchError`
  (subclasses `FileFormatError`, still a `ValueError`).
* **Writer**: dual signature `write_pch(path, modal)` / `(modal, path)`
  like the other io writers; emits sequence numbers and 9-decimal
  mantissas inside the standard 18-char fields (any punch reader parses
  it; roundtrip good to ~1e-9 rel). Accepts **both** modal flavours by
  duck typing: `core.results.ModalResult` (via `dof_index`) and
  `fea.eigen.ModalResult` (via `dof_map` — this is what `solve_modes`
  returns, so the practical path works out of the box).
* **Documented losses** (format limitations, warned at write): punch has
  no generalized-mass or damping record (`read_pch` returns 1.0 gen mass
  = the Nastran MASS-normalization default); complex shapes are refused
  with a pointer to UNV dataset 55.

## `io/cdb.py` — ANSYS coded database, blocked subset

* **Records read**: NBLOCK (fixed-format via the Fortran format line —
  necessary because negative `e21.13e3` values touch the neighbouring
  field, whitespace splitting would corrupt coordinates), EBLOCK (SOLID
  and compact keys, multi-line records), ET + ETBLOCK, MP + MPDATA
  (EX/NUXY/PRXY/DENS/GXY/ALPX, first temperature point), R/RMORE +
  RLBLOCK, SECTYPE/SECDATA/SECBLOCK (shell thickness, layers summed),
  D (UX..ROTZ, ALL → SPCs grouped per node/value), F (FX..MZ → loads).
  All other commands are bookkeeping and ignored silently; structurally
  relevant ones (`CP`, `CE`, `CERIG`, `RBE3`, non-global `CSYS`) get one
  aggregated warning each.
* **Element mapping** (by ANSYS name *number*, so `ET,1,185` and
  `ET,1,SOLID185` both resolve): LINK1→TRUSS2D, LINK8/180→BAR2,
  BEAM3/4/188→BEAM2 (orientation node K honoured; BEAM4 section from real
  constants, BEAM188 section values not derivable → zeros + warning),
  SHELL41/63/181→QUAD4/TRIA3, SHELL93/281→corners, SOLID45/185→HEX8 with
  ANSYS degeneracy collapse (I J K K M M M M → TET4; wedge/pyramid have no
  femtools element → skipped + warning), SOLID95/186→HEX8 corners,
  SOLID92/187/285→TET4, MASS21→MASS (m = RC 1), COMBIN14→SPRING (k = RC 1;
  two nodes without DOF pins = femtools axial spring, which matches
  COMBIN14's longitudinal default).
* **Properties** are synthesized one per (kind, MAT, REAL, SECNUM)
  combination with the ANSYS attribute ids kept in `Property.attrs`
  (`ansys_type`/`ansys_real`/`ansys_secnum`); missing MP data or shell
  thickness never aborts the read — dangling refs / t=0 are reported via
  aggregated warnings ("fix before solving"), matching the BDF reader's
  degrade-with-warning philosophy. No `write_cdb` (export out of scope).
