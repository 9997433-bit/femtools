## The one thing to read before writing a doc row or an acceptance line

**The unweighted MAC of a self-expansion is *not* the identity, and it must not be.** The diagonal is
1 to round-off, but the off-diagonal is the **auto-MAC of the reference mode set**, which is only
zero when those modes are orthogonal *in the Euclidean sense*. FE modes are **mass**-orthogonal, so
on my cantilever the off-diagonal terms sit at **0.21** — and `expanded_mac` reproduces the FE
auto-MAC there to 7.8e-16, i.e. it adds nothing and removes nothing. There are exactly two ways to
get the full identity, both checked:

* an orthonormal reference basis (`M = I`), or
* mass-normalized FE modes with `weights=mass`, where the MAC becomes the squared normalized
  cross-orthogonality and the table is `I` to 4.4e-16.

So the result exposes **two** numbers instead of one:

* `diagonal_error` — `max |1 − mac[k, k]|`, the reference-independent SEREP fixed-point check. **This
  is the gate number** for a general FE mode set.
* `identity_error` — `max |mac − I|`, valid only for the two orthogonal cases above.

An acceptance row that asserts a full unweighted identity on real FE modes will fail on any model
with rotational DOFs or a non-uniform mass distribution. Phrase it as *"unit MAC diagonal (1e-10),
full identity under `weights=M`"*.

## The API

```python
expanded_mac(
    phi_test, modes, master=None, *,
    reference=None, dof_map=None, test_map=None, n_modes=None,
    freq_hz=None, rcond=1e-12, weights=None, return_transform=False,
) -> ExpandedMACResult
```

It is the two published steps and nothing else — `expand_serep` (O'Callahan, Avitabile & Riemer,
Proc. 7th IMAC, 1989) followed by `mac_matrix` (Allemang) — verified **bit-identically** against the
composed calls in the test suite:

```python
# before
expansion = expand_serep(phi_test, modal, master)
mac = mac_matrix(expansion.modes, np.asarray(modal.modes))

# after
result = expanded_mac(phi_test, modal, master)
print(result.table())
```

* `phi_test`, `modes`, `master`, `dof_map`, `test_map`, `n_modes`, `rcond`, `return_transform` mean
  exactly what they mean in `expand_serep` (indices, boolean mask, DOF keys like `"12Y"`, or a
  `test_map` matched against the model map, with the sensor scale factors applied).
* **`phi_test` may also be the full `(n_full, n_mode)` set**, in which case it is restricted to
  `master` first. That is the self-check spelled short: `expanded_mac(modal, modal, master)`, which
  is bit-identical to `expanded_mac(np.asarray(modal.modes)[master], modal, master)` and additionally
  carries the modal frequencies into the report. A full-size `phi_test` was an error before, so this
  only widens the contract.
* `reference` — the full-DOF set to correlate against; defaults to the expansion basis (truncated by
  `n_modes`), which is the fixed point. Given a permuted, rescaled copy it returns the permutation
  matrix to 1e-16.
* `weights` — goes straight to `mac_matrix`, so the mass matrix gives the cross-orthogonality-based
  variant on the expanded DOF set.

`ExpandedMACResult` is a dataclass, because an expanded MAC without the residual next to it is a
number you cannot judge:

* `mac` (`np.asarray(result)`, `result[i, j]`, `result.shape`, `values`) — the
  `(n_mode_test, n_reference)` table.
* `expansion` — the `ExpansionResult` that produced it, with `residual`, `coefficients`, `rank`,
  `transform`, `master`, `slave`, `dof_map`; `modes`, `master`, `residual`, `method`, `n_master` are
  surfaced on the result itself.
* `diagonal`, `min_diagonal`, `diagonal_error`, `max_off_diagonal`, `identity_error`,
  `is_identity(tol=1e-10)`.
* `freq_test`, `freq_reference`, and `table()`.
* **It also unpacks as the documented pair** `mac, expansion = expanded_mac(...)`, so both return
  shapes the brief allowed are available from one object.

### What the fixed point does *not* prove

SEREP can only produce shapes inside the span of the basis, so a measured shape is **projected** onto
it before the MAC ever sees it: the criterion is optimistic by construction and a unit diagonal on
real test data means "the fit lives in the basis", not "the model is right". The part of the
measurement the basis could not represent is `result.residual` (0 to 1.6e-15 in the self-check, > 0.5
for a shape the retained basis cannot follow), and both the docstring and the table put it next to
the MAC for that reason. This is also why the diagonal alone cannot detect a *blind* master set: a
mode with no amplitude at any sensor expands to the zero vector and its diagonal entry comes back as
exactly `0.0` (checked), not as a silent 1.
