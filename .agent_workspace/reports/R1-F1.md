## Residual risks

1. **CI green-ness depends on other agents' code.** `ruff check .` covers the whole repo; any Round-1 branch that lints dirty will fail CI after merge. Rules were kept exactly at the seed set (E, F, I, UP, B) to avoid moving the goalposts; the only addition is a *relaxation* (B008 ignore for `cli.py`).
2. **Exit-code-5 masking.** The pytest guard treats "no tests collected" as success. After R1-G1 merges tests, an accidental collection wipe-out (e.g. bad `testpaths`) would pass silently. Round 2 should flip the guard to hard-fail once `tests/` is populated.
3. **PEP 639 metadata needs setuptools ≥ 77.** Build isolation fetches it automatically; offline/pinned environments older than setuptools 77 will fail to build. Mitigation is documented here; revert to `license = {text = "MIT"}` is a two-line change if it bites.
4. **Status tags in `PRODUCT_MAP.md` describe the contract, not merged reality.** Written while implementation branches are in flight; any contract item an implementer drops must be re-tagged.
5. **Architecture decisions not yet enforced by code.** DOF ordering formula, auto-SPC behavior, exception hierarchy module (`femtools.core.errors`), and the `femtools.drivers` entry-point group are specified here but owned by R1-F2/O1; divergence is possible.
