## What the problem actually was

A flat shell has no genuine stiffness about its own normal, so `TRIA3`/`QUAD4`
carry a rank-deficient drilling penalty and `assemble_km` removes the drilling
rotations that receive nothing else. Removing them *by index* only works while
the drilling direction **is** a global DOF. Tilt the plate and the drilling
rotation becomes a mixture of `rx`, `ry`, `rz`; no whole global DOF can be
dropped without taking a genuine bending rotation with it, so the per-element
null spaces survived as one global zero-energy mechanism and the free-free
spectrum reported a seventh rigid body mode. Round 5 could only warn about it.

## What I implemented

New module `src/femtools/fea/nodal_frames.py`.

* `averaged_shell_normals(model)` — area-weighted average of the attached shell
  element normals at each node, sign-aligned against the first normal seen at
  that node so a mesh with inconsistent element numbering still yields one
  coherent normal field. Nodes whose normals cancel (a shell folded back on
  itself) are left out and get no triad.
* `rotation_triad(normal)` — right-handed orthonormal triad whose **third
  column** is the normal. The in-plane pair is anchored on the global axis the
  normal is *least* aligned with, so the construction never divides by a small
  projection and is reproducible: the same normal always yields the same triad.
* `NodalFrames` — the triads of one assembly plus the orthogonal block-diagonal
  `Lambda = diag(I3, R)` they induce, with `to_basic` / `from_basic` /
  `congruence`. Translations are never rotated.

`assemble_km` gained `nodal_frames: bool = True`. It builds the frames after the
SPC partition and applies `Lambda.T @ A @ Lambda` to `K`, `M`, `C` and the
drilling penalty. The existing one-DOF elimination then fires unchanged, because
in the analysis frame the drilling rotation of a flat patch is local component 5
whatever the plate's orientation. `AssemblyResult` carries `frames`,
`framed_nodes`, `to_basic`, `from_basic`. `solve_static` reads loads in the basic
frame and rotates them in; the result comes back in the analysis frame, which is
Nastran's `GRID`/`CD` convention and keeps `K`, `M`, `free_dof` and every
full-length vector mutually consistent.

Two deliberate abstentions, both of which are what protects the goldens:

* **The triad is the identity wherever the averaged normal already is a global
  axis.** An axis-aligned model is not merely numerically unchanged, it is
  bit-for-bit unchanged — pinned by
  `test_axis_aligned_assembly_is_untouched_by_the_frames`, which asserts
  `(K_with - K_without).nnz == 0`.
* **A node with a rotational SPC keeps the basic frame.** An SPC is written in
  the basic frame and only stays a single-DOF constraint there. For the same
  reason `solve_static` now raises rather than accepting an enforced *rotation*
  on a framed node, where one basic-axis rotation is a constraint across three
  equations, not a value for one of them.

Literature: nodal/local triads for skew boundary conditions, Bathe *Finite
Element Procedures* §5.5.2; shell normal averaging, MacNeal *Finite Elements:
Their Design and Performance* §7. No solver-specific or proprietary content.

## Optional item: Simo–Rifai EAS for HEX8

Attempted, and it resolved into a proof rather than a formulation.

I built the Simo–Rifai EAS-9 brick independently —
`eps~(xi) = (det J0 / det J) T0^-1 M(xi) alpha` with the nine amplitudes
statically condensed out (Simo & Rifai 1990, IJNME 29; hexahedral extension per
Simo & Armero 1992 / Andelfinger & Ramm 1993) — and compared it with the shipped
Wilson–Taylor incompatible-modes element. **They are the same matrix**: worst
relative difference `2.0e-16` over seven hexahedra (unit cube, 0.4 skew
parallelepiped, 0.3 trapezoid, four randomly distorted bricks). The comparison
is not insensitive: the transposed natural-strain convention, a genuinely
different element, differs by `9.7e-2` on the same shapes.

So there is nothing for an `"eas"` formulation to buy. It would duplicate the
element bit-for-bit, and it specifically cannot cure the trapezoidal distortion
loss documented in `verification.py` (0.975 -> 0.518 at skew 0.2), because the
element that loses that accuracy *is* the EAS element. Curing trapezoidal
distortion needs a genuinely larger enhancement (EAS-30 / Andelfinger–Ramm), and
I did not have a public parameter table I could reproduce faithfully — the brief
says skip if risky, so I did not guess one.

Rather than skip silently I shipped the finding as a verification case,
`femtools.fea.verification.hex8_eas_equivalence` (with `hex8_eas9_stiffness` as
the reference implementation), pinned by
`test_shipped_hex8_already_is_the_simo_rifai_eas9_element`. The shipped element
itself is untouched, `HEX8_FORMULATIONS` is unchanged, and the 98.6% tip ratio
and 6 RBM are re-measured above.
