## Design

- **Graceful failure** follows the established `_missing()` convention
  (exit 3). Sub-module imports use `import femtools.fea.reduction as ...`
  (not `from femtools.fea import ...`) so the error names the exact missing
  module (`femtools.fea.reduction`, not `femtools.fea`). A module that exists
  but lacks the requested function (e.g. `estimate_h2` missing) also exits 3
  with a precise message. User/data errors exit 2; kernel `ValueError`/
  `LinAlgError` are caught and reported cleanly.
- **Forward compatibility with in-flight kernels** — signatures are frozen in
  `REMAINING.md` but details may drift, so the CLI is duck-typed the same way
  `tests/test_round4_reduction.py` / `test_round4_mpe.py` are:
  - `_reduction_parts()` accepts `(T, Kr)` / `(T, Kr, Mr)` tuples, a bare
    basis matrix, or a result object (`T/transform/basis`,
    `K_red/Kr/Krr/K_reduced/K`, `M_red/Mr/M_reduced/M`). A bare
    ndarray/sparse return is detected via `ndim` *before* attribute scanning
    — `ndarray.T` is the transpose, an easy trap. Missing reduced matrices
    are recomputed as `T.T @ A @ T`.
  - `_call_estimator()` inspects the kernel signature, drops unsupported
    tuning kwargs (`nperseg/window/overlap`) and passes the sampling rate as
    `fs=` keyword when accepted (the contract-test convention, works for
    keyword-only `fs`) or positionally otherwise.
  - `_frf_estimate_parts()` accepts `(f, H[, coh])` tuples, bare arrays
    (frequency grid then inferred from `fs`/`nperseg` with a warning), or
    objects (freq attrs incl. `frequency`/`frequencies`, value attrs incl.
    `h_complex` — the exact candidate lists used by the round-4 contract
    tests). Coherence is taken from the estimator result or via a separate
    `coherence()` call when available; its absence is tolerated.
- **`reduce`** assembles once (`assemble_km`), works on the free-DOF
  partition, and maps `NODE:DOF` masters through `dof_map` with clear errors
  for unknown nodes, constrained/inactive DOFs and duplicates. Dense copies
  are passed to guyan/irs (the reduction contract is dense); Craig-Bampton
  gets the sparse partition (its kernel handles both). With `--compare`
  (default) it solves the reduced dense eigenproblem and prints a
  full-vs-reduced frequency table with signed errors. `-o` saves
  `T, K_red, M_red, master_dof, master_free, free_dof, method,
  freq_full, freq_reduced` to `.npz`. `-n` doubles as SEREP basis size /
  CB fixed-interface mode count / comparison length.
- **`estimate-frf`** reads `.npz` time data; input/output arrays are found by
  conventional keys (`x/u/input/force/excitation`, `y/a/response/...`) or
  selected with `-x/-y`; the rate comes from `--fs`, an `fs`-like key, or the
  median `diff(t)`. Prints lines/df/window summary plus mean/min coherence;
  `-o` saves `freq_hz, H, coherence, fs, estimator`; `--plot` reuses
  `viz.plot_frf`.
- **`report-mac`** mirrors `mac`'s loading (model file or `.npz` modes, self-
  MAC when B omitted). Pairing (`--pair/--no-pair`, `--mac-threshold`) is
  optional-degradable: a missing pairing module warns and produces the report
  without the pair table. `--format auto|html|text` dispatches on suffix.

## Gaps / handoff notes

1. **R4-O1 / R4-O4**: the CLI calls `guyan(K, master)`,
   `irs(K, M, master)`, `serep(phi, master_rows)` with dense `K/M` and
   0-based free-partition indices, and `estimate_h1/h2(x, y, fs=..., ...)`.
   Any return shape listed above unpacks correctly; if you add a
   `ReductionResult`, keeping attrs `T`/`K`/`M` (CB naming) is zero-cost.
2. `reduce` compares mode-by-mode in order; when the master set spans only
   one bending plane the reduced spectrum is a subset of the full one and
   rows can pair across planes (documented behavior, not a bug — a
   MAC-based pairing of the comparison table would be a Round-5 nicety).
3. `estimate-frf --plot` draws H[0,0] only; multi-channel selection flags
   (`--out-index/--in-index`) were deliberately left out until a kernel
   defines the channel layout.
4. For the test owner: CliRunner cases worth adding once kernels land —
   `report-mac` HTML contains `Mode pairs` for two-file input; `reduce`
   exit 3 today / exit 0 with R4-O1; `estimate-frf` peak ≈ resonance on a
   synthetic SDOF; each new command's bad-input exit 2 paths.
5. GUI (`gui/**`) does not expose the new commands; the FSL script engine
   (`script/**`) has no `report`/`reduce`/`estimate` statements. Both were
   left untouched on purpose — candidates for a later round.
