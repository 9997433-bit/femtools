## What it does

`H(0) = O C` from the block Hankel matrix of Markov parameters, truncated SVD
`H(0) = U S Vᵀ` giving `O = U_n S_n^½` and `C = S_n^½ V_nᵀ`, then

```
A = S_n^-½ U_nᵀ H(1) V_n S_n^-½,   B = C[:, :n_in],   C = O[:n_out, :]
λ = ln(μ)/Δt  from  eig(A),        φ = C ψ
```

* **Inputs**: real Markov parameters / sampled IRFs `(n_out, n_in, n_t)`,
  `(n_out, n_t)` or `(n_t,)` with `dt`/`fs`; or a complex FRF matrix with
  `freq_hz`, run through the existing `lsce.irf_from_frf`; or any object
  exposing `.frf` (and `.freq_axis`).
* **Reuse**: row stacking is `ssi.block_hankel` (one call per input column,
  interleaved into block columns), the result container is
  `common.ModalParameterResult`, poles go through `common.poles_from_roots`,
  and the optional order sweep is `common.stabilization_diagram` +
  `select_stable_modes` — the same machinery LSCE and SSI use.
* **Single order is enough**: `stabilization=False` with `order=4` clears the
  gate on the 2-DOF case (row 2 of the table below). The sweep is on by
  default because it is what the other estimators do.
* **Accuracy indicator**: the paper's *modal amplitude coherence* is in
  `extras["amplitude_coherence"]` and can filter poles via `min_coherence=`.
  It also breaks ties when `n_modes=` has to drop candidates.
* **Exponential window undone exactly**: `irf_from_frf` multiplies sample `k`
  by `ρ^k`, so the realised system is `(ρA, B, C)` — dividing `A` by `ρ`
  restores the poles with no correction on `B`, `C` or the shapes.
  `ρ = 0.99712411…` on the gate case; without the correction the damping of
  mode 1 would read ~2.3 % instead of 1.0 %.

## Gate: synthetic 2-DOF, `df` and MAC

The truth is a genuine 2-DOF chain, `M = diag(1, 2)`, `k₁ = 2e5`, `k₂ = 1e5`,
solved as an undamped eigenproblem — the identified values are compared against
analysis, not against numbers the generator was handed:

```
f_truth = 31.978217 Hz, 88.560698 Hz     ζ_truth = 1.0 %, 1.5 %
FRF axis 0 … 400 Hz, df = 0.25 Hz (DC aligned, so no resampling in the iFFT)
```

Gate is |f_id − f_truth| < 1·df and MAC > 0.99.

| Case | f identified [Hz] | \|Δf\|/df | ζ [%] | MAC | coherence |
|---|---|---|---|---|---|
| clean, order 16, sweep | 31.97822, 88.56072 | 3.1e-06, 8.3e-05 | 1.0000, 1.5000 | 1.0000000, 1.0000000 | 1.000000 |
| clean, **order 4, single order** | 31.96447, 88.47180 | 0.055, 0.356 | 0.9828, 1.4890 | 0.9999530, 0.9999963 | 0.99988 |

| 0.5 % FRF noise, seed 19 | 31.97797, 88.56124 | 9.7e-04, 2.2e-03 | 0.9983, 1.4990 | 0.9999999, 0.9999999 | 1.000000 |

Worst frequency error over every gated case is **0.356 df** (the minimal
4-state realisation) and **5.7e-03 df** for the default over-determined one;
worst MAC is **0.9999530**. Both gates clear with orders of magnitude of
headroom.

Hankel geometry on the gate case: `r × c = 16 × 1584` blocks of `2 × 1`,
`dt = 0.0025 s` (`f_range=(1, 200)` narrows the band before the iFFT, so the
pulse response is sampled at 400 Hz). Singular-value spectrum, normalised:

```
1.000000  0.920770  0.912919  0.859893 | 0.020948  0.015829  0.000875  0.000401
```

— exactly four significant values with a factor-41 drop at the fifth, which is
the paper's order-selection criterion. The floor is not zero because
band-limiting the FRF at 400 Hz leaves the sampled response only *nearly* a
4-state exponential sum; the test asserts `s₄/s₀ > 0.5` and `s₅/s₄ < 0.05`
rather than pretending it is exact.

Multi-reference check (3 modes, 6 outputs, 2 inputs at DOFs 1 and 4, 1 % noise,
seed 3): f = 12.00023 / 41.00041 / 88.00135 Hz (|Δf|/df = 9e-04, 1.6e-03,
5.4e-03), MAC = 0.9999999 / 0.9999986 / 0.9999462, coherence ≥ 0.99967.

## Notes for the parent

* `era` is ready for top-level `_EXPORTS`; it imports on this tree and both the
  frozen spellings above resolve.
* R10-F4's CLI verb can call `femtools.mpe.era.era` directly. The FRF path
  needs only `frf` + `freq_hz` + `n_modes`; everything else has a default that
  clears the gate.
* Two names beyond the brief are exported because the CLI/examples want them:
  `era_realization(markov, order, ...) -> (A, B, C)` for the raw realisation and
  `markov_hankel(markov, r, c, offset=0)` for the block Hankel matrix. Drop them
  from `_EXPORTS` if the parent prefers a one-name surface — `era` alone is the
  contract.
* Deliberately *not* implemented (documented in the module docstring): ERA/DC,
  the later EMAC / MPC indicators of the Pappa papers, and the direct
  feedthrough term `D`. `first=1` is the hook for a Markov sequence whose first
  entry is `D`.
