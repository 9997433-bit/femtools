# R3-F4 report — CLI pretest ranks translational free DOFs

Agent: R3-F4 (claude-fable-5-thinking-xhigh). Exclusive paths only; no git operations performed.

## Scope delivered

`femtools pretest` now builds its EFI candidate set with
`femtools.pretest.candidates.translational_dofs(modal)` and ranks only the
translational (X/Y/Z) DOFs of the free set — rotations and SPC-constrained /
inactive rows are excluded — exactly as recommended in the R2-O3 handoff note.
No other command changed behavior.

## Why it mattered (measured)

On a 10-element BEAM2 cantilever (11 nodes, node 1 fully clamped, `-n 6 -s 10`)
the old code ranked the raw 66-row mode matrix and its entire top-10 was
**rotational DOFs** (3RZ, 3RY, 6RY, 6RZ, 11RY, 11RZ, 10RZ, 10RY, 7RZ, 7RY) —
none of which an accelerometer can measure. The new code ranks the 30
translational free DOFs (node 1's 3 constrained translations dropped) and
selects physical bending sensors: 11Z, 11Y, 8Y, 8Z, 4Z, 4Y, 5Y, 5Z, 7Z, 7Y.

## Design

- **`_pretest_candidates(modal)`** — lazy-imports `translational_dofs` and
  slices the solved `ModalResult`. Returns `None` (→ graceful fallback, see
  below) on `ImportError` or when the slice fails (`TypeError` / `ValueError`
  / `KeyError`, e.g. a modal result without a usable DOF map) or comes back
  empty. `translational_dofs` defaults (`components=(1,2,3)`,
  `active_only=True`) already intersect with `modal.free_dof` and drop
  zero-motion rows, so SPC'd DOFs are excluded without extra CLI logic.
- **Ranking call** — `effective_independence(cand.phi, n_sensors=…,
  candidate_dofs=cand.dofs)`, so the reported ids stay *global* DOF row
  numbers (same id space as before the change; verified 11Z ↔ row 62 =
  (11−1)·6+2). The existing duck-typed unpack of the result object is kept.
- **Output** — a `candidates: N translational free DOFs (M constrained/inactive
  DOFs dropped)` line, a new left-aligned `sensor` column with
  `CandidateSet.labels` (e.g. `11Z`), and the JSON payload keeps the
  `dof_ids`/`efi` keys unchanged and adds `labels`.
- **Edge cases** —
  - `--n-sensors` above the candidate count: warning on stderr, clamped to
    all candidates (previously the larger raw matrix masked this; hard-failing
    on the default `-s 10` for small models would be a regression).
  - `--n-sensors` below the number of target modes: `ValueError` from EFI is
    caught → clean `error:` line, exit 2 (previously an unhandled traceback).
  - Candidate slicing unavailable: warning on stderr, falls back to the old
    raw-matrix ranking (old table layout, no label column), exit 0. Note a
    truly *missing* `candidates.py` makes `femtools.pretest` itself
    unimportable (the package `__init__` imports it), which the existing
    `_missing` path already reports as exit 3 — unchanged.

## Gaps / handoff notes

1. The CLI still treats all `--n-modes` solved modes as targets; it does not
   run `effective_mass`/`select_target_modes` to pick targets by effective
   mass fraction. A `--f-max`/`--mass-fraction` flow would be the natural
   Round-4 extension.
2. `--n-sensors` clamping (rather than erroring) when it exceeds the candidate
   count is a deliberate UX choice; flag if strictness is preferred.
3. For the test owner: `CliRunner` cases worth adding — top-N contains no
   `R*`-labelled DOFs for a clamped beam; JSON payload has `labels`; `-s` below
   target modes exits 2.
