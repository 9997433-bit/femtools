## What changed

### New: `src/femtools/dynamics/system.py` (398 lines)

`as_system(K, M=None, *, assemble=None) -> SystemMatrices` is the single place that answers
"what am I solving". It accepts, in this order:

1. an existing `SystemMatrices` (so a resolved system can be reused without re-assembling);
2. `(K, M)` — two matrices, unchanged, and with **no** import of `femtools.fea`;
3. an `AssemblyResult`, or anything exposing `Kff`/`Mff`/`free_dof`;
4. a `ModalResult` carrying the assembly it was solved from;
5. a model database — anything `assemble_km` accepts, assembled here.

Cases 3–5 solve the **free-free partition** `Kff`/`Mff`, not the global matrices. That is
not a detail: the global `K` has empty rows wherever a DOF is SPC'd or carries neither
stiffness nor mass, so `Z(w)` built from it is singular by construction and the FRF would be
meaningless. Row *i* of the resolved system is free DOF *i*.

`femtools.fea` is imported lazily, inside the branches that need it. Importing
`femtools.dynamics` still loads zero `femtools.fea` modules and a pure-numpy `direct_frf`
still runs, which is the property R1-O2 established and I did not want to spend.

`SystemMatrices` carries the matrices plus the bookkeeping needed to address them:

- `resolve(spec, name)` — everything `resolve_dofs` accepted still means *rows of the solved
  system*; a mesh-backed system additionally accepts `(node_id, component)` pairs and
  `{node_id: components}` mappings, with the component spelled as an index, a label
  (`"uz"`, `"rx"`) or a Nastran digit (`"3"`).
- `align_modal(modal)` — `solve_modes` returns modes over the *global* DOF space with zeros
  on the constrained DOFs, while the system solves the free partition. Such a basis is
  restricted to `free_dof` instead of failing on a shape mismatch.
- `solve_modal(n_modes=None)` — normal modes from the source assembly, aligned.
- `C` — damping that came *with* the source (`DAMPER` elements, an assembly-time Rayleigh
  term). It is added to whatever the `damping` argument produces, so a model that carries
  its own dampers does not silently lose them.

The `(node, component)` form is unambiguous against a list of row indices: a *sequence of
length-2 sequences* is read as pairs, so `[(7, 2)]` is node 7 component 2 while a flat
`(7, 2)` still means rows 7 and 2, exactly as before.

### `frf.py`

`direct_frf` gains `M: Any = None`, keyword-only `assemble` (kwargs for `assemble_km`), and
routes through `as_system`. `modal` may additionally be the string `"auto"`, which solves the
complete basis from the source — `ModalDamping` needs a basis to build
`C = M Phi diag(2 zeta w_r) Phi^T M`, and on a mesh source there is no reason to make the
caller run the eigensolve by hand. It is opt-in rather than automatic because a complete
eigensolve is not something a solver should do behind the caller's back; when the basis is
missing and the source could provide one, the existing error now says so.

`meta` keeps `ndof`, `sparse` and `damping`, and gains `source` plus — for a mesh source —
`assembly`, `dof_map`, `free_dof`, `input_dofs`/`output_dofs` (global numbers) and
`input_labels`/`output_labels` (`(node_id, component)`). Keeping the `AssemblyResult` there
means a second call costs nothing.

`verify_modal_vs_direct` gains the same first-argument freedom, plus `full_modes`. `modal`
may now be omitted when the source can produce a basis, so the whole acceptance case is

```python
res = verify_modal_vs_direct(
    model, inputs=[(17, "uy")], outputs=[(17, "uy"), (9, "uy")],
    damping=rayleigh, n_modes=20, full_modes=21, n_lines=300,
)
res["rel_l2"]                     # 2.228264e-02
res["fmax_hz"], res["band_hz"]    # 1113.186959, (222.637392, 890.549567)
```

`full_modes` sizes the basis solved internally. It defaults to the complete spectrum,
because that is what makes a `ModalDamping` `C` — and hence the comparison itself — exact.
Damping with a physical form of its own (Rayleigh, structural, explicit `C`) does not need
it, so on a large model `full_modes = n_modes + 1` avoids paying for the full spectrum; on
the cantilever above the two agree to 3.9e-13. DOF selections are resolved once, up front,
whenever the system can address nodes, which is also what guarantees the modal and direct
sides look at the same DOFs. A plain-matrix system passes the selection through untouched so
that a basis carrying `dof_ids` keeps its own label handling.

The new `system` key in the returned dict lets a caller reuse the assembly.

### `harmonic.py`

Same treatment, kept deliberately narrow: `K` alone may be an assembly or a model, and the
`{dof: amplitude}` load mapping then also takes `(node_id, component)` keys. `method="auto"`
is unchanged — a bare `K` with no `M` is still not a usable system, so it still falls back to
the modal branch rather than raising.

## Verified equivalence

On the 16-element cantilever of `tests/conftest.py` (102 global DOFs, 96 free), driving and
measuring the tip and mid-span `uy`, all eight of these produce a **bit-identical** `H`:

| call form |
|---|
| `direct_frf(asm.Kff, asm.Mff, rows_in, rows_out, f, damping)` (today's form) |
| `direct_frf(asm, inputs=rows_in, ...)` |
| `direct_frf(model, inputs=rows_in, ...)` |
| `direct_frf(modal_result, inputs=rows_in, ...)` |
| `direct_frf(as_system(model), inputs=rows_in, ...)` |
| `direct_frf(model, inputs=[(17, "uy")], outputs=[(17, "uy"), (9, "uy")], ...)` |
| `direct_frf(model, inputs={17: "uy"}, outputs={17: "uy", 9: "uy"}, ...)` |
| `direct_frf(model, inputs=[(17, 1)], ...)` and `[(17, "2")]` (Nastran digit) |

`verify_modal_vs_direct` off the model reproduces the hand-built matrix call exactly
(`3.275859e-02` both ways, delta 0), including the band: `fmax = 1113.186959 Hz`, identical
to the value `tests/test_frf.py` computes by hand. Assembly-time Rayleigh damping
(`assemble_km(model, rayleigh=...)`) reproduces the same FRF as passing that Rayleigh model
through `damping=`, i.e. the source's own `C` is picked up correctly.

## The all-modes floor on a real mesh is the eigensolver, not the FRF

Worth stating precisely, because the headline "all-modes 1e-14" does **not** survive onto a
beam model, and it is not this code path that loses it.

On the cantilever, complete basis, `zeta = 0.01`:

| complete basis from | rel L2 |
|---|---|
| `scipy.linalg.eigh(Kff, Mff)` | **2.7563e-14** |
| `femtools.fea.eigen.solve_modes` (what `modal=None` / `"auto"` uses) | 6.5366e-10 |

Same assembled matrices, same code path, same band — so the model path preserves the
machine-precision property, and the four decades are entirely the eigensolver's accuracy at
the top of the spectrum. Supporting measurements: `cond(Kff) = 2.11e7`, eigenvalue spread
`3.80e7`, frequencies 4.362 Hz to 26.89 kHz; `Phi^T M Phi - I` is 1.11e-15 (the basis is
perfectly orthonormal), but the max eigenpair residual `|Kv - lam Mv| / |Kv|` is 1.998e-07
and the frequencies differ from `eigh` by up to 4.328e-10 relative.

That is the signature of shift-invert asked for the *whole* spectrum: `lam = sigma + 1/mu`
amplifies the round-off in a small `mu` by the eigenvalue spread, giving `eps * 3.8e7 ~ 4e-9`
— which is what is measured. The error is in the highest modes, and their content is exactly
what a complete-basis comparison depends on. Requested-count sweep, max relative frequency
error against `eigh`:

| n_modes | 10 | 20 | 40 | 96 (= n_free) |
|---|---|---|---|---|
| error | 4.67e-11 | 4.91e-11 | 8.53e-11 | 4.33e-10 |
| path | eigsh + Rayleigh-Ritz | eigsh + Rayleigh-Ritz | eigsh + Rayleigh-Ritz | dense-shift-invert |

6.5e-10 is a perfectly good number and nothing here needs fixing for the contract; I am
flagging it so that nobody writes a `1e-14` assertion against a model-solved basis and then
goes looking for the bug in `frf.py`. Use the synthetic-matrix case for the machine-precision
claim and `< 1e-8` for a mesh.
