## What landed

### 1. `TET10` — ten-node quadratic tetrahedron

```python
from femtools.fea.elements import tet10       # registered as etype "TET10"
```

* Registered in `fea/elements/solid.py` with `n_nodes=(10,)`, `dofs_per_node=(0, 1, 2)`,
  `family="solid"`, aliases `CTETRA10`, `TETRA10`, `C3D10`, `TET10N`.
  `CTETRA` / `TET` still resolve to `TET4`; `TET4` still accepts four nodes only.
  Imported from `fea.elements` so the registry fills on `import femtools.fea`.
* Shape functions in volume coordinates: `N_a = L_a (2 L_a − 1)` at the four corners and
  `N = 4 L_a L_b` at the six midsides, with nodes 5–10 bisecting edges 1-2, 2-3, 3-1, 1-4,
  2-4, 3-4 — the ordering Nastran `CTETRA` (G5..G10) and Abaqus `C3D10` both use, exported
  as `TET10_EDGES`.
* Stiffness on the classical four-point symmetric rule (`tet_rule(2)`). With straight edges
  the Jacobian is constant, `B` is linear and the rule is exact, not approximate; it is also
  the minimum rule that leaves the 30×30 matrix at rank 24, i.e. six rigid body modes and no
  mechanism.
* Consistent mass on Keast's fifteen-point degree-five rule, added as `tet_rule(order >= 4)`
  in `fea/quadrature.py` (`tet_rule(1)` and `tet_rule(2..3)` are unchanged, bit for bit).
  `N_i N_j` is quartic, so the stiffness rule would have got the mass wrong.
* `lumped_mass=True` uses **HRZ** diagonal scaling (Hinton, Rock & Zienkiewicz 1976), not
  row sums: `∫N dV` of a corner function of a `TET10` is `−V/20`, so row-sum lumping would
  hand four nodes a negative mass. The test measures that `−V/20` and the positive HRZ
  diagonal side by side.
* Degenerate (collapsed) and folded (midside pushed past the quarter point, Jacobian sign
  change inside the element) geometry is refused with a named error, as for `HEX8`.
  A consistently reversed node ordering is still accepted.

### 2. Stress / strain recovery for `TET10`

* `_tet10_recovery` in `fea/recover.py`, evaluated at the natural centroid
  `L = (¼, ¼, ¼, ¼)`. A quadratic tet has a linear strain field of its own, so the centroid
  value is a choice; with straight edges it is *exactly* the mean of the four Gauss point
  values the stiffness was integrated with, which the test checks element by element.
  `recover_strain` is the same call, as for every other type.
* `verification.PATCH_TYPES` is now
  `("BAR2", "BEAM2", "TRIA3", "QUAD4", "TET4", "TET10", "HEX8")`, so the existing
  parametrized patch tests of `test_round7_o1.py` and `test_round8_o1.py` cover `TET10`
  without those files being touched.
* New public patch-mesh builder `verification.tet_patch_model(etype, distortion=)`
  (the old private `_tet_patch_model` grew an `etype` and became public). `TET10` gives
  4 elements / 15 nodes / **5 free nodes**: the enclosed corner *and* the midsides of the
  four interior edges. Also new: `tet_cantilever` / `tet_bending_ratio` (six tetrahedra per
  brick, Kuhn's decomposition, conforming) and `tet10_rigid_body_frequencies`.
* `stress_patch_error` gained two keys, `spr` and `spr_terms`. Existing keys are unchanged.

### 3. `recover_spr` — Zienkiewicz–Zhu superconvergent patch recovery

```python
from femtools.fea.recover import recover_spr   # also femtools.fea.recover_spr
recover_spr(stress_result, model, *, nodes=None, index=None) -> NodalStressResult
```

* A linear polynomial fitted by least squares over the patch of elements incident on a node,
  sampled at the element centroids — the superconvergent points of a linear element — and
  evaluated at the node. Same two positional arguments as `average_nodal`, so one can be
  swapped for the other; returns the same `NodalStressResult`, with `location="spr"`.
* Exactness is structural rather than a matter of tolerance. The offsets are measured from
  the node, so the polynomial there *is* its constant term; the basis columns are accepted
  one at a time by modified Gram-Schmidt so the constant column is always in and the fit is
  never a minimum-norm guess; and the fit is taken on the deviation from the patch mean, so
  a constant field comes through at the round-off of a mean.
* Boundary patches are the known weak spot of SPR (ZZ borrow an interior patch for them).
  femtools takes the other documented route and lowers the polynomial order:
  `SPR_MAX_AMPLIFICATION = 20` bounds how much the fit may magnify the scatter of its own
  samples, and terms are dropped until it does — in the limit back to the arithmetic mean.
  Without that guard a two-sample exactly-determined extrapolation turned 6e-16 of round-off
  into 1.6e-12 on the HEX8 patch.
* `NodalStressResult` gained one optional field, `patch_terms` (how many polynomial terms
  each node got, 1–4). `average_nodal` leaves it empty and is otherwise **untouched**: still
  the unweighted `1 / n_a` mean, still `location="node"`, re-measured entry for entry in the
  new test module.
* `TET10` is **not** skipped by SPR: its centroid values are used as patch samples. This is a
  documented departure from the 1992 paper — the superconvergent points of a quadratic tet
  are its four Gauss points, not its centroid — so for `TET10` the result is an honest
  constant-exact least-squares patch fit rather than a formally superconvergent one. Said in
  the module docstring, in the `recover_spr` docstring and in a test docstring.

## Notes for the parent

* `available_elements()` and `element_info()` now include `TET10`; anything that pins the
  element list verbatim (docs `CONTRACT_API.md`, PRODUCT_MAP rows) needs the extra row.
* `stress_patch_error` returns two extra keys (`spr`, `spr_terms`) — additive only.
* Known caveat worth carrying into SOTA: a `TET10` with genuinely **curved** edges (midside
  nodes moved off the middle) only passes the constant-stress patch test to the accuracy of
  the four-point quadrature, because the Jacobian then varies inside the element. The shipped
  patch and cantilever meshes keep midsides at the middle of their edge, and the element
  docstring says so.
