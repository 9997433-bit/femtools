## 1. `mpe/frf_estimation.py` — Welch H1 / H2 / coherence

Segment-averaged auto- and cross-spectra behind one `welch_spectra`, with `estimate_h1`,
`estimate_h2`, `coherence`, `multiple_coherence` and a `FRFEstimate` result carrying `H`,
`coherence`, `freq_hz` and `n_averages`.

Validation is against a transfer function that is known in closed form rather than approximated:
the simulator is an exact zero-order-hold discretisation of a 3-mode modal model, so its
*discrete-time* response `C (zI - A)^-1 B` is the truth. (Comparing against the continuous-time
FRF would have charged the estimator for the ZOH half-sample lag, which is a property of the
sampling, not of H1.)

**H1/H2 is exactly the coherence.** The identity `H1/H2 = gamma^2` holds to
**8.9e-16** — machine precision, not "close" — over the whole band, at every noise level tested.
This is the single sharpest available check that the three spectra are averaged consistently:
a mismatched window normalisation, a stray detrend or an off-by-one in the overlap all break it
immediately.

**H1 is right when the noise is on the output, H2 when it is on the input**, and the crossover
is quantitative. With 5 % output noise (`fs = 1024 Hz`, 200 s, `nperseg = 4096`, 99 averages):

| estimator | median relative error, 5–150 Hz | off-resonance L2 |
|---|---|---|
| H1 | **7.55e-2** | 1.70e-2 |
| H2 | 7.87e-1 | 3.59e-1 |

Turning the noise around, H1 attenuates by exactly the textbook factor while H2 does not:

| input noise | median `|H1|/|H_true|` | median `|H2|/|H_true|` | predicted H1 bias `1/(1+r^2)` |
|---|---|---|---|
| 0 % | 1.00014 | 1.00032 | 1.00000 |
| 10 % | 0.99035 | 1.00131 | 0.99010 |
| 30 % | 0.91682 | 1.00176 | 0.91743 |
| 50 % | **0.79851** | **1.00149** | **0.80000** |

The measured H1 attenuation tracks the prediction to within 0.2 % of itself across the whole
range, and H2 stays flat at 1.0015. That is the theory reproduced, not merely illustrated.

Averaging / resolution trade-off on clean 400 s data (relative L2 over 5–150 Hz):

| `nperseg` | averages | `df` | full band | off-resonance |
|---|---|---|---|---|
| 1024 | 799 | 1.000 Hz | 5.84e-1 | 3.19e-1 |
| 4096 | 199 | 0.250 Hz | 1.52e-1 | 1.96e-2 |
| 16384 | 49 | 0.062 Hz | **1.35e-2** | 4.87e-3 |

The full-band error is dominated by leakage at the lightly damped peaks (`zeta = 0.01` at 93 Hz
needs the resolution), which is why the off-resonance column improves an order of magnitude
faster. This is bias from finite resolution, not variance from too few averages — more averaging
at 1024 lines would not have helped.

**Documented limitation.** `estimate_h2` is only defined elementwise for single-input data and
for square MIMO problems, because H2 inverts the *input* cross-spectrum: with more outputs than
inputs there is no square system to invert without choosing an arbitrary sub-block. Rather than
silently pick one, `estimate_h2` raises for `n_out != n_in` in the multi-input case and points at
`estimate_h1`. For single-input data it is computed per output as `G_yy,oo / G_xy,o`, which is
what preserves the `H1/H2 = gamma^2` identity above.

## 2. `mpe/ssi.py` — covariance-driven SSI

`ssi_cov` with `output_covariances` and `block_toeplitz` exposed separately, `"none"` and `"cva"`
weighting, reference channels, a multi-order stabilisation sweep and a modal-contribution score
that separates physical from computational poles at a single order.

4 modes (8 / 21 / 39 / 62 Hz, `zeta` = 1.0 / 1.5 / 2.0 / 1.2 %), 6 outputs, `fs = 256 Hz`,
300 s of output-only response, order 30:

| case | max `|df|/f` | max `|dz|/z` | min MAC | wall |
|---|---|---|---|---|---|
| 0 % noise | 3.37e-4 | 0.068 | 0.99998 | 0.02 s |
| 2 % noise | **3.16e-4** | **0.078** | **0.99995** | 0.02 s |
| 10 % noise | 2.93e-4 | 0.089 | 0.99980 | 0.02 s |
| CVA weighting | 3.85e-4 | 0.091 | 0.99996 | 0.02 s |
| 3 reference channels of 6 | 3.47e-4 | 0.059 | 0.99995 | 0.02 s |
| single order, no stabilisation | 5.12e-4 | 0.071 | 0.99996 | 0.01 s |
| 60 s record instead of 300 s | 3.65e-3 | 0.351 | 0.99903 | 0.01 s |

FDD and EFDD on the *same* data, for scale: FDD 3.80e-3 frequency error and 100 % damping error;
EFDD 5.49e-4 and 148 % damping error, at 0.89 s and 0.12 s respectively. SSI-COV is an order of
magnitude better on frequency, more than an order of magnitude better on damping, and roughly
45x faster than FDD here — which is the whole reason the method is worth having alongside the
FDD family already in the tree.

Two honest observations. Damping is 20–50x less accurate than frequency in every row; that is
intrinsic to the estimator and to a finite record, not a bug, and the 60 s row shows it degrade
first (35 % damping error while frequency is still at 0.4 %). And CVA weighting does not help
here: on evenly-scaled synthetic channels it has nothing to correct for, so it costs a little
accuracy for nothing. It earns its keep on real data where channel noise levels differ, which is
why it is offered but not the default.

## 3. `updating/frf_updating.py` — WLS on FRF samples

`update_from_frf` fits over a selectable set of spectral lines, reusing the damped Gauss-Newton
loop of `update_model` so bounds, Bayesian regularisation, convergence control and the
`UpdateResult` contract are shared rather than re-implemented. Residual kinds: `log_magnitude`
(default), `magnitude`, `real_imag`, `real`, `imag`, `log_magnitude_phase`. Measured coherence
becomes inverse-variance sample weights. `frf_sample_function` and `modal_frf_samples` are
exposed so the same synthesis can be used to generate reference data.

**Real FE model**, 10-element BEAM2 cantilever with two material regions, driving-point FRF at
the tip DOF, truth `E1 = 1.10, E2 = 0.95`, start `[1.0, 1.0]`, 12 modes, 2 % modal damping:

| case | max `|dp|/p` | iterations | RMS residual |
|---|---|---|---|
| clean `log|H|`, 600 lines, 2–900 Hz | **0.00000 %** | 4 | 1.74e-2 → 5.17e-11 |
| clean `log|H|`, 60 lines | **0.00000 %** | 7 | 1.81e-2 → 3.21e-13 |
| 2 % FRF noise | **0.092 %** | 6 | 1.76e-2 → 1.93e-3 |
| 5 % FRF noise | **0.228 %** | 7 | 1.83e-2 → 4.82e-3 |
| clean, `real_imag` | 0.071 % | 3 | 1.37e+0 → 7.59e-3 |

The updated model is attached to the result, and re-solving it reproduces the measured
frequencies to **1.9e-10**, so the returned model really is the fitted one and not the nominal.

**Coherence weighting is the difference between a usable and a useless fit** when the SNR varies
across the band. With *absolute* measurement noise (constant `sigma`, so `gamma^2` collapses at
the anti-resonances where the response is small) on the 2-region reference beam:

| noise | mean `gamma^2` | unweighted | coherence-weighted |
|---|---|---|---|
| 0.005 `rms|H|` | 0.764 | 11.37 % | **0.024 %** |
| 0.020 `rms|H|` | 0.442 | 11.83 % | **0.083 %** |
| 0.050 `rms|H|` | 0.268 | 11.40 % | **0.197 %** |

Unweighted, the fit is dominated by anti-resonance lines that carry no information and sits at
~11 % error regardless of the noise level; weighting by `gamma^2` recovers two to three orders of
magnitude. When the noise is instead proportional to `|H|` the coherence is flat and weighting
correctly changes nothing (0.314 % either way) — the weights do exactly what they should and
nothing more.

**Why `log_magnitude` is the default, with numbers.** `real_imag` is the more informative
residual in principle (it uses the phase), and on well-resolved data it is fine. But near a
resonance whose peak has moved between model and measurement, the relative error in `Re H` and
`Im H` blows up while `log|H|` stays bounded. Sweeping the line resolution on the reference beam
(band 5–400 Hz, first 4 modes at 8.7 / 53 / 148 / 290 Hz, truth `[1.10, 0.95]`):

| lines | `df` | `log|H|` | `real_imag` |
|---|---|---|---|
| 200 | 1.99 Hz | 0.00000 % | 0.785 % |
| 400 | 0.99 Hz | 0.00000 % | **3.769 %** |
| 800 | 0.49 Hz | 0.00000 % | 1.928 % |
| 1600 | 0.25 Hz | 0.00000 % | 0.395 % |
| 3200 | 0.12 Hz | 0.00000 % | 0.492 % |

`log|H|` is exact at every resolution; `real_imag` is non-monotonic in the resolution and can be
4 % out where the peak sampling happens to be worst. That is a property of the residual, not of
the solver, so `log_magnitude` is the default and `real_imag` is offered for data where the
resolution is known to be adequate. Related: the default weighting is now `"unit"` for the
complex residual kinds (with an inverse-magnitude scaling applied inside `_default_weights`)
rather than `1/r^2` relative weighting, which would hand the fit to the zero crossings of
`Re H`.

## 4. `updating/selection.py` — parameter selection

`select_parameters` prunes the candidate set from the sensitivity matrix alone, before any
updating run. The default criterion is the parameter-space Effective Independence: since
`det(A_-j) = det(A) (A^-1)_jj`, dropping the parameter with the largest diagonal entry of `A^-1`
costs the least information, and because `1/(A_jj (A^-1)_jj) = 1 - R_j^2`, that single criterion
catches both insensitive and collinear parameters. Alternatives: `"qr"` (pivoted QR column subset
selection), `"forward"` (greedy D-optimal growth), `"sensitivity"` (column norm) and
`"correlation"`.

Test case: 16-element beam with **8** stiffness regions but only **4** measured frequencies —
deliberately rank-deficient, which is the situation that actually arises in practice.

EFI, pivoted QR and forward D-optimal growth **all select the same subset** `[E1, E5, E6, E7]`
with the same condition number (4.426) and the same minimum subset independence (0.3235). Plain
column-norm ranking picks `[E1, E2, E5, E6]` instead: condition number 6.091, minimum
independence 0.1209 — it sees magnitude and is blind to collinearity, exactly as advertised.
Auto-sizing with `max_condition=20` arrives at the same four parameters without being told how
many to keep.

Updating with and without the selection, 20 realisations of 0.2 % frequency noise, truth
perturbing the four selected regions to `[0.88, 1.12, 0.93, 1.07]`:

| | median max `|dp|/p` | worst |
|---|---|---|
| all 8 parameters | **50.000 %** | 50.000 % |
| 4 selected | **2.975 %** | 4.829 % |
| | *prediction error on the unfitted modes 5–8* | |
| all 8 parameters | 2.125 % | 2.319 % |
| 4 selected | **0.183 %** | 0.423 % |

The full-set number is 50 % in every single trial because the update runs straight into the
`bounds=(0.5, 1.5)` limit — with 8 unknowns and 4 equations there is nothing to stop it, and no
amount of regularisation would have made those four extra parameters identifiable. The selected
subset lands within 3 % and, more tellingly, predicts the four modes it was never fitted to an
order of magnitude better.

**Two reporting fixes this exposed.** `independence` for the full candidate set is identically
zero whenever there are more parameters than responses (the columns are then necessarily
dependent), which is correct but useless, so `ParameterSelection` now also carries
`subset_independence` — the `1 - R^2` of the retained parameters among themselves, which is the
number that matters. And `condition_number` is now computed over all `n_par` directions, so a
4x8 candidate matrix reports `inf` rather than the finite condition number of its row space:
saying "3.978" about a problem with a null direction would be actively misleading.

## 5. `optimization/surrogate.py` — quadratic RSM

`fit_rsm` / `predict_rsm` with `order` in `1` / `"interaction"` / `"pure-quadratic"` / `2`,
weighted least squares, optional ridge, multi-response fits, and an `RSMFit` carrying
`predict`, `gradient`, `hessian`, `stationary_point`, `coefficient_table` and `summary`.

Inputs are coded to `[-1, 1]` over the sampled range before any term is formed; fitting a modulus
in pascals next to a thickness in millimetres in physical units squares the spread of the design
matrix.

Exact recovery of a known quadratic in 3 variables from a 15-point central composite design:
R2 = 1.000000000000, Q2 = 1.000000000000, design condition number 8.778, and **1.5e-14** max
error on 500 unseen points.

FE response (first bending frequency of a 12-element beam with 3 stiffness regions,
`p in [0.6, 1.4]^3`), validated on a 200-point held-out LHS:

| plan | n | R2 | Q2 (LOO) | holdout RMS | holdout worst |
|---|---|---|---|---|---|
| CCD | 15 | 0.999623 | 0.995949 | 0.155 % | 0.403 % |
| LHS | 40 | 0.999796 | **0.999515** | **0.151 %** | 0.500 % |
| LHS | 80 | 0.999803 | 0.999712 | 0.162 % | 0.688 % |

The holdout error stops improving at 40 points because it is no longer fit error — it is the
quadratic model's inability to represent `f ~ sqrt(E)` exactly. Q2 tracks the true holdout
error closely, which is the point of computing it.

**Q2 catches over-fitting where R2 cannot.** Same FE response with 1 % noise, always 10 terms:

| n | R2 | R2_adj | Q2 |
|---|---|---|---|
| 10 | 1.00000 | nan | **nan** |
| 12 | 0.99928 | 0.99603 | **0.90758** |
| 20 | 0.99506 | 0.99061 | 0.97961 |
| 60 | 0.99249 | 0.99113 | 0.98983 |
| 200 | 0.99170 | 0.99130 | 0.99086 |

At `n = 12` R2 still says 0.9993 while Q2 has already dropped to 0.908. At `n = 10 = p` the
surface interpolates, every leverage is one and PRESS carries no information; reporting `nan`
there rather than the arithmetically-available 0.99997 was a deliberate choice — a spurious
`Q2 = 1` on an interpolating surface is worse than no number at all.

Canonical analysis of the fitted quadratic is exact: a known minimum at `[0.5, -1.0]` with
`y = 3` is returned as `[0.5, -1.0]`, `y = 3.000000000`, `kind = "minimum"`; `1 + x^2 - y^2`
is classified `"saddle"` with eigenvalues `[-2, +2]`. A near-singular Hessian is reported as
`"ridge"` with a pseudo-inverse step rather than a fabricated optimum.

## 6. `optimization/multi.py` — Pareto fronts

`pareto_weighted` traces a front by repeated scalarised minimisation through `size_optimize`, so
nonlinear constraints are honoured exactly at every point. Supporting API: `pareto_front`,
`non_dominated_sort`, `crowding_distance`, `simplex_lattice` (Das & Dennis) and `hypervolume`
(exact, by recursive slicing).

**The weighted sum cannot reach a concave front, and the Chebyshev scalarisation can.** On
`f1 = x`, `f2 = 1 - x^2`, `x in [0, 1]`, 21 weight vectors, hypervolume against `(1.1, 1.1)`
whose true value is 0.543333:

| method | points | interior points | hypervolume | % of true |
|---|---|---|---|---|
| weighted sum | 21 | **1** | 0.335000 | 47.9 % |
| Chebyshev | 22 | **20** | **0.519774** | **95.7 %** |
| weighted sum + NSGA | 45 | — | 0.528397 | 97.3 % |

The weighted sum returns the two anchors and nothing else, because no supporting hyperplane
touches a concave stretch — this is geometry, not a solver failure, and it is why the Chebyshev
option exists. On a *convex* front (`f1 = x^2`, `f2 = (x-2)^2`) both are correct: max deviation
from the analytic front 6.7e-7 (weighted sum, 38 objective evaluations) and **0.0e+0**
(Chebyshev, 142 evaluations) — the Chebyshev route is exact but roughly 4x more expensive,
since it carries an extra variable and one inequality per objective.

Constrained structural example, 3-bar sizing for mass against tip deflection with a 200 MPa
stress limit, 9 weights, Chebyshev: 10 non-dominated designs from 959 objective evaluations,
ideal `(0.405 kg, 2.143e-4 m)`, nadir `(16.2 kg, 8.571e-3 m)`, knee at 2.561 kg / 1.355e-3 m
with 31.6 MPa peak stress. Adding `refine="nsga"` gives 44 points at a worst stress of exactly
**200.0 MPa** — the constraint is active at the minimum-mass end and the constrained NSGA
respects it to the limit — and raises the hypervolume from 0.116171 to 0.121263.

Three problems found and fixed while measuring, all of which produced plausible-looking but
wrong fronts:

* A zero weight in the Chebyshev epigraph contributes the constraint `t >= 0`, which is not a
  statement about the design at all and pins the anchor runs short of their single-objective
  optima. Only objectives with a positive weight now get a row.
* Warm-starting one anchor from another lands on a stationary point of the objective now being
  minimised (`d f2/dx = 0` at exactly the point `f1` was minimised at), and a first-order solver
  stops there having moved nothing. Anchors now always start from `x0`, and any run that fails to
  improve on its warm start pays for one restart from `x0` — that single change took the concave
  front from 2 interior points to 20.
* The payoff table used for normalisation is frozen after the anchors. Letting it drift meant
  every interior weight solved a slightly different problem and the front came out unevenly
  spaced.

`ParetoResult` carries `success` and `feasible` separately, because they legitimately disagree:
SLSQP reports "positive directional derivative" when it stops on the min-max kink (1 of 10 runs
in the 3-bar case) with a perfectly good design in hand. The epigraph variable is snapped to its
exact value after each solve and the reported violation covers the *design* constraints only, so
`feasible` means what it says (10 of 10 there).

## 7. `rbpe` — `restraint=` and `mount_k=`

Both options added to `rigid_body_properties`, plus a public `mount_stiffness_matrix` that builds
the rigid-body `6x6` from a scalar, a diagonal, a matrix, or a physical list of springs.

**Mounting stiffness.** A suspension contributes `K`, and the response is
`A(w) = T_out [M - K/w^2]^-1 T_in^T`: the mounts act as an *apparent negative mass* `K/w^2` that
diverges as the frequency falls, which is why a mass line taken too close to the suspension modes
reads high. Given `mount_k` the fit is done line by line and the term is removed analytically.

12.5 kg body, CG `(0.10, -0.05, 0.20)`, full inertia tensor with products, 24 sensor channels,
6 inputs, on 4 vertical (900 N/m) and 2 lateral (400 N/m) springs — suspension modes at
0.84 / 0.88 / 2.61 / 4.68 / 4.94 Hz:

| band | mounts ignored | `mount_k` given | `mount_k="fit"` |
|---|---|---|---|
| 20–60 Hz | 3.01 % inertia, 0.72 mm CG | **0.000 %** | **0.000 %** |
| 10–30 Hz | 12.74 %, 2.95 mm | **0.000 %** | **0.000 %** |
| 6–15 Hz | 50.41 %, 10.66 mm | **0.000 %** | **0.000 %** |
| 4–10 Hz | **510.86 %**, 24.75 mm | **0.000 %** | **0.000 %** |

`mount_k="fit"` identifies `M` and `K` together — the equilibrium equations stay linear in the
pair — and recovers the stiffness to **0.0000 %** of `max|K|`, reproducing the suspension
frequencies `[0, 0.844, 0.879, 2.610, 4.677, 4.943] Hz` exactly. Even in the 4–10 Hz band, which
straddles the top two suspension modes, the fit is exact.

**Inertia restraint.** `restraint="inertia"` restrains the measured acceleration field to the
rigid-body subspace, `qdd = pinv(T_out) x_ddot`, and imposes Newton-Euler equilibrium
`M qdd = T_in^T F`, which is linear in `M` itself — no inversion of a fitted `M^-1`, and the
non-rigid part of the measured motion is discarded by the projection. Both fits now run in
length-scaled DOF so the force and moment equations carry comparable magnitudes.

With a flexible mode leaking into the 20–60 Hz band:

| first flexible mode | mass line | inertia restraint |
|---|---|---|
| 200 Hz | 0.451 % mass, 20.69 % inertia | **0.247 %**, **13.12 %** |
| 140 Hz | 0.935 %, 45.60 % | **0.530 %**, **27.89 %** |
| 90 Hz | 2.329 %, 144.23 % | **1.519 %**, **75.59 %** |

Consistently a factor of ~1.9 better on inertia, which is the projection doing exactly what it is
for.

**Two claims I tested and did not make.** Against purely *random* FRF noise the restrained
estimator is slightly *worse* than the mass line (2 % noise, 20 seeds: 6.96 % vs 5.03 % median
inertia error), because the noise then sits in the coefficient matrix rather than the right-hand
side, which biases least squares. And it does not reduce the number of shakers needed: with 4 or
5 inputs both estimators fail identically (condition number ~1e16), because a rank-deficient set
of rigid-body accelerations leaves part of `M` unobserved however the equations are arranged.
Both facts are written into the module docstring rather than left for a user to discover.

## Design notes

Everything went into **new modules** (`frf_updating.py`, `selection.py`, `surrogate.py`,
`multi.py`, `frf_estimation.py`, `ssi.py`) except the RBPE work, which had to extend
`rigid_body_properties` in place because the task was to add options to an existing signature.
That keeps `docs/CONTRACT_API.md` stable, avoids touching any file another R4 agent might be
editing, and means the existing `update_model`, `size_optimize`, `fdd`/`efdd` and mass-line paths
are byte-identical.

New code reuses existing machinery rather than duplicating it: `update_from_frf` drives the same
damped Gauss-Newton loop as `update_model`, `pareto_weighted` drives `size_optimize`, and
`ssi_cov` returns the same `ModalParameterResult` as the FDD family. Every public function has a
doctest, and all doctests pass under `pytest --doctest-modules`.

## Not done

* No tests were added under `tests/`, since that directory is shared and R4-O2 was writing there
  concurrently. Coverage of the new code is via doctests plus the probe scripts whose numbers are
  reported above; a follow-up agent owning `tests/` should convert the probes into
  `test_frf_estimation.py`, `test_ssi.py`, `test_frf_updating.py`, `test_selection.py`,
  `test_surrogate.py`, `test_multi.py` and RBPE mount cases.
* `estimate_h2` for non-square MIMO is deliberately unimplemented (see §1).
* The NSGA refinement is a compact NSGA-II, not a tuned one; it is a fallback for non-convex or
  noisy problems, not a competitive MOEA.
