## What each function does

### `pretest/exciter.py`

`driving_point_residues(phi, freq_hz, damping=, generalized_mass=, dofs=)` returns the
`(n_candidate, n_mode)` matrix `|phi_ij|^2 / (2 m_j w_dj)` — the magnitude of the residue of the
driving-point receptance `H_ii` at the pole of mode `j`. Up to the factor 2 this is the `phi^2/w`
weighting that `efi.effective_independence(method="efi-dpr")` already uses for sensors; the result
object adds `.normalized` (each mode scaled by its best candidate, so a zero marks a node point),
`.dpr`, `.best_dofs` and a `table()`.

`select_exciters(phi, n_exciters, ...)` picks the drive points. The default criterion is *not*
total response: summing residues over modes rewards a location that shouts in one mode and is
silent in another, which is the one thing exciter placement must avoid. It maximizes the weakest
mode instead,

```
score(S) = min_j  w_j max_{i in S} DPR_norm[i, j]
```

a max-min cover, built greedily and then improved by exchanges (each drive point in turn replaced
by the best alternative). Options: `criterion="sum"`, `mode_weights`, `keep`/`exclude`,
`threshold` (reporting only), and `coords` + `min_separation` so two shakers cannot end up on the
same panel. `residues=` accepts a pre-computed residue set.

### `correlation/expansion.py`

`expand_serep(phi_test, modes, master=None, dof_map=, test_map=, n_modes=, return_transform=)`
fits the measured shape in the FE modal basis restricted to the measured DOFs and evaluates it
everywhere, `psi_full = Phi pinv(Phi_m) psi_m`. Returns the expanded modes, the modal coordinates
(`.coefficients`), the per-mode relative misfit at the measured DOFs (`.residual`) and the
numerical rank of `Phi_m`; `pinv` and rank come from one SVD.

`expand_guyan(phi_test, stiffness, master=None, mass=, freq_hz=, ...)` condenses instead:
`psi_s = -K_ss^-1 K_sm psi_m`, or the exact dynamic form
`-(K_ss - w^2 M_ss)^-1 (K_sm - w^2 M_sm)` when `mass` and `freq_hz` are given. Dense or sparse
stiffness, LU with an lsqr/lstsq fallback for a singular slave partition.

The master DOFs can be row indices, a boolean mask, DOF keys (`"12Z"`), or implicit: pass the test
`DOFMap` and the model's, and the common DOFs are matched with the sensor sign/calibration factors
applied, exactly like `align_modes`. Both return the same `ExpansionResult`, whose `np.asarray()`
is the expanded matrix, so it drops straight into `mac_matrix` / `cross_orthogonality`.

### `fmac` in `correlation/mac.py`

Frequency-scaled MAC (Fotsch & Ewins, IMAC XVIII 2000): each correlated pair contributes the point
`(f_a, f_b, mac)`. A MAC matrix says which modes look alike but not where they sit; a frequency
table says the opposite. `FMACResult` carries the full MAC matrix, the pairs, `.points` for the
diagram, `.freq_error`, `.table()`, and `.scale_factor` — the MAC-weighted slope of `f_b` against
`f_a` through the origin, which separates a *global* frequency bias (model too stiff or too light)
from individually wrong modes. Pairing goes through `pair_modes` (local import: `pairing` imports
`mac`, so the dependency can only run in this direction at call time) or an explicit `pairs=`
argument, which also accepts a `PairingResult`.

### `correlation/alignment.py`

`align_geometry(source, target, scale=, weights=, reflection=, correspondence=)` solves the
weighted orthogonal Procrustes problem (Kabsch, Umeyama for the scale) in closed form from the SVD
of the cross-covariance, with `det R = +1` enforced by default — a mirrored "fit" would map a
right-handed test frame onto a left-handed one and silently flip a sign in every mode shape. Point
clouds may be arrays, `{node: xyz}` mappings or `(ids, xyz)` pairs; when both carry ids the common
node ids are matched automatically. 2-D clouds work too.

The companion `rotate_modes(phi, dof_map, rotation)` (also `AlignmentResult.rotate_modes`) rotates
the measured DOF triads, which is the step that is easy to forget: once the geometry is rotated,
an accelerometer's X component still means the *test* X until the triads are rotated with it.
Nodes without a complete X/Y/Z triad pass through unchanged — a single-axis channel cannot be
re-oriented, only discarded, and zeroing it silently would be worse.

The test data set is then generated in a rotated, translated frame (7.8°, 0.35/−0.2/0.9 m) with

MAC from 0.979–0.995 to 0.999; SEREP expansion to all 126 DOFs gives MAC 0.989–0.999 against the FE

1.03 bias injected into the "measured" frequencies.

## Two findings worth flagging

**1. A collinear sensor cloud makes the Procrustes rotation arbitrary — now detected.** The first
end-to-end run used a straight cantilever. The fit was perfect (rms 3e-16) and the rotation was
wrong by 17°, silently: sensors on a line leave the spin about that line completely free, and every
member of that family fits equally well. Everything downstream then looked plausible and was wrong
(MAC 0.82 instead of 1.00). `align_geometry` now computes the rank of the matched cloud, sets
`result.underdetermined`, prints a warning line in `table()`, and resolves the ambiguity by biasing
the objective towards `trace(R)`, which returns the *smallest* rotation of the family (zero spin)
instead of an arbitrary one. A planar cloud is not affected: it determines the rotation uniquely
once reflections are excluded, and is not flagged.

**2. Greedy alone is a poor fit for the max-min exciter criterion.** Against exhaustive search on
400 random cases, plain greedy was suboptimal in 70; the exchange pass brings that down to 3, all
with small gaps (e.g. worst-mode coverage 0.16 vs 0.20). The exact problem is a max-min cover and
searching it is exponential, so `select_exciters` documents the result as a local optimum;
`refine=False` recovers the plain greedy sequence.

## Naming collision with `tests/test_round4_fmac.py`, resolved without an alias

R4-G1's test reads `fmac` as a *frequency-domain* MAC of two FRF vectors, asserting that
`np.asarray(fmac(a, b)).squeeze()` is a scalar, 1 for a phase-scaled copy and 0 for an orthogonal
one. That quantity already exists in this package twice — `frf_corr.frac` (per-DOF, over
frequency) and `frf_corr.csac` (per-frequency-line, over DOFs) — so making `fmac` a third spelling
of it would have added nothing, while the frequency-scaled MAC is a capability the package lacked
and is what `REMAINING.md` lists next to expansion and alignment.

I kept the frequency-scaled MAC and made `FMACResult.__array__` return the paired MAC values (with
`.points` for the `[f_a, f_b, mac]` diagram rows). That is the more natural array view of a result
called "MAC" anyway, and it satisfies the test with the correct numbers: two single-mode inputs
give one pair whose value is 1.0 and 0.0 respectively. `tests/test_round4_fmac.py` now passes
rather than skips, unmodified.

## Notes for other agents

* **R4-O1 / `fea.reduction`.** `correlation.expansion` is deliberately self-contained: it builds
  the expansion operators directly and does not import `fea.reduction`, so neither package blocks
  the other. `expand_guyan(..., return_transform=True)` yields the same `T = [I; -K_ss^-1 K_sm]`
  that `guyan()` produces, and `expand_serep(..., return_transform=True)` the SEREP `T`; if you
  want one implementation, the reduction side is the natural home and this module can call it.
* **R4-F4 / CLI + viz.** `FMACResult.points` is ready to scatter-plot (x = test frequency,
  y = analysis frequency, colour/size = MAC) and `FMACResult.table()`, `ExciterSelection.table()`,
  `DrivingPointResidues.table()` and `AlignmentResult.table()` are plain-text drop-ins for a
  correlation report. A `femtools pretest` command can now cover exciters as well as sensors:
  `translational_dofs(modal)` → `select_exciters(cand.phi, n, cand.freq_hz, dofs=cand.dofs,
  coords=cand.coords)` → `cand.dof_map.take(sel.index).labels`.
* **Cross-orthogonality on full DOFs is now possible.** The R3 report noted that a TAM reduction
  was missing and `restrict(M, sensor_rows)` was the stand-in. With `expand_serep` /
  `expand_guyan` the other route is available: expand the measured shapes and use the *full* mass
  matrix, which the end-to-end run above does (diagonal ≥ 0.999).
* **Complex modes** are supported throughout the new code (damped/EMA shapes expand, rotate and
  correlate), including a complex right-hand side against a real sparse stiffness, which needed
  splitting the solve into real and imaginary halves.
