## 2. `src/femtools/__init__.py` — provisional lazy-export tier (PEP 562)

The 84 stable exports (`_EXPORTS` + 14 subpackages + `__version__`) are untouched
and remain the first 84 entries of `__all__` in their original order. Added:

* `_PROVISIONAL_EXPORTS` — 30 frozen Round-4 names → defining module, exactly the
  REMAINING.md list (incl. `SolverDriver` → `femtools.drivers.base`), plus
  `_PROVISIONAL_SUBMODULES = {"drivers"}`. Import-time asserts guard against a
  provisional name ever shadowing a stable one.
* `__getattr__` resolves provisional names lazily. Failure discipline:
  - scheduled module (or its scheduled parent package) absent → descriptive
    `AttributeError` ("frozen Round-4 API … not merged"), so `hasattr` probing
    works and `from femtools import name` degrades to a normal `ImportError`;
  - module present but symbol not yet added (today: `fea.eigen` without
    `solve_complex_modes`, pre-fmac `correlation.mac`) → same `AttributeError`;
  - module present but missing a *real* dependency → the original
    `ModuleNotFoundError` is re-raised unchanged (bugs are not masked; verified
    with an injected fake).
* `__all__` gains a provisional name **only when its definition is already in the
  tree**, so `from femtools import *` can never break on a missing R4 module.
  Presence is a filesystem probe (`_module_source` + `_defines_name` column-0
  def/class/assignment scan) — deliberately *not* `importlib.util.find_spec`,
  which executes parent `__init__`s that import numpy/scipy eagerly and would
  destroy the cheap import. Known, benign heuristic limits (documented in-code):
  names created via re-export or module-level `__getattr__` factories are missed
  from `__all__` (they still resolve via attribute access) until promotion.
* `TYPE_CHECKING` re-exports intentionally cover only the stable tier; static
  imports of not-yet-existing modules would fail every type-check run.

Names auto-promote with zero further edits: while I was testing, R4-O3 and R4-F2
landed `correlation/alignment.py`, `correlation/expansion.py`, `pretest/exciter.py`,
`io/pch.py` and `fmac` — `__all__` picked up all 8 names on the next interpreter
start and they resolve to real callables through the lazy path.
