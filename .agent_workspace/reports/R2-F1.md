## 1. Top-level public API (`src/femtools/__init__.py`)

The frozen `docs/CONTRACT_API.md` surface is now re-exported from `femtools`:
75 names (`__version__` + 60 contract types/functions + 14 subpackages), resolved
**lazily via PEP 562 `__getattr__`**. Rationale:

* `femtools.cli` and `femtools.gui.state`/`webapp` do `import femtools` at module top —
  eager re-exports from `__init__` would create import cycles. Lazy resolution makes cycles
  structurally impossible: subpackages are only imported *after* `femtools` is fully
  initialized.
* `import femtools` measured at ~9 ms (no numpy/scipy/matplotlib/typer at import time);
  each `femtools.<name>` access imports only the defining subpackage and caches the value
  in module globals.
* A `TYPE_CHECKING` block with PEP 484 redundant-alias re-exports (`X as X`) gives mypy,
  pyright and IDEs the full static view; `__dir__` covers interactive discovery.

Name-collision policy (documented in the module docstring): the top level exports the
types returned by the contract entry points — `ModalResult`/`StaticResult`/`AssemblyResult`
from `femtools.fea`, `FRFResult` from `femtools.dynamics.frf`. The `femtools.core.results`
containers stay reachable under their subpackage path.

`__version__` stays `0.1.0`, matching `pyproject.toml` (no release cut this round).
