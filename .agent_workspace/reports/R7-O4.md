## 1. `femtools.optimization.topometry`

```python
from femtools.optimization.topometry import topometry_optimize, TopometryResult
```

Element-wise sizing on a mesh the user already has: every designed element gets
its own design variable — the **thickness** of a shell (`QUAD4`, `TRIA3`) or a
**density scale** interpolated SIMP-style into the modulus (any isotropic
element, `HEX8`/`TET4` included) — and the material is redistributed for minimum
compliance,

```
min_x  c(x) = f^T u(x)   s.t.  K(x) u = f,  sum_e m_e x_e <= V*,  x_min <= x <= x_max
```

with `m_e` the element area (thickness design) or volume (density design).

This is the Sigmund distinction, and it is why the module is separate from
`topology_simp`: *topology* decides where material exists on a domain the
optimizer meshes itself (and `topology_simp` accordingly owns its structured
plane-stress Q4 grid and its own mini solver), *topometry* keeps the structure
and tunes how much material each existing element carries. Here the analysis is
the real kernel — `solve_static` on a real `FEModel` — so supports, loads,
shells, solids, nodal frames and drilling suppression all behave exactly as in
any other femtools run.

### Exact element sensitivities

The compliance gradient is the self-adjoint result
`dc/dx_e = -u_e^T (dK_e/dx_e) u_e`, and both element derivatives are closed form:

* **thickness** — a flat shell is *exactly cubic* in the thickness,
  `K_e(t) = t A_e + t^3 B_e` (membrane, MITC4 transverse shear and the drilling
  penalty scale with `t`, bending with `t^3`). `A_e` and `B_e` are recovered once
  from two element builds and verified against a third thickness, so
  `dK_e/dt = A_e + 3 t^2 B_e` costs nothing per iteration. Any element failing
  the check falls back to a central difference of its own matrix, and
  `result.extras["exact_sensitivities"]` reports which happened.
* **density** — with `E(x) = E_min + x^p (E_0 - E_min)` the element matrix is
  exactly proportional to the modulus (both `E` and `G` are scaled, so the
  MITC4 shear term follows), giving
  `dK_e/dx = p x^(p-1) (1 - E_min/E_0) K_e^0`.

Element energies are evaluated on `assembly.to_basic(u)` against basic-frame
element matrices, which is what makes the gradients right for an obliquely
oriented shell whose rotations are solved in a nodal triad.

| gradient audit (central differences, relative step 1e-4) | max abs error / max abs FD |
|---|---|
| thickness, 6-element QUAD4 plate | **3.62e-07** |
| density, 2-element HEX8 block | **3.33e-08** |

(The residual is finite-difference round-off, not model error: it falls as the
step grows to 1e-3 and rises as it shrinks to 1e-7.)

### Measured behaviour

`cantilever_plate()` in the test file: 0.9 x 0.45 m, 6x3 `QUAD4`, clamped edge,
1 kN transverse tip load, uniform 5 mm start, initial volume kept as the
constraint.

| run | compliance | volume | design |
|---|---|---|---|
| uniform 5 mm start | 708.82 | 2.025e-3 | — |
| OC, 60 iterations | **112.62** (-84.1 %) | 2.025e-3 (rel. error 2.1e-13) | 1.0 … 18.7 mm |
| SLSQP, 24 iterations | **106.03** (-85.0 %) | 2.025e-3 | 1.0 … 19.5 mm |
| HEX8 block, density, volfrac 0.5 | 0.5147 → **0.1085** (-78.9 %) | on the bound | 1e-3 … 1 |
| `TRIA3` plate (dict model) | 2414.9 → **105.8** (-95.6 %) | on the bound | 0.8 … 20 mm |

`min_size_ratio == 1.0` exactly in every case: topometry never moves a node, so
`element_size_ratios(result.model, model)` is the identity and no element can be
distorted or inverted. Thicknesses stay strictly positive (bounded below), and
the returned model — one private property, and for the density design one
private material, per designed element — reproduces the reported compliance to
1e-10 when solved independently.

### What the entry point offers

`design="auto"|"thickness"|"density"`, an `elements=` subset (everything else
frozen), `loads=` in any `build_load_vector` form (`loads=None` expands the
model's own `Load` records, whose force/moment *vectors* the load builder does
not read back), one of `volume_fraction` / `max_volume` / `mean_thickness` (the
default keeps the starting volume, i.e. pure redistribution), per-element
`bounds`, `method="oc"|"slsqp"` (SLSQP runs through the in-house
`size_optimize` with the same analytic gradients), Sigmund's sensitivity or
density filter generalised to an unstructured mesh via element-centroid
distances, plus `callback`/`verbose`.

`TopometryResult` carries `x` (the field the returned model holds — the
*filtered* one when a density filter is active, with the raw variables in
`extras["design_variables"]`), `compliance`/`initial_compliance`,
`volume`/`volume_limit`, `mean_thickness`, `improvement`, `feasible`,
`min_size_ratio`, `strain_energy` (which sums to `c/2` to 1e-9), `history`,
`to_dict()` and `summary()`.

The OC loop stops on the classic design-change tolerance (same measure and
default as `topology_simp`) or when a feasible design has stopped changing the
compliance. A minimum-compliance sizing problem with several near-equivalent
ribs keeps shuffling a few elements long after the objective has settled: on the
plate above the compliance is within 0.7 % of its 300-iteration asymptote by
iteration 60, while the design change needs ~166 iterations to fall below 1e-2.
Running out of iterations is therefore a normal, and reported, outcome.

**Not implemented** (documented in the module): stress or displacement
constraints, multiple load cases, frequency objectives, discrete penalisation of
thicknesses, composite ply "free-size" variables.

## 2. `femtools.updating.responses.static_displacement_response`

```python
from femtools.updating.responses import static_displacement_response
```

The static counterpart of `modal_response_function`: `p -> u(p)` at selected
DOFs, built on `solve_static`, so a model can be updated against measured
deflections (proof load, dial gauge, DIC) instead of — or alongside —
frequencies. The model is deep-copied per evaluation, displacements come back in
the basic frame, and measurement DOFs may be given as `(node, "uz")` pairs,
`(node, 2)` pairs, a `{node: "xyz"}` mapping, a `DOFSet`, plain global equation
numbers, or left as `None` to measure every loaded DOF. `scale=` rescales the
response (mm vs m), `solver=` accepts a callback returning either a
`StaticResult` or a bare vector.

| measurement | value |
|---|---|
| response at `p=1` vs a direct `solve_static` | identical, max abs difference **0.0** |
| 20 % modulus error recovered from 3 free-edge deflections | multiplier **0.8333333332** vs exact 5/6, relative error **1.18e-10**, 4 iterations |
| relative RMS response error after updating | **1.47e-10** |

A test also drives one `update_model` run on a residual concatenating a scaled
static deflection and two frequencies, recovering the parameter to <1e-6.

One caveat is pinned by a test rather than papered over: a `kind="E"` parameter
writes the modulus and leaves the shear modulus the material record stores
alongside it, so halving `E` on a MITC4 shell doubles the deflection only to
~1e-3 relative. Changing that would change `Parameter` semantics for every
existing user of the updating layer, so it stays as it is and is documented.
