## Task-by-task outcome

### 1. Dual writer signatures (KEEP) — verified, unchanged
`write_unv` / `write_bdf` / `save_project` all still accept `(path, model)` and
`(model, path)` via `io/_compat.coerce_path_model`. Verified byte-identical output
for both orders on all three writers. No code change needed.

### 2. Property extra bag + alias canonicalisation — DONE
- `Property` gained `attrs: dict[str, Any]` (default `{}`), positioned **after**
  all existing fields, so positional/keyword constructor use is unchanged.
- `FEModel.add_property` now splits keywords three ways:
  - exact/case-insensitive spellings of real fields are canonicalised
    (`IY`/`iy` → `Iy`, `T` → `t`, `K` → `k`, `NSM` → `nsm`, ...), plus common
    engineering aliases `area`→`A`, `thickness`→`t`, `Iyy`→`Iy`, `Izz`→`Iz`,
    and Nastran `I1`→`Iz`, `I2`→`Iy` (matches the PBAR reader's mapping);
  - conflicting aliases with different values raise `ModelError`
    (equal or `None` duplicates are merged silently);
  - anything else lands verbatim in `Property.attrs`, which is one of the
    nested containers `fea.protocols.get_any` searches — **nothing is dropped**.
- End-to-end verified: a cantilever built with `IY=`/`IZ=` spellings solves through
  `fea.solve_modes` to 8.354 Hz vs 8.353 Hz Euler-Bernoulli (brief item 8 closed);
  `get_any(prop, "As_y")` reaches bag entries; FSL `ADD PROP ... IY=...` path re-run green.
- `.ftproj` round-trips `attrs` (key omitted when empty, so old files are
  unchanged on disk and still load; `Property(**json)` keeps working).
- Scope note: `add_material` was left strict (unknown kwarg → TypeError). MAT1
  reuses names like `A` (thermal expansion), so a silent bag there invites
  collisions; fea deliberately never bag-searches material records either.

### 4. UNV material/property gap — closed for femtools round trips, documented for third parties
- `write_unv` now appends **private dataset 30000** (legal range is 1–32767;
  every catalogued dataset is ≤ ~3300, and conforming readers skip unknown
  numbers — verified against the SDRC UFF spec) containing the material and
  property tables as JSON behind a `FEMTOOLSCARDS 1 JSON` marker line.
  The payload is compact JSON with literal spaces re-escaped as `\u0020`, so it
  contains no space characters and survives arbitrary 78-column wrapping plus
  readers that `rstrip()` lines (ours does). All lines ≤ 80 chars.
- `read_unv` restores the dataset (order-independent, duplicate-id safe); a
  corrupt or newer-versioned dataset degrades to a `UserWarning`, never an error.
  Round trip verified including `Property.attrs`, `kappa`, names with spaces, and
  the pid→mid chain (`model.element_material()` works after reload).
- Remaining, documented gap (module docstring "Material/property gap" section):
  *standard* UFF has no material/property card for this subset short of the
  I-DEAS database dumps (1710/2437/...), so exchanges with third-party tools
  still carry geometry + property ids only. No invalid UNV is invented.
- `read_unv(...).model` and `load_project(...).model` are **always `FEModel`**
  (asserted under `warnings→error`; empty datasets yield an empty but valid model).

### 5. BDF TET10/HEX20 — warn (not crash), now aggregated
Already warn-not-crash in R1; hardened: one aggregated `UserWarning` **per card
type** (was one per element — a 100k-element TET10 mesh would have emitted 100k
warnings) with element count, first 5 ids, and a note that quadratic accuracy is
lost and orphan midside grids are eliminated by the assembler. Verified on
free-field TET10s and a small-field HEX20 with `+` continuations: correct corner
connectivity `(1,3,9,7,19,21,27,25)`, no exception.
