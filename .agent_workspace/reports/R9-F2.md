# R9-F2 — Nastran text SOL 101 static punch (still no OP2)

Branch: `cursor/r9-f2-sol101-d551` (base `cursor/femtools-cycle-c-d551`). No PR opened.

## Delivered

### `read_pch_static` (`src/femtools/io/pch.py`, exported from `femtools.io`)

* New sibling of `read_pch`: parses public punch `$DISPLACEMENTS` blocks
  (the layout `DISPLACEMENT(PUNCH) = ALL` punches in a SOL 101 run:
  `$TITLE/$SUBTITLE/$LABEL`, `$DISPLACEMENTS`, `$REAL OUTPUT`,
  `$SUBCASE ID = n`, then `G`/`S` point lines with `-CONT-`
  continuations) into a `core.results.StaticResult`. Original parser,
  same 72-column/sequence-number handling, Fortran `D` exponents,
  whitespace-split fields — no Nastran/pyNastran code, no manuals.
* Rows are labelled by `dof_index` exactly like `read_pch` (6 DOFs per
  `G` point, 1 per scalar point, nodes ascending); one column per
  `$SUBCASE`, `load_case` carries the subcase ids (1-based position when
  a block has no `$SUBCASE` header; a repeated `$SUBCASE` line without a
  fresh `$DISPLACEMENTS` header starts a new column). A single subcase
  returns 1-D `u` with a scalar `load_case`.
* Tolerant like the modal reader: eigenvector blocks (`$EIGENVALUE` /
  `$EIGENVECTOR`), complex-output blocks (`$REAL-IMAGINARY` /
  `$MAGNITUDE-PHASE`) and other result kinds (`$SPCF`, stresses, …) are
  skipped with one warning per kind; uneven subcase node sets are
  zero-filled with a warning; no readable displacement data raises
  `PchError`. Malformed data lines (`-CONT-` first, non-numeric fields)
  raise `PchError` with file/line context.
* `read_pch` is behaviourally untouched (it still returns `ModalResult`
  and skips `$DISPLACEMENTS`); its skip warning now hints at
  `read_pch_static`. Internally both readers share two new private
  helpers (`_read_point_line`, `_stack_point_blocks`) so the point-line
  grammar and the union-DOF-index construction cannot drift.

### `NastranPunchDriver` (`src/femtools/drivers/nastran.py`)

* `write_input(model, workdir, *, sol=103)` — **default stays SOL 103**,
  byte-identical to the Round-7 deck (pinned by
  `test_write_input_default_is_the_round7_sol103_deck`). `sol=101`
  emits a public linear-static case control instead: `SOL 101`, `CEND`,
  `TITLE`, `ECHO = NONE`, `SPC = <sid>` / `LOAD = <sid>` and
  `DISPLACEMENT(PUNCH) = ALL`; no `METHOD`, no `EIGRL`. The selected
  sids are the lowest SPC/LOAD set ids in the model (femtools default 1,
  matching what `write_bdf` emits); several set ids of one kind raise a
  `UserWarning` naming the one selected. Any other `sol` raises
  `ValueError`.
* `read_static(result_file)` — reads a SOL 101 punch via
  `read_pch_static` and returns its `StaticResult`. A `.op2` path raises
  `SolverError` naming OP2 as N/A (femtools ships no OP2 parser by
  design — same convention as the Round-8 RST/ODB messages).
* `run()` unchanged in contract (missing executable / non-zero exit /
  timeout / no `.pch` → `SolverError`, Round-7 messages intact); when a
  run leaves only a `.op2` next to the deck, the "no punch file" error
  now carries an OP2-is-N/A hint.
* `read_modal` untouched. `femtools/__init__.py` not touched (SOL 101 is
  a driver method, not a new top-level name, per REMAINING.md).
