## Landed

### 1. First-class TET10 in the text translators (public card layouts only)

Uses the parent-seeded `ELEMENT_NODE_COUNTS["TET10"] = (10,)`; no stiffness
implemented (O1 owns that). Node order is kept in card order everywhere —
4 corners then the 6 midsides, the convention shared by all four formats.

* **BDF** (`io/bdf.py`): a 10-node `CTETRA` now reads as `type="TET10"` with
  all 10 grid ids; `write_bdf` emits the 10-node `CTETRA` back (small-field
  `+` continuation). The 4-node `CTETRA` stays `TET4` (no warning). A partial
  midside set (5–9 nodes) still degrades to `TET4` with the aggregated
  midside warning. **HEX20 unchanged: one aggregated warning, drops to HEX8.**
* **CDB** (`io/cdb.py`): SOLID92/187 records with 10 distinct nodes stay
  `TET10` (degenerate records still collapse with the midside warning);
  `write_cdb` maps `TET10 -> SOLID187`, nodes 9–10 on the EBLOCK
  continuation line exactly as the reader consumes them. SOLID95/186
  (hex_quad) still midside-drops to HEX8.
* **LS-DYNA .k** (`io/kfile.py`): the documented two-line ten-node
  `*ELEMENT_SOLID` form with 10 distinct nodes stays `TET10`; `write_k`
  emits that same two-line form. Degenerate ten-node records keep the old
  drop path (warning text now says "degenerate TET10 -> TET4").
* **Abaqus .inp** (`io/inp.py`): `C3D10`/`C3D10M` <-> `TET10` (cheap dict
  additions; solid-section member check extended).

### 2. `read_pch_stress` (`io/pch.py`) — public punch `$STRESSES` text, no OP2

`from femtools.io.pch import read_pch_stress` (also re-exported from
`femtools.io` / listed in both `__all__`s, together with `PchStressResult`).

* Parses `$STRESSES` / `$ELEMENT STRESSES` blocks (80-column punch, same
  conventions as `read_pch` / `read_pch_static`: optional sequence numbers,
  `-CONT-` continuations, Fortran `D` exponents, `$SUBCASE` before/after
  the header, repeated `$SUBCASE` without a repeated header).
* Two data-line shapes: plain rows of up to 6 values in Voigt order
  `xx yy zz xy yz zx` (short rows zero-filled; >6 values — type-specific
  2-D layouts femtools does not decode — keep the first 6 with one
  aggregated warning), and the labeled solid layout (`X/Y/Z/XY/YZ/ZX`
  label-value pairs; the first occurrence per component = the `CENTER`
  group; per-corner repeats, direction cosines and principal `A/B/C`
  values ignored).
* Returns `PchStressResult`: `element_ids` ascending, `stress` `(n, 6)`
  for one subcase or `(n, 6, n_cases)` stacked (missing entries
  zero-filled with a warning), `load_case` id(s), `etypes` from
  `$ELEMENT TYPE` headers, plus `von_mises` / `index_of` helpers.
* `$EIGENVECTOR` / `$DISPLACEMENTS` / complex-output / other blocks are
  skipped with one warning per kind, never an error; no readable stress
  data raises `PchError`. `read_pch` / `read_pch_static` now hint at
  `read_pch_stress` when they skip stress blocks (their behaviour is
  otherwise untouched).

### 3. Driver (`drivers/nastran.py`)

* `NastranPunchDriver.read_stress(path)` wraps `read_pch_stress`; a `.op2`
  path raises `SolverError` naming OP2 as N/A (same policy as
  `read_static`).
* `write_input(..., stress=True)` opt-in adds `STRESS(PUNCH) = ALL` to the
  case control (both SOLs). **Default decks are byte-identical to Round
  7/9** — verified by the round-9 deck-layout tests staying green.
