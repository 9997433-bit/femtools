## 1. CLI smoke test + reproduced bug fixes

Smoke-tested every subcommand against a 10-element BEAM2 cantilever (`.json`,
`.ftproj`, `.unv`, `.bdf` variants), synthesized SDOF time histories, and an
update config. Verified: `solve-modes` (freqs match Euler-Bernoulli 8.355 Hz,
`-o`/`--plot`), `mac` (self, two-file, npz+model mix, `.csv`/`.npz`/heatmap),
`report-mac` (html/text, self/pair, square/non-square, freq/no-freq npz),
`reduce` (guyan/irs/serep/craig-bampton, master-DOF error paths, `-o`),
`estimate-frf` (h1/h2, fs-key and t-key data, coherence, peak at the true
resonance, `--plot`), `frf` (all damping specs), `update`, `pretest`,
`script`, `gui`.

Three reproduced bugs, all fixed in `cli.py`:

1. **`mac` crashed on non-square MAC matrices** (`femtools mac model.json
   modes.npz -n 4` vs 6 stored modes): `np.diag(np.diag(mac))` broadcast
   ValueError. Now prints diag stats only for square matrices and
   best-match/overall stats otherwise.
2. **`update` leaked raw tracebacks for bad JSON configs** (unknown
   parameter-descriptor keys or unknown top-level kwargs raised
   TypeError/ValueError through typer). Now caught at the CLI boundary →
   clean `error: invalid update configuration: ...`, exit 2.
3. **`solve-modes --plot --mode-index N` past the solved count** raised a raw
   IndexError from `viz.plot_mode`. Now validated → clean message with the
   valid range, exit 2.

The large mode-2..4 "errors" in `reduce --compare` on the cantilever are the
degenerate y/z bending pairs versus a y-only master set (index-aligned
comparison artifact), not a code bug — left as-is.

## 2. Optional plotly backend in `femtools.viz.plots`

- `plotly_available()`, `get_default_backend()`, `set_default_backend()` added
  and exported from `femtools.viz`. matplotlib stays the default;
  `set_default_backend("plotly")` raises ImportError when plotly is missing
  and leaves the default untouched.
- Every plot function (`plot_mesh`, `plot_mac`, `plot_frf`, `plot_mode`) takes
  `backend=` (None → process default). `backend="plotly"` returns a
  `plotly.graph_objects.Figure`; `outfile=` writes `.html`
  (`include_plotlyjs="cdn"`) or a static image via optional kaleido (clear
  RuntimeError with a hint when kaleido is absent). `ax=` plus plotly and
  `show_rotations=True` plus plotly are rejected with clear ValueErrors
  (rotation glyphs stay matplotlib-only).
- plotly is imported **only** inside a plotly-requested plot: verified
  `import femtools.viz` leaves no `plotly*` entries in `sys.modules`, and all
  functions behave identically with plotly uninstalled (tested before
  installing it).
- Shared geometry was factored (`_mode_geometry`, `_frf_curve`, `_frf_kind`,
  `_mode_default_title`) so both backends render the same wireframes/curves;
  matplotlib color spellings (`tab:*`, `"0.7"`) are translated for plotly.
- PNG producers are pinned to matplotlib regardless of the process default:
  `gui.state.render_png` (all three kinds) and the report heatmap embed in
  `viz.report._heatmap_base64`. Verified GUI PNGs and HTML-report embeds still
  work after `set_default_backend("plotly")`.
- Tested with plotly 7.0.0 (`pip install plotly`, matches the existing
  `viz` extra in pyproject): mesh/mode/mac/frf plotly figures + `.html`
  export all pass.

## 3. `femtools read-mesh` + INP/K suffix dispatch

`femtools.io.inp` / `femtools.io.kfile` do **not** exist in this tree yet
(R6-F2 owns them), so everything is lazy:

- `script/loading.py`: `.inp` → `femtools.io.inp.read_inp`, `.k`/`.key` →
  `femtools.io.kfile.read_k`, imported inside the suffix branch;
  `SUPPORTED_SUFFIXES` extended; reader results unwrapped duck-typed
  (`.model` attribute wins) in case F2 returns a container.
- New `femtools read-mesh FILE [-o out.ftproj] [--plot mesh.png]` prints a
  model summary (per-element-type counts, materials/properties/SPCs, stored
  results). Works today for `.ftproj/.json/.unv/.bdf/.nas/.dat`; `.inp`/`.k`
  currently exit 3 with the standard "module not available" message (no
  traceback, `cli.py` imports fine). Verified with fake
  `femtools.io.inp`/`kfile` modules injected into `sys.modules` that the
  dispatch loads INP/K decks correctly the moment F2 lands — no F4 change
  needed then. All other model-taking commands (`solve-modes`, `mac`, ...)
  gain the same suffix handling through the shared loader, as does the GUI
  (`/api/load` returns a clean 400 JSON error for `.inp` today).
