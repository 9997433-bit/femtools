## Implementation notes

**Vectorization.** Every criterion is a BLAS-level expression, no Python loop over DOFs, modes or
frequency lines. A full MAC is one `gemm`: 20 000 DOF × 16 modes takes 0.57 ms
(`benchmarks/bench_mac.py`, off-diagonal max 5e-34). FRAC/CSAC/CSF share one contraction helper and
accept an arbitrary reduction axis, so `(n_out, n_freq)` and `(n_out, n_in, n_freq)` arrays both work.
The two loops that remain are inherently sequential eliminations (EFI, MAC elimination); each of their
iterations is fully vectorized over the surviving candidates.

**Self-MAC diagonal.** When the second argument is omitted, is the same object, or compares equal
element-wise, `mac_matrix` takes a symmetric branch and writes an exact `1.0` on the diagonal (`0.0`
for null mode shapes), so `1 - min(diag)` is bit-exactly 0 rather than ~1e-16. The same branch is used
by `cross_orthogonality`. For a genuinely different but proportional basis the diagonal is 1 within
1e-15, well inside the 1e-10 contract tolerance. Results are clipped to `[0, 1]` for the unweighted MAC.

**Mass/weight operators.** Anything accepted as a mass or MAC weight may be `None` (identity), a
scalar, a 1-D lumped diagonal, a dense matrix, or a SciPy sparse matrix — the helper only requires
`@`. This keeps the correlation package independent of whatever `fea.assemble` returns.

**Hungarian pairing.** `pair_modes(method="hungarian")` maximizes the total MAC via linear sum
assignment. SciPy's `linear_sum_assignment` is used when importable; otherwise a pure-NumPy
shortest-augmenting-path (Jonker–Volgenant) solver takes over, so the package has no hard SciPy
dependency. The fallback was checked against SciPy on 300 random rectangular cost matrices (including
integer-rounded matrices to force ties): identical optimal cost in every case. Greedy pairing takes the
highest remaining MAC repeatedly and leaves modes unpaired rather than forcing a bad match;
`mac_threshold` and a relative `freq_tol` gate both methods.

**DOF mapping.** `DOFMap` is an ordered `(node, component)` list with a per-DOF sign/calibration
factor. It parses `"12Z"`, `"12:-Z"`, `"7RY"`, `(5, "z")` and the usual aliases (`TX`/`UX`/`T1`/`1`),
and `DOFMap.from_mapping` accepts a `{(node, comp): index}` dict, a `{node: [indices]}` dict, a
`{node: {comp: index}}` dict or a plain key sequence — so it should absorb whatever shape
`AssemblyResult.dof_map` takes without changes on either side. `align_modes` reduces a test and an
analysis mode set to their common DOFs in one call, applying the sensor sign so a reversed
accelerometer correlates correctly.

**EFI.** The effective independence distribution is computed as the row norms of the thin SVD's left
factor (`ED_i = ||U[i, :]||²`) instead of forming `(ΦᵀΦ)⁻¹`, which squares the condition number; a
relative singular-value cutoff keeps it defined for rank-deficient mode partitions. Verified equal to
`diag(Φ(ΦᵀΦ)⁻¹Φᵀ)` to 1e-12, and `sum(ED)` equals the number of independent target modes. Extras:
`mass` (kinetic-energy weighting), `method="efi-dpr"` (driving-point residue), `keep` for mandatory
sensors, and `batch` removal (integer or fraction) which cuts 2000→100 candidates from 1.2 s to 0.01 s
at a small optimality cost. Against exhaustive search on 20 random 9-candidate/3-mode problems, the
selected set reached the maximum Fisher determinant every time (ratio 1.000); against random sets of
equal size it won 50/50.

**MAC-based elimination.** `eliminate_by_mac` scores every candidate removal with a rank-one Gram
downdate `G - φ_q φ_qᴴ`, so one step evaluates all candidates in a single vectorized expression
(chunked to bound memory) instead of recomputing a MAC per candidate. Checked against naive
recomputation for real and complex modes: agreement to 1e-15. It is a greedy method, so it is not
guaranteed optimal — on adversarial random sets the retained max off-diagonal MAC was up to 0.23 above
the exhaustive optimum; on structured mode shapes it matched EFI.

**Effective mass.** `rigid_body_modes` builds the 6 unit rigid-body vectors about a reference point
(validated: `diag(RᵀMR)` reproduces the rigid-body mass matrix). `effective_mass` returns
participation factors, effective masses, totals, fractions and cumulative fractions; for a complete
mode set the effective masses sum exactly to `diag(RᵀMR)` (checked on a 5-mass chain: 10.0 vs 10.0).
`select_target_modes` filters by frequency band, then greedily adds the largest contributors until the
requested cumulative mass fraction is reached *in every direction*, with optional `n_modes` cap,
`min_fraction`, direction subset (by label or index) and `include`/`exclude`.

**Mass loading.** Default `method="modal"` solves the reduced eigenproblem
`diag(m_j ω_j²) x = λ (diag(m_j) + Φ_sᵀ diag(m) Φ_s) x` by Cholesky reduction and also returns the
loaded shapes and their MAC against the unloaded ones (so shape distortion is visible, not just the
frequency drop). `method="first_order"` gives the Rayleigh-quotient estimate `Δf/f = -½ Σ m_s φ_sj²`.
On the toy beam with 20 g at two stations the two agree to within 0.02 % of the frequency. Rotary
inertia and mount stiffness are not modelled, so the shift is a lower bound — documented in the module.
`sensor_mass_limit` inverts the first-order relation into a per-sensor mass budget.

## Toy EFI: 2 modes, 10 DOF (acceptance case)

Simply supported beam sampled at 10 equally spaced interior stations, `φ₁ = sin(πx)`,
`φ₂ = sin(2πx)`, lumped mass normalized so `ΦᵀMΦ = I`. Initial ED (sums to 2, the number of target
modes):

```
station x/L  0.091 0.182 0.273 0.364 0.455 0.545 0.636 0.727 0.818 0.909
ED           0.068 0.204 0.282 0.254 0.193 0.193 0.254 0.282 0.204 0.068
```

Selected sensors (0-based DOF indices) and the resulting off-diagonal auto-MAC of the two target modes:

| n_sensors | EFI selection | off-diag MAC | MAC-elimination selection | off-diag MAC |
|-----------|---------------|--------------|---------------------------|--------------|
| 2 | 2, 7 | 9.1e-33 | 2, 7 | 2.0e-33 |
| 3 | 2, 6, 7 | 9.48e-02 | 2, 6, 7 | 9.48e-02 |
| 4 | 2, 3, 6, 7 | 4.9e-33 | 2, 3, 6, 7 | 4.1e-33 |
| 5 | 2, 3, 5, 6, 7 | 6.5e-03 | 2, 3, 6, 7, 8 | 1.99e-02 |
| 6 | 1, 2, 3, 5, 6, 7 | 2.8e-03 | 1, 2, 3, 6, 7, 8 | 2.1e-32 |
| 7 | 1, 2, 3, 5, 6, 7, 8 | 3.7e-03 | 1, 2, 3, 5, 6, 7, 8 | 3.7e-03 |
| 8 | 1, 2, 3, 4, 5, 6, 7, 8 | 1.7e-32 | same | 2.6e-32 |

Worst case over `n_sensors = 2..10` is **0.0948 < 0.15**, so the acceptance criterion in
`docs/CONTRACT_API.md` holds for every sensor count, not only the nominal one. Elimination order
(worst first) for `n_sensors=4` is `0, 9, 4, 8, 1, 5`: the algorithm discards the two end stations
first (lowest amplitude in both modes), then the mid-span station where mode 2 has its node, which is
the physically expected answer. The retained set `{2, 7}` sits near the antinodes of mode 1 while
straddling the node of mode 2, giving MAC ≈ 0 between the two modes.

  if F1 wants `femtools.correlation` / `femtools.pretest` reachable from the top level, that is a

  natural function name. Resolution: the package exports the scalar MAC as `mac_value` (so
  `femtools.correlation.mac` stays the module), while `femtools.pretest.mass_loading` intentionally
  resolves to the *function* when accessed as an attribute of the package —
  `from femtools.pretest.mass_loading import mass_loading` and `from femtools.pretest import
  mass_loading` both work; only `import femtools.pretest.mass_loading as m` yields the function.

  objects that behave like their selected-id array: `np.asarray(result)`, `len`, iteration and indexing
  address the ids, with `.efi`/`.values`, `.index` (rows into `phi`), `.ranking`, `.removed` and
  `.history` alongside. `PairingResult` exposes `.as_pairs()`, `.index_a/.index_b`, `.mac_values`,
  `.freq_error` and a printable `.table()`.
