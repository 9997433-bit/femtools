## 2. Headline numbers

### Recovering a 10 % Young's modulus error

The acceptance case in `docs/CONTRACT_API.md` is *"Updating E on 2-param beam
(10 % error) → recover E within 2 %"*. Run against the **real** `femtools.fea`
kernel (a 10-element `BEAM2` cantilever split into two material regions, 5
target frequencies, truth `E1 = 1.10 E0`, `E2 = 0.95 E0`):

| quantity | value |
|---|---|
| parameter error after updating | **7.9e-8 %** (tolerance: 2 %) |
| relative RMS frequency error | 2.88e-2 → **1.59e-10** |
| iterations / response evaluations | 3 / 16 |
| recovered `E1`, `E2` | 231.0000 GPa, 199.5000 GPa (truth 231.0, 199.5) |

With 0.5 % random noise on the measured frequencies the same problem gives
**0.78 %** parameter error (WLS) and **0.73 %** with the Bayesian estimator
(`prior_std=0.15`, `noise_std=0.005`), still inside the 2 % bar. The Bayesian
run also returns a posterior standard deviation of 0.9 % / 1.4 % on the two
multipliers.

The same case solved through the dependency-free fallback models
(`femtools.updating.reference`) recovers to 1e-8 relative for the 2-DOF chain,
the axial bar and the Euler–Bernoulli beam.

### Sensitivity matrix

| check | result |
|---|---|
| central FD vs semi-analytic on the FE beam | max rel difference **8.2e-7** |
| closed form `sum_j df_i/dp_j == f_i/2` for a global E multiplier | max rel error **6.0e-12** |
| FE frequencies vs Euler–Bernoulli theory (10 BEAM2 cantilever) | 0.003 % (bar: 2 %) |

The semi-analytic route differentiates the assembled `K`, `M` once per
parameter and then applies `dλ_i/dp = φ_i^T (K_,p − λ_i M_,p) φ_i`, so it is
exact for parameters that enter linearly (E, ρ, spring stiffness) and costs no
extra eigensolves.

### Force identification

median relative amplitude error over 400 spectral lines:

|---|---|---|---|---|

| well posed | 5 % | 4.8e-2 | 4.9e-2 | 4.8e-2 |

| ill posed | 5 % | 2.3e+5 | 1.6e+0 | **5.6e-1** |

Regularisation buys four to five orders of magnitude once the excitation set is

data. `max_condition=` is a blunt, reliable fallback for both.

## 3. Design decisions worth knowing

**Solver independence.** Nothing in these four packages imports
`femtools.fea`, `femtools.dynamics` or `femtools.core` at module level. The
updater accepts three input forms — an `FEModel`, a plain
`response(p) -> ndarray` callback, or one of the analytical reference models —
and only reaches for the FEA layer lazily when it is actually given a model.
`femtools.updating.have_fea()` reports availability. Verified by blocking those
imports through `sys.meta_path`: all four packages still import and the 10 %
recovery case still converges to 6.5e-10.

**2-DOF and friends as first-class fallbacks.** `femtools.updating.reference`
carries a 2-DOF spring/mass chain, an `n`-element axial rod and an
Euler–Bernoulli beam, all numpy-only, all exposing exact `dK/dp` for validating
the analytic sensitivity path, plus `make_updating_testcase()` which builds the
canonical wrong-stiffness problem in one call. These were written for the case
where the FEA layer is missing, but they stayed useful as fast golden cases:
`AxialBarModel` matches the continuum rod frequencies and `BeamModel` matches
Euler–Bernoulli theory to 1e-6 relative on the first mode.

**Array-like result objects.** `SensitivityResult`, `ForceIdResult`,
`TopologyResult` and `OptimizationResult` all implement `__array__`, `shape`
and `__getitem__`, so `np.asarray(S)`, `S.shape`, `S[i, j]` and `S @ x` work on
the result exactly as on the bare matrix while the object still carries
provenance (method, step sizes, condition numbers, iteration history).

**Scaling in `size_optimize`.** SLSQP mixes objective and constraint magnitudes
inside one QP, so a stress constraint expressed in Pa (1e8) next to a mass
objective (1e-2) stalls the line search. The objective is normalised by
`|f(x0)|` and each constraint by its value at `x0` by default; the 2-bar case
goes from "positive directional derivative, success=False" to a clean exit at
the analytical optimum. Feasibility is also measured on the scaled constraints.

**DOE calling conventions.** `latin_hypercube` reads naturally in either
positional order, so both `latin_hypercube(24, bounds)` and
`latin_hypercube(bounds, n_samples=24)` are accepted — the count is told apart
from the bounds by type. `full_factorial` likewise takes either level *counts*
(`full_factorial(2, bounds)`, a 2-level grid spread across `bounds`) or the
level *values* themselves, one sequence per dimension
(`full_factorial([[-1, 1], [10, 20, 30], [5]])`), which is what you want for
categorical or hand-picked levels and what `tests/test_doe.py` expects. Passing
`bounds` alongside explicit level values is rejected rather than silently
ignored.

**Bayesian measurement scale.** `weights` only fixes the *relative* importance
of the responses, but the Bayesian estimator also needs their absolute scale to
balance against the prior. `noise_std` (default 0.01, i.e. 1 % relative) supplies
it. Without this the default weighting implies 100 % measurement error and the
prior swamps the data — the first implementation returned the prior mean
unchanged.

## 4. Bugs found and fixed during verification

- **GCV under-regularised barely over-determined systems.** The thin-SVD
  residual omits the component of the measurement outside `range(A)`. Adding
  that constant back (`||b||² − ||U^H b||²`) fixed a case where GCV chose
  `α = 7e-16` for a condition number of 2e7, improving the identified forces by
  four orders of magnitude. The same term fixed the L-curve, which previously
  picked a sensible corner only by accident.
- **LSCE biased every frequency by a constant offset.** Inverse-FFT of an FRF
  requires a DC-aligned frequency grid; a band such as 1.0 … 250 Hz is not, and
  naive zero-padding shifted all identified frequencies by 0.108 Hz (0.43 % on
  the lowest mode). `irf_from_frf` now resamples onto the aligned grid, dropping
  the error to 1e-4 relative — and to zero when the input is already aligned.
- **FDD peak interpolation was biased.** Parabolic interpolation on the linear
  singular-value curve mis-locates the sharp peaks of lightly damped modes; the
  fit now runs on the log spectrum, cutting the frequency error by roughly 5×.
- **RBPE mass-line band selection.** A fixed fraction of the first resonance
  picked a band far too wide (inertia error 3.7 %). The band is now grown while
  the frequency-smoothed real part stays within 2 % of its low-frequency value,
  with a noise-adaptive floor so that measurement scatter does not truncate it.

## 5. Notes for other agents

- **Tests (R1-G1).** `femtools.mpe.synthetic` provides deterministic generators
  intended for exactly this: `synthetic_frf(...)` returns a `SyntheticModal`
  carrying the truth poles, shapes and residues alongside the FRF, and
  `synthetic_response(...)` produces white-noise-driven output-only time
  histories for FDD/EFDD. `femtools.updating.reference.make_updating_testcase`
  returns `(response_fn, p_true, p_start, targets, model)` for the acceptance
  case. Both are seeded and reproducible.
- Two caveats worth encoding as test tolerances rather than as bugs: EFDD
  damping carries roughly 10–15 % scatter on a finite record, and a 2-parameter
  beam updated from frequencies alone is genuinely ill-conditioned once the
  measurements carry ~1 % noise (the sensitivity columns become nearly
  parallel), which shows up as several percent of parameter scatter. Use the
  Bayesian mode or more/different responses when that matters.
- **`femtools/__init__.py`** (owned by R1-F1) does not re-export these
  packages. Nothing needs it — `from femtools.updating import ...` works — but
  if the top-level namespace is meant to be populated, `updating`,
  `optimization`, `mpe` and `rbpe` each expose a curated `__all__`.
- **`femtools.correlation`** (R1-O3) is not imported by the updater; a local
  MAC implementation lives in `femtools.updating.responses` so that mode pairing
  works standalone. If a single shared implementation is wanted later, that is
  the one line to redirect.
- `size_optimize` and `topology_simp` are deliberately callable-driven and
  self-contained (the SIMP kernel has its own Q4 assembly). Wiring them to the
  general FEA layer for FE-based sizing is a natural round-2 step and needs no
  change to the public signatures.
