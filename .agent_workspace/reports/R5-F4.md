## Bugs fixed (both in `src/femtools/cli.py`)

### 1. `reduce --compare` always failed for SEREP (singular reduced mass)

A SEREP basis built from fewer modes than masters leaves `M_red` singular
*by construction* — `fea.reduction.ReductionResult.reduced_modes` documents
exactly this ("a plain `eigh(K_red, M_red)` fails outright"). The CLI's
compare block used the plain `scipy.linalg.eigh(Kr, Mr)`, so the frequency
comparison — the main point of `--compare` — degraded to a warning in the
standard SEREP configuration (more sensors than target modes), and
`freq_reduced` was missing from the `-o` npz.

Fix: new `_reduced_frequencies(Kr, Mr)` helper mirrors the kernel's
subspace approach: eigendecompose the symmetrized `M_red`, drop the null
directions (relative tolerance `n * 1e-14`, as in `reduced_modes`), and
solve the projected pencil with `eigvalsh`. When directions are dropped the
CLI prints `reduced mass has rank r of n; comparing the r finite-frequency
modes`. For SPD reduced mass (guyan/irs/craig-bampton) all directions are
kept and results are unchanged (verified against pre-fix tables).

### 2. `estimate-frf --overlap` was silently ignored

The estimator kernels follow the scipy.signal convention and take
`noverlap=` (samples); the CLI passed `overlap=` (fraction), which
`_call_estimator`'s signature filter silently dropped. `--overlap 0.0` and
`--overlap 0.75` produced byte-identical `H`.

Fix: `_call_estimator` now translates `overlap` to
`noverlap = round(overlap * nperseg)` when the callee accepts `noverlap`
but not `overlap`. Verified: `H` for 0.0 vs 0.75 now differ; the default
0.5 output is byte-identical to pre-fix (the kernel default is
`nperseg // 2`), so existing results are unaffected. The coherence call
shares the helper and gets the same fix.

- SEREP comparison row showing +349 % on the doubly symmetric test beam with
  an almost-uy-only master set is a genuine sensor-set deficiency (measured
  mode partition rank 3 < 4 modes; the kernel flags `exact=False`), not a
  CLI defect. A y+z master set reproduces all retained modes exactly.
- `--nperseg` larger than the signal is clamped by scipy inside the kernel;
  the CLI echoes the requested value. Kernel-side behavior, left alone.
