## Design notes

### CLI damping (`frf --damping / -z`, default `"0.02"`)

Spec grammar (parsed into the mapping form `dynamics.damping.as_damping` already accepts —
no changes needed outside my paths):

- bare number → modal zeta, **backward compatible** (`--damping 0.02` unchanged)
- `modal:Z` / `modal:Z1,Z2,...` → per-mode viscous zeta
- `rayleigh:ALPHA,BETA` or `rayleigh:alpha=..,beta=..` → `C = alpha·M + beta·K`
- `structural:ETA` (aliases `hysteretic:`/`eta:`) → complex stiffness `K(1+iη)`
- `none` / `off` / `undamped` → `NoDamping`
- combined `zeta=0.01,eta=0.02,...` key list → `CombinedDamping`

Malformed specs raise `typer.BadParameter` (exit 2) with the offending token and the grammar.
The console line now reports the parsed model (e.g. `damping: Rayleigh alpha=1.5 beta=2e-05`).

### plot_mode rotations

`show_rotations=True` draws the nodal rotation pseudo-vector (rx, ry, rz — right-hand rule)
at the *deformed* node positions; deformation itself still uses translations only. 3D axes:
quiver arrows (plus a manual `auto_scale_xyz` merge — mplot3d quiver does not autoscale, the
arrows overflowed the box otherwise). 2D axes: quiver of the in-plane part plus circle
markers for θz with radius ∝ |θz| (solid = CCW, dashed = CW, legend added). `rotation_scale`
sets the largest arrow length in model units (default 8 % of the bbox diagonal). Default
behavior (`show_rotations=False`) is pixel-identical to Round 1.

### GUI loading

The GUI is a local tool, so a *path on the server machine* is the natural transport (no
multipart upload): form at the top of the left column, `POST /api/load` (used by the form)
and `GET /api/load?path=...` (query flavor) on **both** backends. Results stored in
`.ftproj`/`.unv` files are imported into `engine.results`, so `/api/plot/mode` and `MAC A=...`
work immediately after a load; FSL scripts continue on the loaded model without
`NEW PROJECT`. Missing file / empty path / unsupported extension / reader failures → HTTP 400
`{ok:false,error}`. Missing `femtools.core/io` → 400 naming the missing module (`status()`
already exposes module availability to the page).

### JSON model schema (new `.json` surface, both CLI and GUI)

Single object with `name`, `nodes` (list of `{id, xyz}` or `{id: xyz}` map), `materials`,
`properties` (aliases `mat`/`prop` accepted for `material_id`/`property_id`), `elements`,
`spcs` (`{"node": 1, "dof": [1..6]}`, `"dof": "all"`, or a 6-entry `mask`). Full schema in the
`femtools.script.loading` docstring. Built via `FEModel.add_*`, so core validation applies.

## Gaps / handoff notes

1. `plot_mode` rotations are a *display* of rotational DOFs (arrows/markers); rotations are
   not used to curve element interpolation (no shape-function-based deformation), and there
   is still no animation.
2. The FRF CLI covers `modal_frf` only; `direct_frf`/`harmonic` are Python-API-only.
   `ViscousDamping` (explicit C matrix) has no CLI spelling — it needs an array, not a flag.
3. GUI load is path-based by design (local tool). A multipart upload endpoint would be
   needed for remote deployments; not added.
4. `.ftproj` results of kind FRF/ODS are imported into the session but only modal results
   are plottable (`/api/plot/mode`); the results panel lists them all.
5. For F2: `script/loading.py` reads `Project.model/.results` and `UnvData.model/.modal/.frf`
   — if those container fields are renamed, only `load_model_file` needs updating. The JSON
   schema intentionally lives in my package; if core later grows an official
   `FEModel.from_dict`, `model_from_json_dict` should delegate to it.
6. For G1 (test ideas): damping-spec parser table test via `CliRunner`; `plot_mode`
   `show_rotations` smoke test; GUI `/api/load` happy/error paths (all currently verified by
   my /tmp scripts only, since `tests/**` is not my path).
