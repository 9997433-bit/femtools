## CLI commands added

| command | wraps | notes |
|---|---|---|
| `dump-psd` | `dynamics.random.dump_psd` + `psd_response` | model file (synthesizes via the `frf` pipeline + `--force-psd` level) or plain `.npz` with `psd`/`freq_hz` (canonicalized; rms integrated when absent) |
| `load-psd` | `dynamics.random.load_psd` | summary table, per-DOF rms / 3-sigma, `--plot` via `viz.plot_psd` |
| `era` | `mpe.era.era` | `.npz` impulse responses (`h`/`irf` + `dt`/`fs`/`t`) or FRF block (`H` + `freq_hz`, incl. `dump-frf` archives / `frf -o` output); `--order`, `--fmin/--fmax`, `--output` saves `modes` so the result feeds `femtools mac` |
| `recover-spr` | `fea.recover.recover_spr` | same solve pipeline as `recover-stress`, nodal table + `.npz` output |
| `expanded-mac` | `correlation.expansion.expanded_mac` | `--master` as `NODE:DOF` (via modal DOF map) or raw row indices for `.npz` mode sets; MAC table, diag/off-diag summary, expansion residual, heatmap |

Matching FSL verbs: `DUMP PSD` / `LOAD PSD` / `ERA [RESULT= ORDER= MODES=]` /
`RECOVER SPR` / `EXPAND MAC MASTER=`. `EXPAND MAC` stores the MAC as a plain
ndarray, so the existing GUI `/api/plot/mac?name=` heatmap renders it by name;
`ERA` results carry `freq_hz` and print/list like any modal result.

## Lazy-fail verified (kernel missing → exit 3 / ScriptError, no crash)

Verified two ways. `recover_spr` had not landed yet when I started, so
`femtools recover-spr` genuinely exited 3 ("requires a femtools module that is
not available … femtools.fea.recover") against the real tree; the kernel
landed mid-round and the same command then produced the constant-stress patch
exactly (σxx = 1e7 Pa at every node of an axial bar under 1000 N / 1e-4 m²).
Then, with a meta-path import blocker in a subprocess:

- block `femtools.mpe.era` → `era` exit 3
- block `femtools.fea.recover` → `recover-spr` exit 3
- block `femtools.correlation.expansion` → `expanded-mac` exit 3
- block `femtools.dynamics.random` → `dump-psd` and `load-psd` exit 3
- same blocks through the script engine → clean `ScriptError` for
  `ERA` / `RECOVER SPR` / `EXPAND MAC` / `DUMP PSD` / `LOAD PSD`
- GUI `/api/spr` answers HTTP 400 with a JSON error (page shows a muted note)
- degenerate ERA input ("no physical poles" `RuntimeError`) → `ScriptError` /
  exit 2, not a traceback

Both the ImportError-on-module and ImportError-on-name (`cannot import name
'recover_spr'`) flavors are covered by the same `except ImportError`.
