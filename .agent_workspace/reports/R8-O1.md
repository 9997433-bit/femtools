## `apply_rbe3` (`fea/mpc.py`)

Interpolation multipoint constraint, **not** RBE2 kinematics and **not** a
penalty spring.  One dependent (reference) grid point's listed components are
the weighted average of the *same* components of the independents,

```
u_d[c] = sum_i (w_i / sum_j w_j) * u_i[c]
```

equal weights by default, `RBE3.weights` when the record carries them.  The
rows go into the existing `ConstraintTransform.from_rows`, so there is one `G`,
one congruence `G^T A G`, no Lagrange multiplier, no extra equation and no
stiffness anywhere.  The constraint reads **no coordinates at all** — a
weighted average is a statement about components, not about levers — which is
the structural difference from `apply_rbe2`.

Record fields are read duck-typed with the same tolerance as the rest of the
kernel: `dependent` / `refgrid`, `independents` / `gi`, `components` / `refc`
(default `123`, matching the dataclass), `independent_components` / `ci`,
`weights` / `wt`.  A dependent component that is not among the independent
components is **refused** rather than being quietly manufactured from a
rigid-body term.

`is_rbe3` tells the two card types apart by the grammatical number of their
grid fields (an `RBE2` has one independent and many dependents; an `RBE3` one
dependent and many independents), so one mixed container — `model.mpc`, or an
explicit list handed to `assemble_km(mpc=...)` — may hold both.

## Composition (`apply_mpc`, `resolve_mpc`, `assemble_km`)

`apply_mpc(model, rbe2=..., rbe3=...)` collects both tables into a single row
set and builds **one** `ConstraintTransform`; chains are resolved across card
types, so an `RBE2` arm may hang off an `RBE3` reference grid (and the other
way round) and `G` is still idempotent.  A DOF claimed by both is an error,
whichever card got there first.

`apply_rbe2` and `apply_rbe3` are now thin wrappers over `apply_mpc` with the
other table set to `()`, which is what guarantees the bit-identical claim:
with an empty `rbe3` the rows dict, its insertion order and therefore the CSR
`data`/`indices` of `G` are unchanged.  `assemble_km` honours both by default
through `resolve_mpc`; `mpc=False` still disables everything.

## `average_nodal` (`fea/recover.py`)

`average_nodal(stress, model) -> NodalStressResult`: the value at a node is the
unweighted mean of the centroid tensors of the `n_a` elements incident on it
(`1 / n_adjacent`), taken in the **basic** frame because tensors written in
different element frames cannot be added.  Not Zienkiewicz-Zhu SPR: no
polynomial, no patch, no error estimate — the docstring says so and says where
SPR would be the better answer.

`NodalStressResult` carries `node_ids`, `stress`, `strain`, `count`, `xyz`,
`element_ids`, `etypes`, `layer` plus `von_mises` / `principal` / `tensor()` /
`node()` / `index_of()`.  `von_mises` is taken *of the averaged tensor*, which
is what keeps a constant state exact.  Nodes with no recovered element on them
are omitted rather than reported as zero; a `MASS`/`SPRING` element contributes
nothing (it is already in `StressResult.skipped`).

The physically interesting number is the third row.  Because the dependent
motion is a *weighted average*, a rigid body motion of the independents carries
the reference grid to their **weighted centroid**, so the reduced rigid body
mass matrix is exactly the bare triangle's plus a point mass sitting there —
for any weights, and wherever the reference grid itself was drawn.  Moving it
off the centroid changes nothing measurable, which is the honest statement of
what this constraint is: rigid-body exact when the reference grid is at the
weighted centroid (the usual RBE3 layout), and delivering the load or mass to
that centroid otherwise.  It is not a least-squares rigid-body fit, and it does
not pretend to be one.

## Notes for other agents

* `RBE3.components` defaults to `(1, 2, 3)` and the kernel matches that default
  for a record that omits the field; a dependent component outside
  `independent_components` raises `ValueError`.  R8-F2's BDF reader should map
  `REFC` → `components` and the `Ci` of the `wt, c, gi` triples →
  `independent_components`.
* `ConstraintTransform.independent_nodes()` legitimately reports a node that is
  *partly* dependent (e.g. an `RBE3` driving only `123` of a node whose
  rotations then drive a rigid arm).  That is not a bug; it is why the DOF-level
  `dependent` array is the authoritative set.
* `stress_patch_error` gained two keys (`nodal`, `nodes`); existing keys and
  values are unchanged.
* R8-F4's `plot_stress` can colour by `NodalStressResult.von_mises` for a smooth
  field or by `StressResult.von_mises` for the raw element field; both carry the
  same `layer`.
