## The new module — `femtools.dynamics.energy`

```python
from femtools.dynamics.energy import modal_strain_energy, modal_kinetic_energy
modal_strain_energy(modes, K)   -> ndarray (n_modes,)   diag(Phi^T K Phi) / 2
modal_kinetic_energy(modes, M)  -> ndarray (n_modes,)   diag(Phi^T M Phi) / 2
element_modal_energy(model, modes) -> ElementEnergy     .strain / .kinetic (n_el, n_modes)
```

Also exported from `femtools.dynamics` (`ElementEnergy`, `element_modal_energy`,
`modal_kinetic_energy`, `modal_strain_energy`). The package-level lazy `_EXPORTS` in
`femtools/__init__.py` is R6-F1's file and was left alone; the names are importable now,
so F1 can promote them.

**Argument order is not fixed, deliberately.** The brief froze the formula, not the
signature, and the probe R6-G2 had already committed to `scripts/probe_boundaries.py`
calls `modal_strain_energy(modes, stiffness)` while `docs/PRODUCT_MAP.md` reads
"from assembled K, M and mass-normalized Φ". Rather than break one of them, both orders
work: the two arguments are separated by type (a modal object, an assembly or a model is
unambiguous), then by sparsity (mode shapes are never stored sparse here), then by shape
(only one reading makes `Phi^T A Phi` conformable), then by symmetry (`K` and `M` are
symmetric, a mode matrix is not). The residue — two square symmetric arrays of the same
size, which is exactly the probe's `eye(2)` / `diag(2, 8)` — reads the first argument as
`Phi`, and that is documented in the docstring together with the advice to use keywords.
The probe now passes and reports `"convention": "half-quadratic"`.

What the entry points accept beyond the frozen pair, in the spirit of the rest of the
package: mode shapes as an array (a single mode may be 1-D), a `ModalModel`, a mapping or
a `ModalResult`; the matrix as dense, sparse, an `AssemblyResult`, a `ModalResult`
carrying one, or a model database, in which case the free partition is used and a
global-DOF mode matrix is restricted to it. `modal_strain_energy(solve_modes(model, 10))`
is therefore the whole call. Complex modes contract as `Phi^H A Phi` and the real part is
returned. `mass_normalize=True` (default) rescales a modal *object* that declares
`generalized_mass != 1`; it never touches a plain array, whose scaling is the caller's by
definition.

Measured, on a mass-normalised basis: `max |MSE - omega^2/2| = 6.8e-13` and
`max |MKE - 1/2| = 2.2e-16` on an 8-mass chain; `5e-14` relative on the 16-DOF BEAM2
cantilever. Both orders, the sparse form, the keyword form and the single-argument
`ModalResult` form agree exactly.

### The per-element split, and why it is exact

The assembled `K` is the sum of the element matrices scattered into the global DOF space,
so `sum_e phi_e^T k_e phi_e = phi^T K phi` identically — the SPC'd and suppressed DOFs
are zero in a mode shape, and `k_drill` is already part of the element `k`, so nothing is
missing from the sum. `element_modal_energy` rebuilds the element matrices through
`femtools.fea.elements.element_matrices` (imported lazily, inside the function) and
measures the identity rather than asserting it:

| model | elements | `meta["closure"]` |
|---|---|---|
| HEX8 cube, 2x2x2 | 8 | `4.4e-16` |
| QUAD4 plate, 4x3, consistent mass | 12 | `1.9e-13` |
| QUAD4 plate, 4x3, `lumped_mass=True` | 12 | `2.9e-13` |
| BEAM2 cantilever, 8 elements | 8 | `4.4e-16` |

`ElementEnergy.fraction("strain")` gives the per-mode fractions that MSE-based updating
and damping-treatment placement rank on (columns sum to 1; a rigid-body mode gives a zero
column, not `nan`), and `ranking(mode, kind, n)` is the top-*n* list. On the first bending
mode of the cantilever it puts 42 % of the strain energy in the root element and 42 % of
the kinetic energy in the tip element, which is the answer a hand calculation gives.

One honest limitation, documented in the docstring with its measurement: the closure
cannot catch an `assemble` mismatch, because the global form it checks against is built
with the same options as the split. Solving with `lumped_mass=True` and splitting with the
default consistent mass leaves the closure at `8e-13` — but
`meta["modal_kinetic_energy"]` falls from `1/2` to `0.46, 0.42, 0.30`, and that is the
number to read.

## Bug 1 — the pseudo-inverse fallback that never fired

`factorized_solver` is documented to "fall back to least-squares / pseudo-inverse solve
when `A` is singular so that free-free models do not blow up the caller". The dense path
tested that with `np.abs(np.diag(piv[0])).min() > 0.0`. A numerically singular matrix
does not produce an exactly-zero pivot: on the 21-mass free-free chain LAPACK returns
`7.3e-12` against a `4.3e4` diagonal, factorises happily, and the solve satisfies
`A x = b` to round-off while carrying an arbitrary multiple of the rigid-body mode.

Where that lands, on a free-free component whose basis omits the rigid-body mode — which
`rubin`'s own docstring warns is the caller's responsibility, and which is exactly what
handing in *measured* elastic modes does:

| | before | after |
|---|---|---|
| static solve, `\|x\|` | `6.3e+11` | `3.3e-04` |
| rigid-body drift in it | `1.4e+11` | `-3.1e-19` |
| `residual_vectors` residual flexibility, norm | `6.3e+11` | `1.3e-05` |
| its rigid-body content | `1.4e+11` | `1.7e-18` |
| warning | none | `RuntimeWarning`, naming the mechanism |

The two paths of the same function also disagreed, because the arbitrary null-space
content depends on the factorisation: on a non-uniform free-free chain with a
self-equilibrated load, `|x|` was `492` dense, `158` sparse and `117` for the minimum-norm
answer; on a rank-deficient SPD matrix, `4.42` / `2.52` / `0.72`. After the fix all three
agree to round-off, on both storage formats.

The fix accepts the factorisation only when LAPACK's `?gecon` reciprocal condition
estimate stays above `SINGULAR_RCOND = eps` (the sparse proxy is the spread of the `U`
diagonal, which is what `splu` gives you), and warns when it falls back, because a
singular solve means the model is floating on a mechanism and the caller should know. The
estimate costs `O(n^2)` next to an `O(n^3)` factorisation. `lu_factor`'s own
`LinAlgWarning` is now suppressed, since the check that follows it reports the same thing
properly.

**This is the change with regression risk against the Rubin invariant, so it is the one I
measured hardest**: `residual_vectors` shifts a free-free `K` by `M phi_rb phi_rb^T M`
before solving, and `craig_bampton` factorises a fixed-interface `K_ii`, both of which are
well conditioned in every path the repository exercises. The new branch is not taken
anywhere in the test suite (144 tests run with `-W always::RuntimeWarning` produce no
warning summary at all), and every CMS number below is unchanged bit-for-bit.

## Bug 2 — the modal branch answered a different structure

`harmonic_response(assembly_with_damping, ..., method="modal")` returned the response of
the *undamped* model. `system.C` — damping assembled with the model, from `DAMPER`
elements or an assembly-time Rayleigh term — was read only by the direct branch, and the
explicit `C` argument was documented as "direct method only" and silently ignored rather
than refused. On an 8-DOF BEAM2 cantilever assembled with `rayleigh=(5.0, 1e-5)`
(`Cff.nnz = 96`), over five lines through the first resonance:

| | before | after |
|---|---|---|
| modal vs direct, relative L2 | `0.288` | `2.5e-11` |
| modal vs the *undamped* assembly | bit-identical | differs |

A matrix `C` is a property of the structure, not of the solution method, so the modal
branch now projects it onto the basis (`ViscousDamping`, i.e. the classical-damping
assumption) instead of discarding it, and reports what that assumption throws away as
`meta["damping_coupling"]` — the off-diagonal-to-diagonal ratio of the projected matrix,
zero for classically damped models. Rayleigh damping is classical, which is why the two
methods now agree to `2.5e-11` rather than approximately.

## Bug 3 — a 1-D `C` broadcast across `Z(w)`

`Z(w) = K(1 + i eta) - w^2 M + i w C` is built with numpy broadcasting, so a
length-`ndof` `C` — the diagonal, which is what a caller passing a vector means — is added
to *every row* of `Z`. The result is a fully populated, plausible-looking dynamic
stiffness. On a 6-mass chain with `C = diag(0.5 .. 3.0)` over 1-40 Hz:

| relative L2 over the band | worst line | peak `\|H\|` |
|---|---|---|
| `3.06` (306 %) | `32x` | `5.5x` too high |

`direct_frf`, `harmonic_response` and `ViscousDamping` itself now check the shape and say
what a 1-D array is not. A mismatched *size* used to raise a raw numpy broadcast error
(`operands could not be broadcast together with shapes (3,3) (5,5)`); it now names the
argument and the size it needed. Correct dense, sparse and list-of-lists `C` are
unaffected and still agree with each other.

## Bug 4 — `as_response` at the DC line

Mobility and accelerance are identically zero at `f = 0` whatever the structure does
statically, so dividing them back by `i w` / `-w^2` is `0/0`. The whole DC line came out
`nan + nan j`, announced by nothing but a numpy `RuntimeWarning`, while the receptance
computed directly at the same line is a perfectly ordinary static compliance (`1.0` in the
probe). Converting now raises and says to drop the DC line — the same treatment R5 gave
`lower_residual` at DC. `as_response` has no callers inside the repository, so this can
only reach code that was already receiving `nan`.

## Bug 5 — `assemble=` accepted and ignored

`direct_frf(assembly, ..., assemble={"lumped_mass": True})` assembles nothing: the keyword
is consumed only by the model branch of `as_system`. Lumped and consistent mass are not a
detail — on the BEAM2 cantilever they differ by 0.8 % on the first pair of modes and 2.7 %
on the second, and by 4.1 % on the QUAD4 plate — so a caller who asked for one and got the
other has no way to notice. Every branch that cannot honour the keyword now refuses it and
says where to put it instead. Nothing in the repository passes `assemble=` alongside an
assembly.

## Bug 6 — mapping keys swallowed by a `pop` default

Carried over from R5's "known, not fixed" list, now fixed. Python evaluates
`d.pop("dof_i", d.pop("dof", None))` inner-first, so `"dof"` was always consumed:
`{"dof": 1, "dof_i": 2, "k": 3}` quietly became a spring at DOF 2 instead of raising, and
`{"k": 3, "stiffness": 99}` quietly ignored the second stiffness. `_pop_alias` takes the
first spelling that is present and leaves the rest to the existing unknown-key check. All
the legitimate spellings (`dof`/`dof_i`, `k`/`stiffness`, `mass`/`m`, `dofs`) still parse.

## Checked and left alone

Not every suspicion survived contact. Recording them so the next round does not re-audit:

* Mixing a sparse and a dense damping contribution (`RayleighDamping` on a sparse assembly
  plus a dense explicit `C`) produces the same FRF to the last bit as the all-dense route.
  The `np.matrix` that scipy's `sparse + ndarray` returns passes through `as_dense`
  harmlessly.
* `craig_bampton` on a chain whose only boundary DOF is an end mass does **not** hit a
  singular `K_ii`: a fixed-interface partition is singular only when an interior region is
  disconnected from the boundary entirely. The new fallback correctly stays out of it, and
  dense and sparse agree to `4e-16`.
* `random._as_force_psd`'s shape-collision rule (`n_in == n_freq`) resolves the way its
  docstring says, in both the 1-D and the 2-D branch.
* `fba.frf_based_assembly` does not verify an explicitly supplied `freq_hz` against the
  axis of the `FRFResult` inputs (only its length). A wrong axis would mislabel the result
  rather than corrupt it; left as a note.
* `ModalModel.mass_normalized()` still returns `self` on an already normalised basis, so
  callers share the object. No caller mutates it (R5 note, re-checked).
* `synthetic_frf` with `noise=0` returns the input `FRFResult` unchanged, `method="modal"`
  rather than `"synthetic"`. Cosmetic.
