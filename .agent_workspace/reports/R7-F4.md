## 2. CLI `write-mesh` and `recover-stress` (lazy, exit 3)

- `femtools write-mesh IN OUT`: loads any read-mesh-supported input, dispatches the writer on the **output** suffix — `.cdb` → `femtools.io.cdb.write_cdb`, `.k/.key` → `femtools.io.kfile.write_k`, `.inp` → `femtools.io.inp.write_inp`, plus `.bdf/.nas/.dat`, `.unv/.uff`, `.ftproj` which already have writers. All writer imports are inside the command; a missing kernel exits **3** with the same missing-module message as `read-mesh` (verified today for `.cdb` and `.k`, which don't exist on this tree). Unsupported suffix exits 2. Writer calls try `(path, model)` first and retry `(model, path)` on TypeError/AttributeError, so either R7-F2 calling convention will bind (verified with stubs, including a `coerce_path_model`-guarded one).
- `femtools recover-stress MODEL [-l NODE:DOF=VALUE ...] [-o out.npz] [--max-rows N]`: imports `femtools.fea.recover.recover_stress` (frozen R7 name) and `femtools.fea.static.solve_static` lazily — on this tree it exits **3** naming `femtools.fea.recover`. `--load` adds nodal forces/moments on top of loads stored in the model file; solves the static case and prints an element-centroid stress table (per-6-component labels sxx..szx, von Mises column only when the kernel provides one — no invented invariants), saves `element_ids`/`stress`/`von_mises` to npz. Duck-typed unpack accepts a `StressResult`-like object or `{eid: components}` mapping, NaN-padding ragged component counts across mixed element types; passes `assembly=` through when the kernel signature takes it. Happy path verified end-to-end with a stubbed kernel (exit 0, correct table and npz).

## 3. ScriptEngine: `SOLVE STATIC`, `SET`, (+ `ADD LOAD` enabler)

- `SOLVE STATIC [NAME=..]` runs `femtools.fea.static.solve_static(model, ..., full_result=True)` and stores the `StaticResult` in `engine.results` (default `"static"`). Missing `femtools.fea` → ScriptError (same lazy pattern as SOLVE MODES); a singular/failed solve is wrapped as `ScriptError("SOLVE STATIC failed: ...")` so the GUI script API returns `ok: false` instead of a 500.
- `SET name=value [name=value ...]` assigns case-insensitive script variables (raw text values, kept in `engine.variables`); later tokens expand `$name` anywhere (`$$` = literal `$`, undefined variable = ScriptError). Enables parameterized decks: `SET E=210e9` … `ADD MAT 1 E=$E`.
- `ADD LOAD <node> [FX=..] .. [MZ=..]` added as the minimal enabler — SOLVE STATIC can only ever produce zeros from a pure-FSL script without a load command. Maps straight to `FEModel.add_load`.
- NEW/ADD/SPC/SOLVE MODES/MAC/SAVE/PRINT untouched in behavior (SOLVE dispatch refactored into `_solve_modes`/`_solve_static`; `test_script_engine.py` and the full suite pass). Grammar + command reference updated in `script/README.md`.
- End-to-end check: FSL cantilever bar with `SET`-parameterized E/A and `ADD LOAD` tip force reproduces u = FL/EA to machine precision via `SOLVE STATIC`, through the engine API, `femtools script -c`, and the GUI stdlib `/api/script`.

## Load-vector gap worked around (noted for R7-O1/fea owner)

`femtools.fea.loads.build_load_vector` does not recognize the `force`/`moment` attribute layout of core `Load` records, so `loads=None` (→ `model.loads`) silently builds a **zero** vector. Out of my paths (`fea/**`), so both new surfaces flatten `model.loads` themselves via the public `Load.as_dof_values()` into the `{(node, dof): value}` mapping `solve_static` reads directly (`_load_mapping` in `script/engine.py`, `_model_load_mapping` in `cli.py`). Worth a proper fix in `fea/loads.py` (add `force`/`moment` to `_apply_record`'s probed keys) by whoever owns fea.
