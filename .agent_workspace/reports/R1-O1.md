### Element formulations

| Type | Formulation | DOF |
|------|-------------|-----|
| `BAR2` | 3D pin-jointed rod, axial stiffness, consistent mass in all 3 translations | 3/node |
| `TRUSS2D` | planar (global XY) axial truss | 2/node |
| `BEAM2` | 3D Euler-Bernoulli, 12 DOF, consistent mass; optional Timoshenko shear via `As_y`/`As_z` or `K1`/`K2` | 6/node |
| `TRIA3` | CST membrane + **DKT** (Batoz) bending + drilling | 6/node |
| `QUAD4` | bilinear membrane 2x2 Gauss + Reissner–Mindlin bending 2x2 Gauss with **MITC4** assumed transverse shear + drilling | 6/node |
| `TET4` | constant strain tetrahedron | 3/node |
| `HEX8` | trilinear hexahedron, 2x2x2 Gauss | 3/node |
| `MASS` | concentrated mass + full 3x3 rotary inertia (CONM2-like) | 6/node |
| `SPRING` | scalar (`c1`/`c2`), axial, or grounded; scalar or 3/6-vector stiffness | 6/node |
| `DAMPER` | same kinematics, contributes to `C` | 6/node |

`available_elements()` returns the ten canonical names. Aliases (`CQUAD4`, `CBAR`, `ROD`,
`CTETRA`, `CELAS2`, …) resolve to the same builders but are hidden from the list, so BDF/UNV
readers can pass their own card names straight through.

### Assembly

`assemble_km(model)` returns sparse CSR `K`, `M`, `C` over `6 * n_nodes` DOFs plus the DOF
partition. `AssemblyResult` also unpacks as `K, M, C = assemble_km(model)`, and exposes
`Kff`/`Mff`/`Cff`, `expand()`, `restrict()`, `reduce()`.

Three DOF-elimination mechanisms, all reported separately on the result:

1. **SPC** (`spc_dof`) from `model.spcs`, supporting 6-entry boolean masks, `dofs` lists,
   Nastran component strings (`"123456"`) and non-zero enforced values.
2. **Empty DOFs** (`null_dof`) — no stiffness *and* no mass. This is what keeps `Kff`
   non-singular for truss-only and solid-only meshes without the user having to constrain
   every unused rotation.
3. **Fictitious drilling** (`drilling_dof`) — shell drilling rotations whose *only* stiffness
   contribution came from the drilling penalty. The penalty is accumulated into a separate
   matrix during assembly, so this test is exact rather than a heuristic threshold. On a flat
   plate every drilling DOF is caught, which removes the spurious mechanism that otherwise
   shows up as a seventh rigid-body mode.

`free_dof` is the set actually solved (everything minus the three above); `unconstrained_dof`
keeps the plain "not SPC'd" definition for callers that need it.

Options: `lumped_mass`, `rayleigh=(alpha, beta)`, `element_filter`, `on_unknown` in
`{"raise", "skip", "warn"}`, `apply_spc`, `remove_null_dofs`, `suppress_drilling`.

### Duck typing

`femtools.core.model` does not exist yet, and the kernel never imports it. Everything goes
through `femtools.fea.protocols`, which was verified against three unrelated model shapes
(see §3.5). Attribute lookup tries the direct name, then a list of aliases, then nested
parameter bags (`attrs`, `params`, `extra`, `data`, `fields`, `options`, `kwargs`, `props`).
The material record is deliberately excluded from element/property lookups because `MAT1`
reuses `A` for thermal expansion, which would silently collide with a section area.

## 2. Eigensolver

`solve_modes(model, n_modes=10, shift=0.0)` uses ARPACK `eigsh` in shift-invert mode
(`sigma`, `which="LM"`), with a dense shift-invert path for systems below 30 free DOFs or when
`n_free < n_modes + 2`. Modes are returned over the **full** `6 * n_nodes` space with zeros on
constrained DOFs, which preserves `Phi.T @ M_global @ Phi = I` exactly as well as for the
free-free partition.

Three things were needed to make it reliable, each found by measurement:

**Shift placement.** `shift=0.0` picks an automatic shift. My first rule scaled it to the
*median* diagonal Rayleigh quotient, which was badly wrong: shift-invert separates a rigid-body
mode from the first elastic mode by `1 + lambda_1/|sigma|`, so the shift must be small compared
with the elastic spectrum. On a 8x8 TRIA3 plate the median rule gave `|sigma| = 1.0e7` against
`lambda_1 = 5.6e7`, a separation of only 6.6, and ARPACK dropped rigid modes. The shift is now
placed nine decades below the spectral-radius estimate `max(K_ii/M_ii)`, giving separations of
1e3–1e5 on the same models while keeping `K - sigma*M` comfortably factorisable.

**Rayleigh–Ritz refinement.** The shift-invert LU is built explicitly and passed to `eigsh` as
`OPinv`, then reused for a 3-iteration subspace refinement of the ARPACK basis enriched with a
few inverse-iterated random vectors. Rayleigh–Ritz values bound the true eigenvalues from
above, so enriching the subspace is monotone — the refinement can only improve the answer, and
it costs no extra factorisation. This is what recovers members of repeated clusters.

**Determinism.** The ARPACK start vector is seeded, so repeated calls return bit-identical
frequencies.

Sweep over 112 free-free models (QUAD4 and TRIA3 plates 3x3…16x16, free-free BEAM2 chains
10–60 elements, `n_modes` in 8/10/12/16/20): **112/112 return exactly 6 rigid-body modes**.
Before the three fixes above the same sweep failed 6 cases.

Mass normalisation uses a Cholesky factor of the generalized mass matrix (`Phi <- Phi L^-T`),
which also cleans up ARPACK's arbitrary mixing inside degenerate clusters, followed by a
deterministic sign convention. Worst `max|Phi.T M Phi - I|` observed across every model tested:
**4.9e-15** (contract tolerance 1e-8).

QUAD4 plates, timings on this VM (assembly is pure Python per element):

| Mesh | n_dof | free | nnz(K) | assemble | 12 modes |
|---|---|---|---|---|---|
| 40x40 | 10 086 | 8 405 | 197 208 | 0.81 s | 0.39 s |

Assembly was originally 7.3 s at 80x80 because the node/property/material tables were rebuilt

attribute lookup, a per-record material cache and precomputed Gauss/scatter data cut that to
3.3 s. Modal solve dropped from 11.6 s to 1.9 s by building the shift-invert LU once and
passing it to `eigsh` as `OPinv` instead of letting ARPACK factorise again.

## 4. Design decisions worth knowing downstream

- **`modes` is full-size** `(6*n_nodes, n_modes)`, zero-padded on constrained DOFs. Correlation,
  pretest and dynamics can index it by node without carrying the free-DOF map, and
  `Phi.T M Phi = I` holds for both the global and the reduced mass matrix.
- **`free_dof` excludes empty and drilling DOFs**, not only SPC'd ones. A truss model would
  otherwise have a singular `Kff`. `spc_dof`, `null_dof` and `drilling_dof` are reported
  separately, and `unconstrained_dof` gives the SPC-only complement.
- **`BAR2` is a pin-jointed rod, not a beam.** The contract example creates it with only `A`,
  and the 1e-8 axial acceptance case needs a pure axial element. Full beam behaviour is
  `BEAM2`.
- **DOF designators are zero-based when integers** (`0..5`) and accept names (`"uz"`, `"fz"`,
  `"t3"`). Nastran-style one-based digits are only interpreted inside component *strings*
  (`"123456"`), where that is unambiguous.
- **Beam local frame**: default orientation is global `+Y` (falling back to `+Z` for beams
  nearly parallel to `Y`), so a beam along global `X` gets local axes identical to the global
  ones. `I1` maps to `Iz` (bending in the local x-y plane) and `I2` to `Iy`, matching Nastran.
- **`solve_modes(shift=...)` is in `omega^2` (rad/s)^2**, the natural unit for shift-invert.
  `freq_shift_hz=` is provided for callers who think in Hz.
- **`ModalResult` carries `assembly`, `dof_map` and `free_dof`**, so `femtools.dynamics`
  (R1-O2) can build modal FRFs and Craig-Bampton reductions without re-assembling.

## 5. Known limitations

1. **HEX8 shear locking.** Full 2x2x2 integration was specified; the element is therefore
   stiff in bending on coarse meshes (66 % of the reference at one element through the
   thickness, 99 % at six). Convergence is monotone and correct. Incompatible/enhanced-assumed-
   strain modes would fix this and are a natural follow-up; they were left out to keep the
   element exactly as specified.
2. **Warped QUAD4** nodes are projected onto a mean plane. Accurate for mild warp, not for
   strongly warped shells.
3. **No MPC/RBE, no offsets, no nodal output coordinate systems.** Everything is assembled in
   the global basis. If `femtools.core` grows `CoordSys` support for nodal displacement
   coordinate systems, a rotation stage will be needed in `assemble_km`.
4. **Drilling stiffness is a fictitious rank-deficient penalty** (`1e-3 * E * t * A`, zero
   energy for a uniform element rotation), not an Allman-type drilling DOF. Rigid-body modes
   stay exact, and drilling DOFs that receive no genuine stiffness are removed. For folded or
   curved shells the drilling DOFs are retained and carry that penalty.
5. **No stress/strain recovery yet** — not part of the Round 1 contract. Hooks exist
   (`ElementContext`, per-element `B` matrices) if R1-O4's optimization work needs element
   forces.
6. **`solve_static` handles the linear statics case only** (no inertia relief for a free-free
   model, no follower loads).

## 6. Changes wanted outside my ownership (not made)

- `src/femtools/__init__.py` currently exports only `__version__`. If F1 wants
  `from femtools import solve_modes` to work, `femtools.fea`'s public names would need
  re-exporting there. Everything is importable from `femtools.fea` today, so nothing is
  blocked.
- No changes are needed in `femtools.core` for the kernel to work. If `Property` promotes
  section values to real attributes (`A`, `I1`, `I2`, `J`, `t`, `k`, `m`, `c`) rather than a
  generic bag, the kernel picks them up either way — both paths are tested.

## 7. How this was validated

Six harness scripts were written and run under `/tmp/fea_check/` (outside the repository, so
nothing was added to `tests/`): closed-form bar and beam checks, shell/solid/scalar benchmarks,
a HEX8 convergence study plus feature checks, membrane patch tests and free-free rigid-body
sweeps, a duck-typing compatibility matrix, and a replay of R1-G1's own fixtures (§3.6).
Two harness assertions are intentionally
reported as failures because their tolerances were set against continuum theory rather than the
discrete solution: the 1-element bar against `pi/2 * c/L` (10.3 %, the textbook one-element
error) and the 20x2x2 HEX8 cantilever against Euler-Bernoulli + shear (11.2 %, the locking
behaviour quantified in §3.4). Every other check passes.

`ruff check src/femtools/fea` and `mypy src/femtools/fea` (repo configuration) both pass clean.
