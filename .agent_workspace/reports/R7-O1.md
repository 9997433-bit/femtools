displacements and there was no way to turn them into stress. And `FEModel` had

analyst asks of them.

## Stress recovery — `src/femtools/fea/recover.py`

`recover_stress(model, u, ...) -> StressResult`, with `recover_strain` the same
computation under the name that says which array you meant to read. Every
element is evaluated at its **centroid** with its own `B` matrix and the same
constitutive matrix its stiffness was built with: the plain displacement-method
recovery of Cook §6.12/§15.6, Bathe §4.2.1, Zienkiewicz & Taylor §6. No Gauss
point extrapolation, no nodal averaging, no smoothing — each is a separate
decision with its own error, and for a linear element the centroid value is the
one the element actually represents best.

| type | what is evaluated at the centroid |
|---|---|
| `BAR2` | axial extension along the bar axis; end force in `extras` |
| `BEAM2` | axial strain on the neutral axis, plus the full local end-force vector, torque and both end moments (bending shows up in the moments, not in a neutral-axis stress) |
| `TRIA3` | CST membrane `B`, DKT curvature at the area centroid; transverse shear is zero by the discrete-Kirchhoff construction |
| `QUAD4` | membrane and bending `B` at `(0, 0)`, MITC4 tying rows for the transverse shear |
| `TET4` | the constant `B` of the linear tetrahedron |
| `HEX8` | `B` at `(0, 0, 0)`. The nine Wilson–Taylor incompatible modes carry derivatives of `1 - xi^2`, all of which vanish at the centre, so the centroid strain is the compatible one whichever formulation is selected |

Three conventions that the docstring states because they are choices, not
consequences:

* one six-component Voigt tensor `(xx, yy, zz, xy, yz, zx)` per element —
  `solid_D`'s ordering — with **engineering** shear strains, so `sigma = D @ eps`
  holds componentwise;
* solids report in the basic frame, shells and line elements in their own
  element frame, whose axes are the rows of `StressResult.frame`;
  `stress_basic` / `strain_basic` rotate them out. Shell rows are the state at
  the `layer` requested (`"mid"` default, `"top"`, `"bottom"` or a fraction);
* components a formulation does not carry are completed **from its own stress
  assumption** rather than left at zero: a shell's `ezz` follows `szz = 0`, a
  rod's transverse contraction follows its uniaxial state. Stress and strain
  therefore always describe one consistent state instead of a tensor with holes
  in it.

`StressResult` carries the element ids, types, both tensors, frames, centroids,
the layer, per-type `extras` (end forces, membrane forces, moments, shear
resultants) and a `skipped` map. `von_mises`, `principal`, `max_shear`,
`tensor()` and `element()` are derived on demand. A `MASS`/`SPRING`/`DAMPER`
has no stress state, so it is always reported in `skipped` with a reason rather
than raising; a genuinely unregistered type obeys `on_unknown` (`"raise"`
default, `"skip"`, `"warn"`).

`u` may be a bare vector or the `StaticResult`, which also supplies the
assembly. Given an assembly the field is pulled back through the nodal frames
and the dependent motion of any rigid body is filled in first, so an obliquely
hung shell and a rigidly driven node both recover correctly.

### The patch test

`femtools.fea.verification.stress_patch_error(etype)` drives a small distorted
mesh with an exact linear field on its boundary, leaves the enclosed node free,
solves, and compares the recovered centroid state of **every** element with the
analytic constant one — in the basic frame, so it checks the reported element
frames too. The requirement was 1e-12:

| type | elements | stress | strain | free-node displacement |
|---|---|---|---|---|
| `BAR2` | 3 | 1.55e-16 | 1.82e-16 | 0.0 |
| `BEAM2` | 3 | 3.10e-16 | 1.82e-16 | 8.73e-14 |
| `TRIA3` | 8 | 3.92e-16 | 5.08e-16 | 0.0 |
| `QUAD4` | 4 | 2.85e-16 | 2.20e-16 | 3.01e-16 |
| `TET4` | 4 | 7.88e-16 | 5.76e-16 | 2.03e-16 |
| `HEX8` | 8 | 6.31e-16 | 3.22e-16 | 4.97e-16 |

Machine precision on every type, four orders inside the requirement, and it
holds at the top and bottom shell fibres as well as at the mid-surface.

### That it is the right number, not just a repeatable one

A patch test only proves internal consistency, so the acceptance tests also
check the recovery against quantities computed outside it:

* HEX8 tip-loaded cantilever, 32 elements: mean centroid `szx` is
  `99.99999999975` against `P/A = 100` — the elementary average shear, matched
  to 2.5e-12 relative;
* rod under `1e4 N` on `5e-4 m^2`: `sxx = 2.0e7` exactly, `F/A`;
* clamped plate, top fibre: `sxx` equals `6M/t^2` from the element's own moment
  resultant to 0.0, and the through-thickness variation is antisymmetric about
  the mid-surface in the in-plane components while the transverse shear (a
  section average) stays constant, as it should;
* the same plate hung obliquely returns the same von Mises to **1.15e-11**
  relative on a 48998 peak, with each element frame equal to the aligned frame
  carried by the rotation to 4.4e-16;
* `BEAM2` end forces are self-equilibrating: translational equilibrium and
  `M1 + M2 + r x V = 0` both to machine precision.

Cost: 0.021 s for 320 HEX8, about 66 us/element.

## RBE2 rigid bodies — `src/femtools/fea/mpc.py`

`apply_rbe2(model, rbe2=None, ...) -> ConstraintTransform`. An `RBE2` welds
dependent grids to one independent grid through the rigid-body kinematics
`u_m = u_n + theta_n x r`, `theta_m = theta_n`, `r = x_m - x_n` — the public
Nastran card layout (`GN`, `CM`, `GM`) and nothing more than a statement about
kinematics. It is imposed the classical master–slave way (Cook §13.5;
Zienkiewicz & Taylor, master-slave elimination): build `G` with the identity on
retained DOFs, the rigid-body coefficients on each eliminated row and a **zero
column** there, then take `G^T A G` of every system matrix and `G^T f` of every
load. That last one is what carries a force on a rigid offset back to the
independent node *as a force and a moment*.

`ConstraintTransform` exposes `G`, the rectangular `T` the literature uses,
`dependent` / `independent`, `congruence`, `reduce`, `to_full`, `to_independent`
and the node lists. `resolve_mpc` interprets `assemble_km(mpc=)`: `None` reads
`model.rbe2`, `False` disables, a transform is used as given, anything else is
read as explicit records that replace the model's table. Chains — a dependent
node acting as the independent node of a further body — are substituted at
construction, so every row references independent DOFs only; a cycle or a chain
deeper than `MAX_CHAIN_DEPTH = 8` raises with the card id in the message, as do
a DOF eliminated twice, a component outside `1..6`, an offset that the
available DOFs cannot express, and a missing node.

Two properties the rest of the kernel leans on:

* **`G` is idempotent** (`G @ G == G`, verified to 0.0). A dependent row
  references independent columns only, so filling the dependent entries of a
  vector is safe to repeat and a quadratic form `v^T (G^T A G) v` is unchanged
  by it. That is why mode shapes can be reported with the rigid motion filled
  in and still be mass-orthonormal against the transformed mass matrix —
  pinned by a test that checks both at once.
* **`G` is exact.** No penalty stiffness, no Lagrange multipliers, no extra
  equations. The constrained model keeps exactly the rigid-body modes of the
  structure it describes.

Integration: `assemble_km` applies the transform after the nodal-frame rotation
(the frames are the identity on constrained nodes and the transform is the
identity elsewhere, so the two compose), classifies the emptied dependent rows
as `mpc_dof` rather than mistaking them for null DOFs, and raises if an SPC and
a rigid body claim the same DOF. `solve_static` maps the load vector through
`G^T`, fills the dependent motion back into the answer, and rejects an
`enforced=` value on a dependent DOF — that DOF is not the solver's to set.
`AssemblyResult` gained `mpc`, `mpc_dof`, `recover_dependent` and
`constrain_load`, and `expand` fills the dependent motion so a mode shape covers
the rigid parts of the model. Idempotency is what makes that free: the same
`phi^T M phi` comes out before and after the fill, so the reduced matrices and
the full-length vectors stay mutually consistent everywhere else in the package.

### Measured

`rbe2_rigid_pair` — two concentrated masses welded free-free, offset
`(1.0, 0.5, -0.3)`:

| | |
|---|---|
| zero frequencies | **6** |
| free DOFs / eliminated DOFs | 6 / 6 |
| `max abs Kff` | **0.0** — a kinematic statement, not a stiff spring |
| reduced mass vs. the analytic rigid-body matrix `[[m I, -m2 skew(r)], [-m2 skew(r)^T, I1 + I2 - m2 skew(r)^2]]` | **8.9e-17** |

`rbe2_offset_moment` — a rigid arm `0.25 m` above the tip of an 8-element
`BEAM2` cantilever, `120 N` axial on the arm node, so the tip sees the force
plus a `30 N m` moment:

| | recovered | analytic |
|---|---|---|
| tip axial | 4.2857142857143e-06 | 4.2857142857143e-06 |
| tip deflection | -0.028571428571435 | -0.028571428571429 |
| tip rotation | 0.028571428571433 | 0.028571428571429 |
| vs. force + moment applied directly | **0.0** (bit-identical) | |
| `u_arm - (u_tip + theta_tip x r)` | **0.0** | |

The rigid arm and the hand-computed equivalent load produce the same
displacement field bit-for-bit, which is the sharpest statement of the offset
being handled exactly.

Also pinned: a rigid link inside a free-free structure still leaves exactly six
rigid-body modes and a positive seventh; a partial `CM` leaves the unlisted
components genuinely free; the `femtools.core.model.RBE2` table is consumed
as-is through the duck-typed protocol (also `gn`/`gm`/`cm`, packed `123456`,
`"1236"` and sequence spellings); and a model with no rigid bodies is
**untouched** — `apply_rbe2` returns an identity transform whose `G` is never
materialised, and the assembly is bit-identical with and without.

Assembly cost, 525-node / 320-element HEX8 model: 0.453 s plain, 0.458 s with a
rigid body eliminating 150 DOFs — **1.01x**, and exactly 1.00x with no rigid
bodies, where the transform is skipped outright.
