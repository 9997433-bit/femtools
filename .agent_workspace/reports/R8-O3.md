## The API

```python
mapped_mode_matrix(
    modes, fe_ids, *,
    dof_map=None, dofs=None, dofs_per_node=None, missing="raise",
) -> NDArray            # (n_point * n_component, n_mode)
```

`map_nearest_nodes` answers *which* FE node each measurement point sits on; this is the gather that
answer exists for. For every id it returns, the rows of `modes` belonging to that node are copied
into the output **in the order of the test points**, so the analysis shapes come out on the test grid
and go straight into `mac_matrix`:

```python
fit  = align_geometry((known_ids, test_xyz), model)   # test frame -> FE frame
ids, dist = map_nearest_nodes(fit.apply(test_xyz), model, tol=0.01)
phi_a = mapped_mode_matrix(modal, ids, dofs=("x", "y", "z"))
mac   = mac_matrix(phi_test, phi_a)
```

This is the complement of `align_modes`, not a competitor: `align_modes` intersects two *labelled*
DOF maps, which presumes the test channels already carry FE node numbers. When the test side is a
digitized point cloud there are no such labels yet, and `mapped_mode_matrix` is what produces the
analysis matrix on the cloud's own ordering. The two-line relabelling recipe that the
`map_nearest_nodes` docstring has carried since R7 is exactly what this replaces.

* **`modes`** — an `(n_dof, n_mode)` array or any modal result carrying one (`ModalResult`, reader
  results). A 1-D input is one mode. A `ModalResult` also supplies its own `dof_map`, so
  `mapped_mode_matrix(modal, ids)` is the whole call.
* **`fe_ids`** — a `NearestNodeMap` or its `ids` array. A `-1` (unmatched, or rejected by `tol`) is
  handled per `missing`.
* **`dof_map`** — anything `DOFMap.from_mapping` understands. Verified working with: the kernel
  `DofMap` off a `ModalResult`, an `FEModel`, the bound method `model.dof_map`, the
  `{(node, comp): eq}` dict it returns, a `DOFMap`, and the `ModalResult` itself. Rows are found by
  `(node, component)`, so a permuted, sparse or non-contiguous map works — nothing assumes the map's
  node order matches the model's.
* **`dofs`** — components to pull at each node, **in output order**; ints `1..6` or labels, and a
  leading `-` flips that row's sign the way a reversed accelerometer does (`dofs=("x","y","-z")`).
  The default is all six, or, when a DOF map is given, the components that map actually holds (so a
  3-DOF-per-node solid map yields X/Y/Z without being asked). Consistent with the rest of the module,
  a bare string is **one** label: `dofs="Z"` is the z channel, `dofs="xyz"` is an error.
* **`dofs_per_node`** — row block size of the positional fallback (default 6). Rejected together with
  `dof_map`, which already fixes the layout; the error says to use `dofs=` to pull fewer components.
* **`missing`** — `'raise'` (default), `'zero'` (keeps the point's rows as zeros, so the output stays
  aligned row-for-row with the test matrix) or `'drop'` (leaves them out; `NearestNodeMap.matched`
  then selects the surviving test rows on the other side).

Design points worth knowing:

* **No DOF map is needed for a bare-array FE side.** `map_nearest_nodes` returns *row positions* when
  the FE side was a plain coordinate array, and without a `dof_map` this reads the ids the same way —
  node-major, `dofs_per_node` rows per node. The two halves of the workflow then agree by
  construction. When the ids are real model node ids and no map was given, the resulting row index
  runs off the end of the matrix and the error says precisely that, rather than silently gathering
  the wrong block: model node `8` of a 48-row matrix "needs row 47…, so pass `dof_map=` (or a
  `ModalResult`, which carries its own)". A 1-based id set can never quietly produce a valid
  off-by-one-block answer for the last node, which is what makes the loud failure reliable.
* **A repeated FE node is legal.** Two measurement points can share their nearest node when the match
  is not one-to-one, so the gather cannot go through `DOFMap.common` — building a `DOFMap` for the
  target order would hit its duplicate-DOF check. `_mapped_rows` does the same packed-`(node, comp)`
  sorted search `DOFMap.common` uses (one sort, not one dict lookup per DOF: 3000 points against a
  40 000-node / 240k-DOF model in 3.4 ms) but tolerates duplicates and **names** the first DOF it
  cannot find instead of dropping it.
* **Only rows are gathered.** Nothing is interpolated, nothing is re-scaled, no shape is normalized —
  which is why a model correlated against a relabelled copy of itself gives a bit-exact unit MAC
  diagonal. Whether the gather is *meaningful* remains what `NearestNodeMap.distance` reports: a
  point sitting 10 mm from its node gets that node's motion regardless, and that is the diagnostic
  `map_nearest_nodes` returns distances for.
* dtype is preserved, so complex modes stay complex.

### One caveat worth recording: a *literal* cube is degenerate

The brief's wording is "two translated copies of the same 8-node **cube**". A geometric cube
(1×1×1) has **repeated eigenvalues** — clamped on one face it gives 354.607 Hz twice and
1341.784 Hz twice — and inside a repeated eigenvalue the individual eigenvectors are not unique: any
orthonormal basis of the 2-D eigenspace is a valid answer. Translating the mesh perturbs the
assembled matrices at the ULP level (the element Jacobian is formed from coordinates, not from
differences), which is enough to rotate the basis LAPACK returns inside that eigenspace. So on a
literal cube the *per-mode* MAC diagonal comes out `[0.605, 0.605, 1, 1, 0.108, 0.108]` — exactly 1
for the two non-degenerate modes, and split within each degenerate pair. That is a property of
degenerate eigenproblems, not of the mapping, and the probe pins it three ways:

* the two non-degenerate modes are 1 to 1e-12;
* each degenerate 2×2 MAC block **sums to exactly 1 per column** — the mapped shapes span the same
  subspace, i.e. nothing was lost by the gather;
* a copy built by *relabelling* the same solved modes (rather than re-solving the translated mesh)
  gives `diag == 1` for all six modes even on the cube, and the gathered matrix is
  `np.array_equal` to the original — the gather is the exact inverse permutation.

**Recommendation for whoever writes the acceptance test:** use an 8-node *block* with distinct edge
lengths (I used 1 × 1.3 × 1.7, which gives six distinct frequencies) and assert `diag(MAC) == 1` to
1e-12; or keep a literal cube and assert the block sums. Asserting a unit per-mode diagonal on a
solved literal cube will be flaky for reasons that have nothing to do with this function.

## Notes for other agents

* **R8-F1 / docs.** `from femtools.correlation.dofmap import mapped_mode_matrix` resolves on this
  tree, so the R8 row can move off `R8-wip`. It is exported from `femtools.correlation` but **not**
  from `femtools/__init__.py` (not mine to edit); if a top-level export is ever wanted the entry is
  `"mapped_mode_matrix": "femtools.correlation.dofmap"`. Public literature only, and nothing new is
  claimed: the gather is bookkeeping around the nearest-neighbour node match already cited for
  `map_nearest_nodes`, feeding the MAC of Allemang & Brown 1982 (Allemang, "The Modal Assurance
  Criterion — Twenty Years of Use and Abuse", *Sound and Vibration*, 2003). It is explicitly **not**
  an expansion or a reduction — no SEREP, no Guyan, no interpolation — and the docstring says so, so
  it should not be described next to `expand_serep` / `expand_guyan`.
* **R8-G1 / tests.** Cheap regressions, none of them in a `test_round8_*` file: a translated,
  renumbered 8-node **block** (not cube — see above) gives `diag(MAC) == 1` to 1e-12;
  `mapped_mode_matrix(phi, ids)` equals an explicit `vstack` of `phi[6*i:6*i+6]`; an unmatched `-1`
  raises by default and is zeroed / dropped on request; `dofs=("x","y","-z")` negates only the third
  row of each block; a repeated id is gathered twice.
* **R8-G2 / probes.** `probe_mapped_mode_matrix` was already written against this signature and
  passes unchanged (`max_mac_diagonal_error: 0.0`). The interesting boundaries beyond it are the
  `missing=` policies, a non-one-to-one match, and the no-`dof_map` fallback when the ids are model
  node ids (it must raise, not gather the wrong block).
* **R8-F3 / notes and examples.** The end-to-end story above (digitize in a rotated frame → align →
  map → gather → MAC) is an example-sized script; `examples/` is not mine.
* **No existing API changed.** The two edited files gained one public function, three module-private
  helpers, one `__all__` entry each and two docstring paragraphs. `mac_matrix`, `map_nearest_nodes`,
  `align_modes`, `DOFMap` and every pretest name behave exactly as before.
