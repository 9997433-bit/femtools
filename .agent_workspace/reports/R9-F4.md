# Cycle C Round 9 — R9-F4 (CLI / script / GUI polish)

## Changes

### CLI (`src/femtools/cli.py`)

- `femtools dump-frf`: writes a reloadable FRF archive via
  `femtools.dynamics.frf.dump_frf`. Accepts either a model file (synthesizes
  modal FRFs with the same `--input/--response/--fmin/--fmax/--n-freq/
  --n-modes/--damping` options as `frf`, through a new shared `_synth_frf`
  helper) or a plain `.npz` already carrying `freq_hz`/`H` (e.g. saved by
  `frf -o` / `estimate-frf -o`), which it canonicalizes. `--compress` writes
  a compressed archive; provenance (`source`, `damping`) goes into `meta`.
- `femtools load-frf`: reads an archive back via `load_frf`, prints a summary
  table (shape, band, response kind, method, DOF ids, meta) and saves a Bode
  plot with `--plot` (curve selected by `--plot-output`/`--plot-input`).
  Non-archive/corrupt inputs exit 2 with the kernel's message.
- `femtools update-static`: wraps `femtools.updating.updater.update_from_static`.
  Repeatable `--measure NODE:DOF=VALUE` specs (same syntax as `--load`, DOF
  1–6) build the kernel's `{(node, component): value}` mapping; repeatable
  `--load` adds the test load (via a new `_apply_load_specs` helper shared
  with `recover-stress`/`plot-stress`); `--config` passes extra
  `update_from_static` kwargs from JSON; `--output` saves the updated model
  as `.ftproj`. Prints `UpdateResult.summary()`.
- All three lazy-fail in the `recover-stress`/`plot-stress` style: a missing
  `femtools.dynamics.frf` / `femtools.updating.updater` exits with code 3 and
  the standard missing-module message (verified by blocking the imports).
- `frf` behavior is unchanged (same options, output, messages); it now calls
  the extracted `_synth_frf`.

### ScriptEngine (`src/femtools/script/engine.py`, `script/README.md`)

- `UPDATE STATIC MEASURE=<node>:<dof>:<value>[,...] [NAME=..] [APPLY=YES|NO]`:
  wraps `update_from_static` with the default one-parameter relative-E fit;
  DOF numbers are 1-based like the rest of FSL. The `UpdateResult` is stored
  in `engine.results[NAME]` (default `"update"`) and the updated model copy
  replaces the active project unless `APPLY=NO`. Lazy `ScriptError` when
  `femtools.updating` is missing.
- `DUMP FRF <path> [RESULT=<name>] [COMPRESS=YES|NO]`: dumps a stored result
  carrying `H`+`freq_hz` through `dump_frf` (default: the most recent such
  result; FSL has no FRF producer yet, so this serves embedded engines).
  Lazy `ScriptError` when `femtools.dynamics` is missing.
- Existing commands untouched: `NEW`, `ADD` (incl. `RBE2`/`RBE3`), `SPC`,
  `SET`, `SOLVE MODES`, `SOLVE STATIC`, `RECOVER STRESS`, `MAC`, `SAVE`,
  `PRINT` all keep their handlers and dispatch entries.
- README: grammar (EBNF `update`/`dump` productions, `measurelist`/`yesno`
  terminals), command reference sections for both verbs, and the lazy-module
  error paragraph updated.

### GUI (`src/femtools/gui/page.py`, `src/femtools/gui/state.py`)

- The page now has a "Stress" section that displays `GET /api/stress`: a
  table of element id, type, the six Voigt components (headers from the
  endpoint's `components`) and von Mises, plus an n-elements / truncation /
  max-von-Mises footer. It refreshes on page load, on Refresh, and after
  every script run / model load. All 400 responses (no model, no static
  result, missing recovery kernel, bad result name) render as a muted hint
  from the JSON `error` — the page never breaks (both backends answer 400s
  with JSON bodies).
- Plot list: a `stress` plot is requested when the results contain a static
  result (`plotNames`); `GuiState.render_png` gained the `"stress"` kind,
  which recovers stresses from the most recent static result and colors the
  mesh with `viz.plot_stress` (matplotlib/Agg). Without a static result it
  raises `GuiApiError` (400) and the existing `onerror` handler hides the
  figure.
- `GuiState`: the static-result lookup and guarded recovery were extracted
  into `_latest_static` / `_recover_stress`, shared by `stress_table`
  (unchanged JSON shape and error texts) and `render_png`.
- `femtools.viz` untouched; `import femtools.viz` still does not import
  pyvista (asserted).
