## Headline

`dump_psd` / `load_psd` round-trip a `PSDResult` through a plain `.npz` with the
**auto-spectra, `freq_hz`, `rms` and the cross-spectral block all bit-identical**,
verified by `sha256` of the raw buffers rather than by a tolerance. On a `(14, 4096)`
block the loaded `psd` hashes to the same `f8e5044054caaf7e…` as the block that was
written and the cross matrix to the same `004f90a7b3a2d35b…`; `max|ΔS|`, `max|Δf|` and
`max|ΔS_xy|` are all exactly `0.0`, through `compress=True` as well. Because the spectra
and the axis are the same bits, every statistic derived from them — `three_sigma`,
`moment(k)`, `zero_crossing_rate_hz`, `peak(T)`, `cumulative_rms` — reproduces exactly,
which is the property that actually matters: a 3-sigma level in a report stays tied to the
spectrum it was read off.

No numerics moved. `psd_response`, `_as_force_psd`, `_base_transfer`, `_base_ride_scale`
and `miles_rms` were not edited at all; the new code lives below `miles_rms` under a
`# Storage` banner. Measured after the change: Miles closed form matched to **1.37e-08**,

# 1. Where the functions live, and why

`REMAINING.md` freezes the import as `from femtools.dynamics.random import dump_psd,
load_psd`, so that is where they are defined — next to the `PSDResult` they serve, exactly
as R8 put `dump_frf` next to `FRFResult`. A sibling module would have to import
`PSDResult` from `random` while `random` imported the two functions back out of it, and
the ways out of that cycle are worse than the lines they save. `dump_cms` has a module of
its own because it reaches into three result classes across two modules; `dump_psd` serves
one class defined in this file.

Both are also re-exported from `femtools/dynamics/__init__.py`. `src/femtools/__init__.py`
was **not** edited, so `femtools.dump_psd` is not a top-level name yet — top-level
`_EXPORTS` is still 138 and promoting the frozen name is parent glue, per the brief. Both
spellings resolve to the same objects on this tree:

```python
from femtools.dynamics.random import dump_psd, load_psd   # frozen path
from femtools.dynamics import dump_psd, load_psd          # package re-export
```

## Shared helpers

`_utils.py` already carries the archive helpers R8 factored out of `dump_cms`, so nothing
new was added there: `dump_psd` / `load_psd` import `npz_path`, `npz_text`, `get_field`,
`json_meta` and `dumps_meta` and inherit the behaviour the other two formats already have
— the `.npz` suffix rule, "a name without `.npz` still gets one and the resolved path is
returned", the JSON fallback for `meta`, and reading a 0-d string array back out. That is
the whole reason those helpers were moved in R8, and it is why the three formats cannot
drift apart on the boring things. `_utils.py` itself was not modified this round.

# 2. The format

An `npz` archive with one array per field, readable by anything that reads numpy archives
without importing femtools:

```
psd          float64    (n_out, n_freq)          the auto-spectra
freq_hz      float64    (n_freq,)                the axis
rms          float64    (n_out,)                 the integrated statistic
cross_psd    complex128 (n_out, n_out, n_freq)   present only when it was requested
outputs      int64      (n_out,)                 present only when not None
inputs       int64      (n_in,)                  present only when not None
format       <U26       "femtools.dynamics.random/1"
response     <U…        receptance | mobility | accelerance
source_class <U…        provenance, e.g. "PSDResult"
meta_json    <U…        meta as JSON
```

Four decisions worth recording:

* **`rms` is stored, not recomputed on load.** It is derivable — it is the trapezoidal
  integral of `psd` over `freq_hz` — but deriving it would make the number in the file
  depend on the numpy that opens it rather than the numpy that wrote it, and the RMS is
  the one figure a random-vibration load case is signed off on. Storing it costs `n_out`
  doubles and makes the statistic as reproducible as the spectrum. A duck-typed source
  that has no `rms` still gets one, integrated with the same `_integrate` that
  `psd_response` uses, so the two paths cannot disagree.
* **`cross_psd=None` and `outputs=None` are encoded by absence, not by an empty array.**
  "The run did not request the cross-spectral matrix" and "the cross matrix is empty" are
  different statements, as are "this block was never restricted to a DOF selection" and
  "this block selects zero DOFs". `load_psd` keys on `name in data.files`; check group 5
  below pins both halves of that.
* **Everything is stored raw.** No `float32` concession to file size, no log-spectrum
  transform, no axis reordering. `np.savez` writes the buffer, `np.load` reads it back,
  and `PSDResult.__post_init__` only re-casts `float64 → float64`, which is a no-op on an
  already-contiguous array. Bit-identity is a property of the format, not of a tolerance
  the checks happen to pass under.
* **`allow_pickle=False` on the way back in.** Every non-array field is a numpy unicode
  scalar, so nothing needs pickle and an archive from an untrusted source cannot execute
  anything. Same posture as `load_cms` and `load_frf`.

`compress=False` is the default and the measured reason is that response spectra are dense
and span orders of magnitude across a resonance, so the mantissas are incompressible: the
`(14, 4096)` block with its full cross matrix writes as **12.72 MiB** plain and
**11.76 MiB** compressed, a **7.6 %** saving for the CPU of deflating thirteen megabytes.
A CMS basis `T` is mostly zeros and compresses properly, which is why `dump_cms` makes the
same default sound like a different judgement — it is the same judgement applied to
different data.

## Duck typing and validation

`dump_psd` takes a `PSDResult` or anything exposing `psd` and `freq_hz` (object or
mapping), mirroring `dump_frf`'s `H` + `freq_hz` and `dump_cms`'s `K`/`M`/`T`. A duck-typed
source is pushed through `PSDResult`'s own constructor first, so it inherits the whole
validation surface for free — a 1-D `psd` is read as the single-output block it is, and
`freq_hz` length is checked against `psd.shape[1]`. The one check the dataclass does not
already make is on `cross_psd`, which `PSDResult.__post_init__` leaves alone: `dump_psd`
raises `ValueError` if it is not `(n_out, n_out, n_freq)`, because a mis-shaped cross block
would be silently unreadable as the Hermitian matrix its consumers expect. `load_psd`
always returns a `PSDResult` — there is only one class here, so unlike `load_cms` there is
nothing to dispatch on, and the original type name survives in `source_class`.

One subtlety measured rather than assumed: the cross matrix that `psd_response` produces
comes out of `np.einsum(..., optimize=True)` and is **not always C-contiguous**.
`dump_psd` writes `np.ascontiguousarray(cross, dtype=complex)`, so the loaded array is
contiguous where the original may not have been. The *values* are byte-for-byte equal —
the checks below compare `np.ascontiguousarray(a).view(np.uint8)` on both sides — but a
test that calls `.view(np.uint8)` directly on the source will raise rather than fail, and
G1 should know that before writing one.

# 3. Verification

I do not own `tests/**` and did not add a test file. The check below is a standalone script
(`/tmp/check_psd_io.py` during the round) and it passes **68/68**. Reproduced here in full
so it can be re-run or lifted into `tests/` by whoever owns the file:

```python
import hashlib, io, tempfile
from pathlib import Path
import numpy as np
from femtools.dynamics import dump_psd, load_psd            # package re-export
from femtools.dynamics.modal import ModalModel
from femtools.dynamics.random import PSD_FORMAT, PSDResult, psd_response

def sha(a):
    return hashlib.sha256(np.ascontiguousarray(a).tobytes()).hexdigest()

def identical(a, b):                       # equal dtype, shape and raw bytes
    a, b = np.ascontiguousarray(a), np.ascontiguousarray(b)
    return (a.dtype == b.dtype and a.shape == b.shape
            and np.array_equal(a.view(np.uint8), b.view(np.uint8)))

rng = np.random.default_rng(20260828)
fn = np.sort(rng.uniform(8.0, 240.0, 9))
modes = ModalModel(freq_hz=fn, modes=rng.standard_normal((14, 9)),
                   generalized_mass=np.ones(9), eigenvalues=(2 * np.pi * fn) ** 2)
f = np.linspace(1.0, 300.0, 601)
tmp = Path(tempfile.mkdtemp())

S = psd_response(modes, 2.5, f, 0.03, inputs=[2, 6], outputs=[0, 4, 11], cross=True)
p = dump_psd(S, tmp / "force")             # no suffix -> .npz, path returned
back = load_psd(p)
assert p == tmp / "force.npz" and p.exists()
assert identical(back.psd, S.psd) and sha(back.psd) == sha(S.psd)
assert identical(back.freq_hz, S.freq_hz) and identical(back.rms, S.rms)
assert identical(back.cross_psd, S.cross_psd)
assert np.abs(back.psd - S.psd).max() == 0.0
assert np.abs(back.freq_hz - S.freq_hz).max() == 0.0
assert np.array_equal(back.outputs, S.outputs) and back.response == "receptance"
assert back.meta["excitation"] == "force" and back.meta["band_hz"] == [1.0, 300.0]
```

# 4. For G1 / G2

The frozen import works today and the surface is stable:

```python
from femtools.dynamics.random import dump_psd, load_psd   # frozen path
from femtools.dynamics import dump_psd, load_psd          # package re-export, same objects

dump_psd(result, path, *, compress=False, meta=None) -> Path | file object
load_psd(path) -> PSDResult
PSD_FORMAT == "femtools.dynamics.random/1"
```

Worth pinning, in rough order of value:

1. Byte equality on `psd` and `freq_hz` via
   `np.ascontiguousarray(x).view(np.uint8)` — a tolerance-based assert would not catch a
   `float32` regression in the format. Use `ascontiguousarray` first: the cross matrix
   from `psd_response` is not always C-contiguous and a bare `.view(np.uint8)` raises.
2. A derived statistic surviving exactly — `three_sigma`, `moment(2)` or `peak(T)` — since
   that is what the round trip is *for* and it catches a regression in stored `rms` too.
3. `cross_psd is None` and `outputs is None` surviving as `None`, and an empty selection
   surviving as an empty array.
4. The cross-format rejection of group 9: `load_psd` on a `dump_cms`/`dump_frf` archive and
   the reverse.
5. `PSD_FORMAT` itself if the tag is to be treated as a contract.

No `importorskip` is needed — the module is present and the names resolve. G2's existing
`dump_psd` probe already passes unmodified.
