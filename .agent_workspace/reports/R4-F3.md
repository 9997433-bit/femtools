### 1.2 Validation methodology (the key evidence)

Since the kernels don't exist yet, I wrote **throwaway literature reference
implementations** of all four modules in `/tmp/r4f3/shims.py` (not committed) and
dry-ran everything against them:

- the three examples pass **25/25 checks** (6 + 3 + 16);
- R4-G1's already-landed `tests/test_round4_reduction.py`, `test_round4_cms.py`,
  `test_round4_mpe.py` pass against the *same* reference implementations
  (6 passed, 1 skip = `solve_complex_modes`, not exercised by my files).

So the docs spec, the examples, and G1's tests are mutually consistent — one
implementation satisfies all three consumers. Measured dry-run numbers (quoted in the
docs as targets, not regression facts):

```
guyan_serep: static exactness 1.1e-12; Guyan errs 6.3e-4 → 3.4e-2 (modes 1→6),
             IRS mean 1.35e-2 → 3.78e-4; SEREP freq dev 2.3e-13, shape recon 7.4e-16
cms_rubin:   max rel err first 4 coupled modes: Rubin 1.9e-7, MacNeal 7.7e-5, CB 2.9e-5
h1_ssi:      max|H1|/|H2| = 0.9996; γ² identity dev 7.8e-16; H1 vs ZOH-exact 4.2 % median
             (vs continuous receptance 3.0 % magnitude — 32 % complex, half-sample delay);
             SSI: f errs ≤ 0.04 %, ζ errs ≤ 9 %, MAC ≥ 0.9997, 2 spurious poles filtered
```

One real bug was caught this way: comparing H1 against the *continuous* receptance gives
32 % complex error purely from the ZOH half-sample delay — the example now compares
against the ZOH-exact discrete FRF and reports the continuous-magnitude deviation as a
note. A second interop hazard was caught by G1's tests: `serep` must **not** return a
bare ndarray, because consumers probing `.T` first read its transpose (now spec'd).

## 3. Contract decisions siblings should honor (summary)

1. Reduction/CMS APIs are **matrix-level with integer DOF indices** (like
   `craig_bampton`), not model/dof-tuple level; callers translate via
   `dof_map`/`free_dof`.
2. `ReductionResult` = NamedTuple `(T, Krr, Mrr)`; `T` rows in original DOF ordering
   with `T[master] = I`; `serep` never returns a bare ndarray.
3. `FreeCMSResult` orders reduced coordinates `[boundary..., modal...]` and exposes
   `.K/.M/.T`; MacNeal consumers must QZ (examples do).
4. `estimate_h1/h2/coherence` return `(freq_hz, array)` tuples (dataclass with
   `.freq_hz/.H` also tolerated by example + G1 test); all three must share one
   segmentation or the γ² identity check fails.
5. `ssi_cov(data, fs, *, order, n_modes=None, n_block_rows=None)` →
   `ModalParameterResult`; `order` counts pole pairs (lsce convention); G1's test
   passes `n_modes=2`, my example passes only `order=`.
