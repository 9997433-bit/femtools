## write_cdb (`io/cdb.py`)

Emits exactly the record subset `read_cdb` parses: one `ET` per ANSYS
element number, free-format `MP` (EX/NUXY/DENS/ALPX, GXY only when E is
underivable), `R`/`RMORE` real-constant sets and `SECTYPE`/`SECDATA`
shell sections keyed by the femtools property id, one fixed-format
`NBLOCK,6,SOLID`/`EBLOCK,19,SOLID` pair (`(3i9,6e21.13e3)` /
`(19i9)`, `N,R5.3,LOC,-1` and `-1` terminators), `D`/`F` records,
`FINISH`.  Mapping: HEX8→SOLID185, TET4→SOLID285, QUAD4/TRIA3→SHELL181
(TRIA3 as the degenerate quad), BEAM2→BEAM4 (R1=A, R2=IZZ, R3=IYY,
RMORE R8=IXX=J), BAR2→LINK180, TRUSS2D→LINK1, MASS→MASS21 (RC1=m),
SPRING→COMBIN14 (RC1=k).  BEAM2 orientation vectors are materialized as
BEAM4 K nodes — one extra grid per distinct (end A, orientation)
position, ids after the real nodes, shared between elements; they read
back as unattached nodes whose DOFs the assembler drops.  Documented
losses, one aggregated `UserWarning` each: DAMPER elements, SPRING DOF
pins, beam kappa, bar J, nsm, material GE, RBE2 tables, non-1 SPC/load
set ids, nodal `cd`.  Property ids are not carried by the format (the
reader re-synthesizes per (kind, MAT, REAL, SECNUM)); the model name
comes from the file stem on read.  `write_cdb(path, model)` and
`(model, path)` both accepted (io `_compat` convention).

## write_k (`io/kfile.py`)

Comma free format everywhere (full double precision `%.17g`; the reader
accepts commas on every card): `*TITLE` = model name, `*NODE`,
`*ELEMENT_SOLID` (TET4 with last corner repeated to 8), `*ELEMENT_SHELL`
(TRIA3 with n3 repeated), `*ELEMENT_BEAM` (orientation vectors as extra
third nodes, shared, ids after the real nodes), `*MAT_ELASTIC` /
`_TITLE` when the material has a name (mid, ro, e, pr; E derived as
2G(1+nu) if only G is given, else `KFileError` — the card requires
E > 0), one `*SECTION_*` + `*PART` pair per property (secid = part id =
property id, part title = property name; beam → ELFORM 2 resultant
A/ISS=Iy/ITT=Iz/IRR=J (+SA from Asy/Asz attrs), bar/TRUSS2D → ELFORM 3
truss with a trailing comma so the single-value card stays free-format),
`*BOUNDARY_SPC_NODE` rows, `*END`.  Round-trip therefore preserves the
model name, property ids and material names (unlike CDB).  Losses, one
aggregated warning each: MASS/SPRING/DAMPER + lumped properties, nodal
loads, RBE2, enforced SPC values (written fixed-at-zero), kappa, nsm,
TRUSS2D→BAR2.  Named sets are dropped silently (metadata; documented).

## read_bdf INCLUDE + RBE2 (`io/bdf.py`)

* INCLUDE is expanded **textually at the physical-line level** (real
  preprocessor semantics: continuations work across file boundaries).
  Relative names resolve against the directory of the *including* file;
  quoted (`'…'`/`"…"`) and bare single-line forms accepted; `$` comments
  stripped first.  Max nesting 8 (`_INCLUDE_MAX_DEPTH`), cycles detected
  via the resolved-path stack (error message shows the cycle chain),
  missing file / unterminated quote / too deep → `BdfError` with file +
  line context.  INCLUDE lines in the skipped executive/case-control
  section are not expanded (pinned by test).  The old "INCLUDE not
  followed" warning is gone.
* `RBE2, EID, GN, CM, GM1…[, ALPHA[, TREF]]` → `model.add_rbe2(id,
  independent, dependents, components)` with CM digits validated 1..6
  (`BdfError` otherwise), THRU in the GM list, and the trailing
  real-typed ALPHA ignored with an aggregated note.  Model-level
  integrity (duplicate id, missing grid, independent∈dependents) stays
  with `FEModel.add_rbe2`/`ModelError` — the dataclass was not touched.
* `write_bdf` now emits `model.rbe2` as RBE2 cards (sorted unique CM),
  so the driver deck and BDF round-trips are lossless for rigid links.
  RBE3 stays unsupported → the usual aggregated UserWarning (pinned).

`drivers/__init__.py`; `drivers/base.py` docstring updated (contract +
one shipped text-only adapter; still no binary parsers).

  ALL` header and an `EIGRL,1,,,n_modes` card right after `BEGIN BULK`

  reads back through femtools' own `read_bdf` (EIGRL aggregates as an
