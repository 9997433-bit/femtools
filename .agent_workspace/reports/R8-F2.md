# R8-F2 — BDF RBE3 + ANSYS/Abaqus text drivers

## Delivered

### `read_bdf` / `write_bdf`: RBE3 (`src/femtools/io/bdf.py`)

* Parses the public card layout `RBE3 EID blank REFGRID REFC WT1 C1 G1 ...
  [WT2 C2 ...] ["UM" ...] ["ALPHA" a]` into `FEModel.add_rbe3` (parent's
  frozen table, consumed as-is): `dependent=REFGRID`, `components=REFC`
  digits, flat `independents`/`weights` built group-wise (each grid gets its
  group's WTi). `THRU` is expanded inside the grid lists. Small-field,
  free-field and continuations all work; free-field trailing `+` markers
  are skipped.
* Unsupported/degraded fields raise **one aggregated `UserWarning` per
  file**, itemized per EID: the `UM` m-set override, the thermal `ALPHA`
  tail, mixed per-group `Ci` lists (first group's list is used for all
  grids — the table holds a single `independent_components`), and REFC
  components not present in `Ci` (dropped). The last case is a real model
  degradation, not bookkeeping: femtools' RBE3 is a component-wise
  weighted average (see R8-O1), so `REFC=123456` fed by translation-only
  independents cannot supply the rotations that real Nastran recovers via
  its least-squares geometry fit. This also keeps the Round-7 pin
  `test_bdf_rbe3_still_warns_as_unsupported` green on its exact deck
  (`RBE3,7,,1,123456,1.,123,2` still warns with "RBE3"; `rbe2` stays empty).
* Malformed cards (bad REFC/Ci digits, non-positive weight, grid before the
  first WT/C pair, empty grid list, dangling THRU) raise `BdfError`.
* `write_bdf` emits one RBE3 card per table row: field 3 blank per the
  public layout, one `WTi, Ci` group per run of equal weights,
  `Ci = independent_components`. `weights=None` writes as `1.0` and reads
  back as an explicit equal tuple. Round-trips are exact (ids, dependent,
  independents, components, weights).
* INCLUDE (depth ≤ 8, cycle-safe) and all RBE2 behavior untouched.

### Drivers (`src/femtools/drivers/`)

* `ansys.py` — `AnsysCdbDriver` (`name="ansys-cdb"`): `write_input` writes
  `<stem>.cdb` byte-identical to `write_cdb` (solution commands are the
  caller's APDL setup); `is_available` probes `shutil.which` over the
  `ansys`/`mapdl` aliases (or the explicit `executable=`); `run` launches
  `<exe> -b -i <deck> -o <deck>.out` and raises `SolverError` on missing
  executable / non-zero exit / timeout / no text result, returning the
  `.pch` or `.unv` the run produced (a lone `.rst` gets a dedicated
  "RST is N/A" hint); `read_modal` reads `.pch` (`read_pch`) and
  `.unv`/`.uff` (`read_unv().modal`) text only — a `.rst` path raises
  `SolverError` naming RST as N/A.
* `abaqus.py` — `AbaqusInpDriver` (`name="abaqus-inp"`): same conventions
  with `write_inp`, the `abaqus` alias, the
  `<exe> job=<stem> input=<deck> interactive` launch line, and ODB as the
  N/A binary format.
* `_textrun.py` — shared private plumbing (PATH resolution, the Round-7
  `SolverError` launch conventions, `.pch`/`.unv` read-back) so the two
  drivers cannot drift. `nastran.py` is untouched (its messages are pinned
  by Round-7 tests).
* Both exported from `drivers/__init__.py`; `femtools/__init__.py` not
  touched (R8-F1 owns the lazy exports). Both pass
  `isinstance(driver, SolverDriver)`.
