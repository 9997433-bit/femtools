## 1. `plot_stress(model, stress, component="von_mises", ...)`

- Frozen import works: `from femtools.viz.plots import plot_stress`; also
  exported from `femtools.viz`.
- `stress` is a `StressResult` (duck-typed: `element_ids` + `(n, 6)` Voigt
  `stress`, precomputed `von_mises` used when present) or a mapping
  `{eid: scalar | 6 components}`.
- `component`: `von_mises` (default, aliases vm/mises), Voigt names
  `xx yy zz xy yz zx` (also `sxx`-style spellings), a 0-based column index,
  or any per-element array attribute of the result (e.g. `max_shear`).
- matplotlib default: surface elements → filled `PolyCollection` /
  `Poly3DCollection` faces (HEX8/TET4 via a boundary-face table), line
  elements → colored `LineCollection` segments, elements without a value
  (e.g. `StressResult.skipped`) → neutral wireframe. 2D for planar XY
  models, 3D otherwise; colorbar labeled with the component.
- `backend="pyvista"` reuses the existing `plot_mesh3d` optional path
  (`_pyvista()` error message, `_pyvista_grid` cell ordering) and colors
  cells via `cell_data` with `nan_color` for uncovered elements. pyvista is
  never imported otherwise; verified `import femtools.viz` leaves
  `pyvista` out of `sys.modules` (pyvista is not installed on this tree,
  so the import-independence is exercised for real).

## 2. CLI `femtools plot-stress`

- Same lazy-import style as `recover-stress` (now literally shared via
  `_recover_pipeline`): missing `femtools.fea.recover` or
  `femtools.fea.static` → same red missing-module message, exit code 3
  (verified with an import-blocking hook for both subcommands).
- Options: `--load/-l` (repeatable `NODE:DOF=VALUE`), `--component/-c`,
  `--output/-o` (default `stress.png`), `--cmap`. Bad component → exit 2.

## 3. ScriptEngine

- `RECOVER STRESS [NAME=..] [RESULT=..]`: default result = most recent
  `SOLVE STATIC` (tracked, reset by `NEW PROJECT`); clear `ScriptError`
  when there is no static result, the named result is missing or is not a
  static result, or `femtools.fea` is absent. Stores the `StressResult`
  under `NAME` (default `"stress"`).
- `ADD RBE2 <id> INDEP=<node> DEP=<n1,n2,...> [DOF=<comps>]` →
  `FEModel.add_rbe2` (model defaults preserved when DOF omitted).
- `ADD RBE3 <id> DEP=<node> INDEP=<n1,...> [DOF=..] [IDOF=..]
  [WEIGHTS=..]` → `FEModel.add_rbe3`; components accepted as comma lists
  (`1,2,3`) or compact digits (`123`); validation errors from the model
  (duplicate id, bad weights, ...) propagate as `ModelError`, consistent
  with the other `ADD` statements.
- Existing commands untouched (`SOLVE STATIC`/`SET`/... all pass);
  README grammar + command reference updated.

## 4. GUI `/api/stress` (both backends)

- `GET /api/stress[?name=..&max_rows=..]` on the stdlib and fastapi
  backends, both thin wrappers over the new `GuiState.stress_table`.
- Runs `recover_stress(model, static)` against the newest stored static
  result (or the one named by `name=`) and returns a small JSON table:
  `result`, `components`, `n_elements`, `truncated`, `max_von_mises`,
  `skipped`, and per-element rows (`element`, `type`, `von_mises`,
  6 Voigt `stress` values), capped at `max_rows` (default 20).
- 400 (`GuiApiError`) when: no model, no static result, unknown result
  name, non-static result, recovery kernel not installed, recovery
  failure, bad `max_rows`. Verified live on the stdlib server (ephemeral
  port) and on uvicorn+fastapi, including the missing-kernel 400 via an
  import-blocking hook.
