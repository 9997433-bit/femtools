## The new API

```python
macx(phi_a, phi_b=None, *, weights=None)             -> (n_a, n_b) in [0, 1]
nmd(phi_a=None, phi_b=None, *, weights=None, mac=None, relative=False)  -> same shape as the MAC
```

### `macx` — extended MAC for complex modes

```
macx[i, j] = (|a^H W b| + |a^T W b|)^2 / ((a^H W a + |a^T W a|) (b^H W b + |b^T W b|))
```

Vacher / Jacquier / Bucharles (IMAC–ISMA 2010) MACX: the classical MAC keeps only the Hermitian
product, which measures two complex modes *as digitized*. Adding the bilinear product `a^T b` makes
the criterion invariant to conjugation — swapping `b` for `conj(b)` exchanges the two terms and
leaves the sum untouched — while keeping the complex-scaling invariance of the MAC.

Same call signature, same input handling and the same degenerate-case behaviour as `mac_matrix`:
1-D input is one mode, a `ModalResult` is unwrapped, `weights` takes a scalar / 1-D lumped diagonal
/ dense / sparse operator, a null mode gives 0 rather than NaN, and a self-comparison is exactly
symmetric with a bit-exact unit diagonal.

### `nmd` — Normalized Modal Difference

`sqrt(1 - MAC)`, the sine of the angle whose squared cosine the MAC is. The MAC is flat near 1
(two shapes differing by 5 % score 0.9975); the NMD is linear in the mismatch there (0.05) and reads
directly as a fraction of the shape.

* `mac=` takes a pre-computed matrix, so `nmd(mac=macx(phi_a, phi_b))` gives the NMD of the extended
  criterion. `weights=` is forwarded to `mac_matrix` otherwise.
* `relative=True` returns Allemang's ratio form `sqrt((1 - MAC) / MAC)` — the tangent instead of the
  sine, the difference measured against the correlated part of the shape. The two agree to first
  order for well-correlated modes; the ratio form diverges as MAC → 0 and returns `inf` there
  (not NaN). The default is the `sqrt(1 - MAC)` form the round brief froze.
* `1 - MAC` is floored at 0, so a weighted or user-supplied MAC that overshoots 1 by a round-off
  gives 0 instead of NaN.

## Verification of the new API

Three throwaway probes in `/tmp` (~90 assertions). Every one passes.

| Property | Result |
|---|---|
| MACX vs element-wise brute force | 8 combinations (real/complex × none/1-D/dense/sparse weight): ≤ 2.8e-16 |
| **MACX == MAC on real modes** | `np.array_equal` — bit exact, plain / weighted / self / complex dtype with zero imaginary part |
| Complex-scaling invariance | `macx(a, b * c) == macx(a, b)` for random complex `c`: 1e-13 |
| Conjugation invariance | `macx(a, conj(b)) == macx(a, b)` and the same on the left argument: 1e-13 |
| A mode against its own conjugate | MACX diagonal 1.0 while the classical MAC gives ≤ 0.11 on the same modes |
| Bounds | 1200 Nelder–Mead restarts on the *unclipped* reference maximize at 1.0000000000000011, plus 20 000 structured `a^T a = 0` pairs at 0.99999999869 — the bound is tight and attained, so the `[0, 1]` clip only absorbs round-off |
| Structure | self-case exactly symmetric, unit diagonal, `macx(a) == macx(a, a)`, null mode → 0, DOF mismatch raises |
| Phase scatter | under per-DOF phase scatter MACX ≥ MAC on every mode (0.08–0.13 higher), i.e. it does isolate the pure-phase part of a low MAC |
| NMD identities | `nmd == sqrt(1-MAC)` to 0 ulp; shape, non-negativity, zero self-diagonal, `mac=` path bit-identical, weighted path, `relative` == `sqrt((1-MAC)/MAC)` to 1e-12 and ≥ the default form |
| NMD linearity | a shape perturbed by `eps` in an orthogonal direction gives `eps/sqrt(1+eps²)` exactly, for eps = 1e-1, 1e-2, 1e-3 |
| NMD edge cases | MAC = 0 → 1 (and `inf` with `relative=True`), MAC = 1+1e-16 → 0, no arguments raises |

**End to end.** A 12-DOF chain with one discrete damper at DOF 5 (non-proportional), through
`solve_complex_modes`:

* With proportional damping (ζ = 0.006…0.061) the modes stay real up to a phase and
  `max|MACX − MAC| = 0.0e+00` over the whole 6×6 matrix.
* With the local damper (ζ = 0.08…1.0) two modes returned conjugated — exactly what a curve fit may
  hand back for the other half of a conjugate pair — score **MAC 0.420 / 0.427** against
  **MACX 1.000000**. `pair_modes(..., mac=macx(...), mac_threshold=0.9)` then recovers the identity
  pairing; on the classical MAC matrix it does not.
* The NMD ranks the six proportional-vs-damped pairs in the exact reverse of the MAC order and
  spreads MAC 0.983…0.999 into NMD 0.025…0.131.

## The three defects

### 1. `exclude=(node, "X")` deleted the whole node — `candidates.py`

`candidate_dofs(..., exclude=...)` documents "node ids (or `(node, component)` keys)". A key inside
a list worked; a **bare** key did not. `np.atleast_1d(np.asarray((2, "X"), dtype=object))` is two
items, `2` and `"X"`, so the integer dropped every DOF of node 2 and the orphaned `"X"` failed to
parse and was silently skipped by the `missing="skip"` lookup:

```
exclude=[(2, "X")]  ->  1X 1Y 1Z 2Y 2Z 3X 3Y 3Z 4X 4Y 4Z     (correct: one DOF gone)
exclude=(2, "X")    ->  1X 1Y 1Z       3X 3Y 3Z 4X 4Y 4Z     (three DOFs gone, no warning)
```

This is the same family as the bare-string case the package already guards with `_as_item_list`
("12Z" must be one label, not three characters). A bare 2-sequence whose second entry is a *string*
is now kept whole; `(2, 3)` stays two node ids, which is what an all-integer pair has always meant
and the only reading that keeps `exclude=(2, 3)` working.

### 2. A NumPy integer node id was silently ignored — `candidates.py`

`is_node` tested `isinstance(i, int)`. `np.int64` is not an `int`, so `exclude=dmap.nodes[0]` (or
any id taken straight out of a DOF map, an `np.unique` result, a candidate set) was classified as a
DOF key, failed `parse_dof_label`, and was skipped: **nothing at all was excluded**. `exclude=2`
and `exclude=np.array([2])` both worked, which is what makes the failure hard to spot — the object
cast in `np.asarray(..., dtype=object)` converts the elements of an *array* to Python ints but
leaves a NumPy *scalar* as it is. The test is now `isinstance(i, (int, np.integer))`, matching
`parse_component` and `_parse_key_raw` in `dofmap.py`.

### 3. Wrong-shaped exciter coordinates were reshaped into fiction — `exciter.py`

`select_exciters(..., coords=xyz, min_separation=d)` did
`np.asarray(coords, dtype=float).reshape(n_cand, -1)`. Candidates are DOFs and coordinates are
nodal, so the natural mistake is to pass the model's `(n_node, 3)` table for a candidate set holding
three DOFs per node — and its size is then *exactly* `3 · n_node`, so the reshape succeeds. A
`(4, 3)` table for 12 candidates became a `(12, 1)` column holding `x, y, z, x, y, z, …`: 12
one-dimensional "positions" that no point of the structure occupies. The separation constraint was
then enforced on those, and the run returned a different, silently wrong pair of drive points
(`[3, 9]` instead of `[0, 8]`) with no error.

The row count is now validated instead of reshaped. Everything that used to work still does: a
`(n_cand, 3)` table, a `(n_cand, 2)` planar one, a flat `(3 n_cand,)` array (still folded to xyz)
and a 1-D `(n_cand,)` array of stations along a line. A row count that does not match, or more than
three columns, is reported with the shape that was wrong.

## Not bugs (checked, deliberately left alone)

* **`parse_dof_label("-2Y")` raises.** The leading `-` sign convention belongs to the *component*
  (`"2-Y"`, `(2, "-Y")`, `components="-Z"`), which all work; a label starting with a minus has no
  node id and the error says so. Documented behaviour, not changed.
* **`comac`/`ecomac`/`effective_mass` take the real part of a complex quantity.** Deliberate — they
  are magnitude/energy measures — and each was checked against a brute-force reference.
* **The dynamic Guyan expansion "failing" on a random model** was my probe using `eigh` on the
  non-symmetric `M⁻¹K`. Against a proper `scipy.linalg.eigh(K, M)` pair the expansion is exact to
  8e-9 and the sparse + lumped-mass path matches the dense one to 1e-9 (R5-O3 defect 1 holds).

## Notes for other agents

* **R6-F1 / exports.** `nmd` and `macx` are importable now, so they can be promoted to the stable
  top-level `_EXPORTS` (`"nmd": "femtools.correlation.mac"`, `"macx": "femtools.correlation.mac"`)
  and to the `TYPE_CHECKING` re-export block. `docs/CONTRACT_API.md` and SOTA.md are outside my
  paths; the public reference for MACX is Vacher, Jacquier & Bucharles, "Extensions of the MAC
  criterion to complex modes" (IMAC–ISMA 2010), and for the NMD, Allemang, "The Modal Assurance
  Criterion — Twenty Years of Use and Abuse", *Sound and Vibration*, 2003.
* **R6-G1 / tests.** Cheap regressions, all currently uncovered and none of them in a
  `test_round6_*` file: `macx(real, real)` bit-identical to `mac_matrix`; `macx(a, conj(a))`
  diagonal == 1 while the MAC diagonal is not; `nmd == sqrt(1 - mac_matrix(...))`;
  `candidate_dofs(exclude=(node, "X"))` removing one DOF, not the node;
  `candidate_dofs(exclude=np.int64(node))` removing the node; and
  `select_exciters(coords=<n_node×3>, min_separation=...)` raising for a DOF-level candidate set.
* **R6-F3 / docs.** `nmd(mac=macx(...))` is the intended way to combine the two, and MACX is
  accepted anywhere a MAC matrix is (`pair_modes(mac=...)`, `fmac(mac=...)`) — the complex-mode
  pairing demo above is three lines.
* **No API changed.** The two new functions are additive; the three fixes are each a silently wrong
  answer now correct or a silently ignored argument now honoured. Nothing that worked before behaves
  differently, which the unedited test suite, the 8 examples and the CLI confirm.
